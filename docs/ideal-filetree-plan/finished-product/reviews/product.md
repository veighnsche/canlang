## Requirements reconstructed before ownership

The product replaces CRUD-centered company SaaS with economical `.can` applications. App identity, selected composition, records, access, business transitions and examples belong in source. Library owners provide reusable mechanics and one machine-readable contract; packages are a delivery choice, not the product's capability map. Original workflows include success, denial, conflicting edits, retries, failure, cancellation and termination. Specialized design/video/observability engines and unrestricted agents remain outside scope. Bounded provider-backed company workflows remain inside it. These boundaries come from [REQUIREMENTS](../../../specification/REQUIREMENTS.md) and the [challenge authority statement](../../../../implementation/CHALLENGE-AUDIT-PLAN.md); diagnostic counts are not an acceptance measure.

The interface journey is: selected source declarations → checked operation/page/field descriptors → installed runtime registry → current identity/team → canonical admission → authoritative commit or authorized read → projected result → browser or MCP. Discovery does not authorize invocation. The browser uses session/CSRF context; MCP uses a current grant audience. Arguments never carry trusted identity, finalized files or authority. Replay keeps stable operation identity without repeating committed effects. Permission failures, setup errors, business rejections and unavailable producers stay distinguishable.

## Current source observations and contradictions

* `interfaces/http/operations.ts` implements canonical framing, CSRF, bound checking and safe denial redisplay; it deliberately rejects HTTP `action_handle`. `mcp/server.ts` constructs an SDK server and transport per request, checks grant audience, framing and current visibility/call permissions. These are source-present mechanisms. Their presence does not certify the default Cloudflare route, browser client installation or whole workflow.
* `ui/forms.ts` now derives/project typed operation inputs and `ui/client.ts` collects controls, uploads bytes and sends JSON with injected fetch. Earlier blanket claims that only selector strings exist are superseded at this scope. The client explicitly leaves URLs and DOM swaps to the caller; it is not a complete installed browser bootstrap. `shell.ts` supplies the shared right-side drawer. Product focus/keyboard/settings/navigation and original browser journeys still require actual assembled proof. No CSV implementation was located in these inspected form/client paths.
* `interfaces/http/pages.ts` has candidate admission/navigation machinery. Current business denial hides a destination and unexpected failure marks navigation incomplete. Preserve empty authorized views, current-context invalidation and local nested gates; do not replace admission with rendering/list-nonemptiness tests.
* `identity/sessions/presession.ts` still finds a row then calls a void deletion before returning success. The presented value is a transferable bearer with no browser/origin binding in this API. `identity/ports.ts` exposes void `deletePreSessionToken`; the inspected contract cannot tell two concurrent consumers which won. `teams/roles.ts` separately lists owners then updates owner status, and read-modify-writes role arrays through void store calls. Required targets must make these atomic outcomes and current-authority checks concrete. This is source-inferred concurrency risk, not an exploit run.
* `cloudflare/runtime/mcp-registry.ts` continues hand-transcribed type mirrors justified by an old missing interfaces dependency, while current `cloudflare/package.json` now has that dependency. Retire mirrors only after exact installed imports/schema/ABI consumers pass; merely moving files leaves contract drift intact.
* The documentation extractor/CLI now exist. The language review independently found creation-requiredness disagreement for ordinary arrays; that must be repaired through the owner-derived input/reference contract, not erased by changing a draft.

Strongest opposing case: widening static acceptance or adding runtime joins can weaken safety and impose token/implementation cost. Preserve demonstrated receiver/field access, trusted identity, guard order, negative examples and finite profiles. A restriction must earn its place against original business outcomes; existing checker behavior alone is not a defense. Individual draft mistakes remain bucket a, coherent missing behavior b/c, unadopted syntax d, deliberate negatives e. Required unavailable behavior is not relabeled deferred merely to close a gate.

## Allocation judgment and remaining gates

Rust is the existing supported compiler implementation and the selected owner for pure numeric/validation/work mechanisms and native artifact preparation. TypeScript remains a justified host domain: browser/SDK integration, JS observable input traversal, storage/provider/network callbacks, authorization, orchestration and publication. `.can` remains business authority. No package/language count is a goal. Keep contracts data-only, public stdlib thin and state the single commit authority; add the work-owned acyclic leaf from the accepted port design. Python grammar prototype remains only until its actual CLI/CI callers are migrated with parity. A direct compiler dependency on the runtime Rust values crate is deferred; static source-context diagnostics and spelling are compiler duties and cross-owner conformance can prove agreement without coupling builds.

New proposed browser/CSV/preferences/atomic-identity modules need exact interface release, meaningful controls and installed journey gates before implementation. Their names are allocation proposals, not installed APIs. They supplement the challenge/description and 230 port items; this audit grants no expansion to current implementers. Release completion requires supported scope, real owner catalogs, actual consumers and rollback—not the mere existence of source or test counts.

These corrections change planning duties, not source.
