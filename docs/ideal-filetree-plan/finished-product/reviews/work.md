## End-to-end workflows, failure and termination

1. **Canonical submitted or compiled call:** a selected app's compiler-derived operation registry receives verified identity/team and closed wire inputs. State reads owner revision, hashes **raw inputs**, replays matching existing receipt (including older IDs), rejects conflicting identity reuse, then applies unseen-ID age, `by`, normalized input/default/ref/version validation. Current source `admission.ts:299` has that order. Current archived refs reject after stale-version checking. The mutation pipeline stages caller/hook secondary writes, resulting versions, constraints/history and all effects. Revalidation and one owner commit make success durable; contention retries only through the caller's bounded policy. A business rejection can commit its explicitly canonical rejected receipt with empty domain effects; programmer/getter/host exceptions retain their contract. Generated reads enter the authorized read port, and UI/MCP share projection. A denied read, stale update, interrupted commit and duplicate submission never create an alternate CRUD engine. T04/T15/T16–T18 and T37 remain actual producer/journey joins, not closed by helper availability.

2. **Expense / Leave / Onboard imported relationships:** an Employee/Customer import retains declaring identity even when a consumer owns contained business records. Parent/team/storage/lifetime checks occur across generated and scenario paths; hook writes use the same constraints and provisional parents. Expense freezes receipt/amount/reviewer and historical claim evidence; current membership revocation removes present access while retained attribution/history remain truthful. Hook order/revision invalidation and any failure roll back the whole batch; no recursive hook engine or deletion exception is inferred. Current `pipeline.ts` already implements flat hook staging and checked parent immutability. T28/T29/T30/T31/T32 and each original app's own file/provider gates qualify this flow separately.

3. **Business notification, event, keyed reminder:** the successful business operation commits its outbox/dispatch/schedule changes at the owner fence before transport. A duplicate committed event maps to stable handler occurrence; a replacement/cancelled reminder prevents undispatched obsolete work. Claim-time checks preserve wrapper-specific order: uncommitted/inherited scope/superseded/settled refusal avoids later callbacks; false guard avoids authority/provider demand; eligible work revalidates live authority before spend. Provider acceptance, failure and uncertain outcome remain distinct. Unknown evidence retains pending/uncertain state; reconcile reuses identity, and action-time evidence is reread. Bounded retry/first-attempt horizon produces visible exhaustion, never invented success. The production `driveDispatchIntent` also has a durable claim before the guard/provider gate; the port must preserve that real shell rather than substitute the pure helper's trace.

4. **CanChat:** `ask` checks readable private branch/current membership, transcript/parallel constraints and allowance, freezes request and creates user turn/run, holds maximum tokens, and stages guarded `LLM.generate` in the same batch. Transport receipt and observed `TextRun` are distinct. Partial/unknown progress keeps holds and unresolved state; stop/revoke requests cancellation without inventing its effect. A correlated progressed result releases hold once actual usage is known, moves running count once terminal, and creates one assistant turn only on succeeded evidence. Terminal-with-unknown-usage can accept the independent late authoritative usage fact without mutating the terminal receipt. Duplicate/wrong-source/wrong-revision/wrong-relation observations fail or replay appropriately. `regenerate` creates a distinct branch/request rather than charging twice for replay. Reconnect/page poll reads current authorized state, never resubmits. Current std TextGeneration contract is explicitly contract-only; an Ollama stream handle alone does not implement durable std cancel/reconcile or restart.

5. **CanCreative / CanGallery:** workflow inspect/validate/publish precedes guarded, budget-held image submit. Provider job identity, cancellation/reconcile and observed charged usage remain evidence-driven; unknown output is pending, not success. Provider bytes pass verified narrow provenance through receiving-app intake, type/size/digest checks, immutable finalization and authorized attachment before generated `Output.image` becomes usable. Duplicate slot finalization reuses its identity; conflicting bytes, provenance, invalid output, permissions or expired content cannot create a replacement silently. Gallery copies only the authorized selected image and rights evidence, preserving private-conversation boundaries; another reviewer makes the business approval. File metadata publication and blob writes require recovery across their separate stores; no R2+state transaction is promised. Finalization pure/module tests do not establish that installed production join.

6. **CanShift / CanVolunteer:** retain both whole-model and parent-anchored cohorts. Shift's Commitment and Swap handlers independently preserve nullable employee/location/account/roster filters, current version/eligibility checks and sticky conflict/obsolete outcomes; they have no artificial ordering dependence. Volunteer reminder refresh pairs keyed cancel/rearm for the current signup; parent cancellation commits immediately with its durable intent while child changes/notices remain independently pending/failed. Freeze the **complete canonical identity set** in the owner store at the source-occurrence/handler cutoff; enumerate bounded pages under a revision fence, never bless a partial set. Later inserts stay outside that run. Each child gets stable parent+handler+record identity, fresh authority/current parent/body evaluation and its own atomic domain/history/replay/events/schedules/outbox/outcome/checkpoint batch. Deleted-with-proof gets explicit skipped/deleted; missing/inaccessible/infra failure cannot become deletion. Failed/rejected children do not stop siblings. All terminal failures yield attention, while incomplete admission/checkpoint remains pending. Two differently filtered source events retain independent coverage; cancellation cannot recall accepted external work. Real restart at enumeration/claim/effect/checkpoint boundaries must retain membership, exclude committed reexecution and make fair progress. Page/chunk/turn/retry limits bound work, not admitted cohort size.

7. **CanKnowledge:** the accepted model-bound `corpus` derives answer/cancel/reconcile/refresh effects and bounded status/available reads. Capture genuine originating principal/team/scope/request digest, authorize exact eligible immutable source row/field/file content before retrieval/model input, and retain **every actually used context source**, including uncited inputs. Index committed source changes; bounded explicit repair never equates queued acknowledgement with searchable freshness. Complete coverage means every eligible authorized source is confirmed indexed at the checkpoint within the pinned 1,000-revision topic/12-source/64,000-scalar request bounds; incomplete/unavailable remains explicit, with no truncation or invented empty success. Validate statements, exact quotes/locators/extraction revisions before minting opaque grounded Answer. Ordinary source cannot construct it, expose raw text/citations or pass it to another provider. Every later progress/history/cache/reconnect/browser/MCP disclosure rechecks original principal/viewer membership and **all** used source/file grants/eligibility: revocation/withdrawal/supersession withholds the whole answer. An unrelated authorized scope change preserves a still-valid answer only historical/as-of; explicit fresh retrieval obtains a current answer. Infrastructure failure remains failure rather than availability=false. Isolated fixture normalizers mint proof only from genuine current seeded caller/source/file/extraction/grants, never authored principal/freshness flags. Accepted grammar and the prior divided consultation are retained; compiler catalog B8 scope is an implementation gap, not a language decision to reopen.

8. **Retention and upgrade termination:** declared expiry has a dedicated owner command independent of user CRUD and file GC, including archived/locked records, references, child lifetime, safe replay tombstones and sensitive copy disposal. Interrupted physical erasure resumes with honest state. Migration compares the exact installed compiler predecessor to desired source, stages/validates bounded owner state and pending-work contracts, fences activation and recovery, and refuses unknown baselines/unsupported transfer. Current `migration/retain.ts` retains pending work across a schema flip; it does **not** supply model expiry. Neither operation is a public business form/tool. Missing producer semantics block only their dependent implementation/journey packets.
