### 1. Shared bounded message syntax — strongest semantic consistency opportunity

**Defining owners:** Values public parser, Compiler source diagnostics, UI
message consumer. Existing files: `values/src/icu.ts`, `ui/src/messages.ts`,
`compiler/src/analysis/icu.rs`, `examples.rs` and related placeholder checks.

**Historical gap:** three related parsers had materially different acceptance,
errors and evaluation order. The [ICU matrix](icu-shared-parser-plan.md) retains
that source-derived baseline at `0bb480bef`, including literal `#`, exact
selectors, names, whitespace, rich tags, nesting and UTF16 offsets. Compiler
consolidation is now complete at the selected scope. UI still admits locale/operands before parsing;
Values still parses first.

**Approved grammar; Shared TS syntax released and complete:** Values now owns
syntax/normalization/narrow diagnostics in `src/icu-syntax.ts`, with the existing
`icu.ts` wrapper preserving ValueError/AST contracts and root `parseMessageSyntax`
exported for UI. UI uses those nodes in its own renderer; its duplicate parser
and AST are removed. The shared corpus has 24 accepted and 40 refused cases.
Contracts/Values/UI emitted and typechecked; the focused run passed 241 tests,
then the affected ICU/messages scope passed 165 after diagnostic fixes with the
unchanged 76 results reused. This closes the TS syntax packet.

**Compiler parse/usage released and complete:** private `analysis/icu.rs` now
supplies syntax and ordered valid-pattern usages to named/anonymous messages,
inline descriptors and static contributed captions. Existing declaration/type
hooks preserve diagnostic order; malformed patterns suppress speculative slot
noise while retaining admitted explicit anonymous schemas. The
[C09I completion note](../../research/compiler-library-audit-20261006/pass9/icu/correctness-packets.md)
records 68 distinct Rust tests and the two frozen-compiler named/anonymous Node
fixture checks, their consumer closure and limits. Accepted I-TYPE remains closed.

**UI full-signature usage released and complete:** source/every present variant
and all branches now receive syntax and declared-usage checks. Construction keeps
metadata/wrapper checks first and performs no value conversion; absent params
remain syntax-only. Formatting keeps locale resolution and eager admission of
all supplied values before checking `options.args ?? params`, reusing each
needed AST within the call. Values exports its existing traversal as
`messageUsages`/`MessageUsage`/`MessageUsageSite`; Values validation/rendering and
UI renderers/error families retain their owners. Own `__proto__` is admitted,
null variants are skipped and empty variants remain valid. Construction accepts
existing nonnullable, nonarray inline enum declarations used by Values formatter
carriers; UI formatting retains its ownerless-enum refusal.

Contracts/Values/UI emitted and typechecked. After the initial 254-test TS run,
the inline-enum regression correction passed 50 affected UI tests, reusing 205

### 2. Exact static Judgment response decoding — conditional portability value

**Owner:** Services `judgments/systemone.ts:exactJson/wireDecimal/staticResult`,
with Values owning decimal/int semantics. It consumes raw provider response text
plus the installed, source-ordered specification and returns a canonical result
or refusal. Its legacy Number-based mapping is a different API/profile.

**Concrete seam:** the static path requires numeric lexemes from
`JSON.parse` reviver `context.source` and explicitly refuses when unavailable.
A supported-host failure is **not established** by this audit. Exact exponent,
scale, int64 usage, distribution/winner/score/legend and tolerance rules already
exist; no new result schema is needed.

**First finite output:** name the actual required host/consumer and establish
whether its numeric-lexeme facility or measured cost creates a gap. If so compare
an exact JS raw-number reader, existing Values primitives, and one Rust
raw-response-to-result operation. Stop with retain-now when no required gap exists.

**If selected:** preserve JSON duplicate-last-wins and string/surrogate behavior,
source order, portable decimals, all invalid-to-null/error classification, exact
probability/tolerance and token counts through real `evaluateStatic` and installed
host delivery. HTTP, source binding, tokenizer, provider state and retries stay TS.
Do not turn this into a general JSON/validation engine or reopen existing V.

### 3. State total-order batch — plausible only after complete-cost comparison

**Owner:** State `query/engine.ts:orderSourceReadRecords`, using Values exact
primitive contracts and the existing Cloudflare original-source read consumer.
Input rows have already passed their owning authority/projection/source checks.

**First finite output:** a declared total-comparison profile and TS baseline
comparison for already materialized rows. The current engine already decodes
keys once; page candidate cap is 1,000. Unbounded DB scans are not removed by
Rust sorting. Compare prepared TS/key vectors before choosing a Wasm boundary.

**If selected:** copy only demanded typed keys/null tags/UTF16 IDs and return
permutation indices; retain original rows in JS. Preserve field-major/row-major
decode and singleton errors, null/missing/tie ordering and exact numeric results.
Money/mixed throwing comparators stay TS unless original comparison-demand and
first failure are proved; a different sort algorithm can change errors. Source
predicates, protected reads, fences and post-transform authority checks keep their
original positions. Do not unify State's two-valued policy with SQL's three-valued
predicates. No per-comparison FFI or whole query-engine rewrite.

### 4. Generation diff — clearest isolated new compute boundary

**Owner:** Cloudflare `generation/controls.ts:textHunks/myersDiff`, called by
real `runDiff`. Whole byte pairs produce bounded hunk output. Trace allocation
occurs before output truncation; the line-product fallback is not a universal
memory bound. No latency/memory failure was measured here.

**First finite output:** representative current diff workloads and an exact hunk
compatibility table, then compare bounded TS algorithm work with a Rust leaf.
Any changed work/input limit or hunk output policy is a separate explicit choice.

**If selected:** preserve strict UTF8 classification, LF/CR/trailing-empty-line
behavior, ties, context, indexes, fallback, 50-hunk/500-line truncation, and the
actual command result. Include I/O, copies, serialization, startup and delivery in
cost. Keep journals/leases/promotion TS. A new native loader is a real prerequisite
if chosen; it cannot borrow held preparation permission or pollute Values solely
to obtain a loader.

### 5. Files content plus digest — retain now, revisit on measured demand

**Owner:** Files `upload/index.ts:detectContentType/checkContent/sha256Hex` and
its actual completion, finalize, current-read and retention consumers. SHA uses
synchronous noble JS; text validity already uses native `TextDecoder`. Short
binary signatures alone do not justify Rust. Larger repeated immutable buffers
could amortize a combined copy/scan/digest, but this is unmeasured.

**First finite output, only when demand exists:** quantify byte-analysis cost in
representative complete flows, including slices/retries, then compare unchanged
TS/noble/TextDecoder, a semantics-compatible native host option and a combined
Rust byte kernel. Async WebCrypto is not a drop-in replacement for the sync flows.

**If selected:** exact prefix precedence/BOM/UTF8/NUL/empty behavior and `sha256:`
spelling, same immutable byte view, detection-before-policy and hashing/cleanup
order on success/refusal; actual installed Node/Worker lifecycle outcomes and
conversion-inclusive cost. No added formats, structural media validation or
security claim. Reuse qualified asset mechanics, but a new Files binary still
needs an explicit defining build/export/distribution owner.

[TypeSafe API](https://docs.typesafe.ai/api) / [Choice](https://docs.typesafe.ai/primitives/choice)
contract. It selected **evaluate first** for ICU, query, diff and Judgment in all
three. Probability assigned to evaluate-first ranges: ICU .85–.90, query .66–.84,
diff .51–.72, Judgment .60–.82. Files split: retain-now, evaluate-first, then a
.50/.50 tie (reported retain-now). These are model opinions, not measured success
probabilities or authorization.

Files disagreement was investigated against actual source/callers: large repeated
buffers create a plausible workload, but magic checks are tiny, text decoding is
already native, sync transactions constrain alternatives and no CPU measurements
exist. Resolution: keep it lower and trigger an evaluation only on actual demand.
No repeated consultation or invented benchmark was needed. Root retains the
engineering judgment. The first consultation attempt was blocked by automatic
review for sensitive-payload concerns; after verifying the repository and exact
source URLs are public, a reduced public-facts-only request was approved and
completed. No private instructions, local paths or secrets were sent as context.
