# Files, Identity, Services, Stdlib, Testkit and UI: Rust benefit screening

Planning only, at supplied `08dc8c392`. This note covers all 253 tracked artifacts in these six packages: Files 31, Identity 48, Services 38, Stdlib 6, Testkit 42, UI 88. The companion `adapters-ui-coverage.json` records each artifact's responsibility and inspection depth. Every tracked text file was read for a structural inventory; candidate bodies and their actual callers were inspected more deeply. Test structure/topic inspection is not an assertion-by-assertion test review, and structural source screening is not complete correctness qualification. No product edit, build, test, install, benchmark, Git mutation or JEV call was performed. The root owns final decisions and any required JEV consultation.

## Recommendation

Keep these packages predominantly TypeScript. They contain genuine pure kernels, but package size and security sensitivity do not establish a Rust benefit. The best *additional evaluation* in this assigned scope is one shared Files byte-analysis operation, conditional on a measured complete-call benefit. CSV, identity codecs, native comparison and HTTP cancellation already have focused library/host solutions; they should not be redispatched as new Rust migrations. UI message parsing and HTML ownership scanning, Services exact provider-result validation and graph substitution are possible later kernels, with narrower likely benefit and substantial compatibility cost. No additional implementation is accepted by this audit.

The Rust execution view in `docs/implementation/RUST-PORT-START-HERE.md` remains authoritative. Identity `I01–I04`, CSV `C01–C04`, Services `H01–H02` are library-sequence IDs, not newly discovered Rust tasks. Existing integration dispositions retain thin identity-codec, native-comparison, cookie and abort-fan-in integration; retain existing CSV export, stable-JSON identity, file-signature catalog and Ollama protocol implementations. Those outcomes and existing native/default/publication holds remain intact.

### Files byte analysis: the strongest new evaluation in this scope

`upload/index.ts:94–175` contains real pure work: three short magic prefixes, NUL-free strict UTF-8 text admission and synchronous `@noble/hashes` SHA-256. `checkContent` preserves claimed type only as evidence; binary prefix precedence is PDF, PNG, JPEG, then text. This is explicitly **not** a full PDF/image parser or malware/content-safety check. `sha256Hex` returns exact lowercase `sha256:` bytes.

Actual consumers repeat byte work: `completeUploadContent` hashes/rechecks completed retries; `finalizeUpload` hashes staging; `currentFileRead` validates one detached physical snapshot; event/provider output and original-retirement cleanup also consume these functions. Beyond this package, `cloudflare/src/runtime/r2-files.ts` imports the same hash for namespace/pointer integrity, and `runtime/bound-files.ts` uses detection. Default maximum upload is 10 MiB, but declared policies can differ. Public helpers accept arbitrary `Uint8Array` views. A Rust kernel could combine detection and digest in one synchronous call and share one reviewed implementation; benefit is plausible for large/repeated buffers, not measured here. Current prefix checks are tiny and TextDecoder is already host-native; one or more full JS↔Wasm byte copies can erase hash improvements.

Finite proposed evaluation (no canonical execution ID assigned): **Files owner**, prerequisite a reviewed exact byte-analysis input/output contract plus measured representative current call workloads; output a private synchronous `analyzeBytes` candidate and adopt/retain result. Preserve prefix classification, empty/NUL/invalid UTF-8 behavior, UTF-8 BOM treatment, exact sliced view bytes, hash spelling and no mutation/aliasing. Public `checkContent` still detects before applying policy; combined calls must not change when hashing happens on rejection or exception paths. Do not fuse in caller authority, policy mutation, storage reads/writes or minting. Acceptance: compare complete completion/finalize/current-read/retirement outcomes through actual Node and Worker adapters, including byte-count drift, replay, retention, policy rejection and interrupted publication; measure total time, memory, startup/bundle cost and copies against current noble/TextDecoder and a host-native alternative that preserves synchronous transaction semantics. Stop with retain-TS if there is no worthwhile complete-operation gain. Existing `AD-files-upload`, `AD-file-magic-scope`, `AD-file-digest-encoding`, `AD-files-provenance` define compatibility context, not implementation authorization.

Existing witnesses to reuse: compares portable SHA-256 to native crypto on exact bytes and slices; completion/finalize-byte-count tests cover actual byte disagreement and interrupted FS publication; finalize/provider-output/retention tests cover current snapshot, replay and permanent State cleanup. These were inspected as source, not rerun.

### Identity: native work is already native

`accounts/passwords.ts` derives PBKDF2-HMAC-SHA256 with WebCrypto, 600,000 iterations, 16-byte salt, 32-byte key. Parsing failures/derivation failures return false; native compare faults propagate. `sessions/tokens.ts` uses `@scure/base` codecs and native WebCrypto SHA-256; byte decoding deliberately masks unused base64url tail bits, whereas bearer lookup hashes the exact presented text. Hex decoding rejects malformed input. `comparison-node.ts` calls `node:crypto.timingSafeEqual`; Worker uses host `subtle.timingSafeEqual` or refuses. Length/codec errors precede the native primitive and are outside its timing guarantee. Rust/Wasm alone does not establish equivalent host timing properties or secret lifetime guarantees.

Cookies already use `cookie`, retaining first-name/raw URI decode behavior, empty/invalid Domain mapping, attribute order and encoding-before-Domain-validation (including lone-surrogate URIError). CSRF HMAC and PKCE SHA-256 remain native. Retain `I01–I04` and the exact tests in sessions/comparison/accounts/pkce/cookies through existing integration scope. Replacing these with Rust would introduce secret copies and distribution/host qualification for no demonstrated missing kernel.

### Services: retain transport; distinguish pure subcomputations

`http/client.ts` now uses `AbortSignal.any`, tracks the winning reason, copies producer-reused chunks, caps redirect bodies and stream totals, and bounds cancellation waits with the existing signal. `HttpBodyLimitError` takes precedence over cleanup/timeout relabeling. `H01/H02` address this existing host scope; Rust should not own it. `models/ollama.ts:394–668` is an actual incremental NDJSON parser/accumulator within cancellation, snapshot, terminal-winner and partial-stream handling. The JSON/line classification is pure, but moving per-line calls to Wasm still leaves fetch, incremental UTF-8 decoding, observers and retained snapshots in JS. Retain until a measured streaming parse bottleneck and an exact chunk/terminal protocol requirement exist.

`media/mapping.ts` is a genuine pure graph kernel: descriptor-only own JSON copy, UTF-16-key-sorted serialization, native SHA-256, digest check, exact five-field mapping, scalar substitution, output-node validation and deep freeze. `ComfyUINativeAdapter.installImages` and `.submit` use it before transport. It must preserve finite numbers, `-0` serialization, shared acyclic data, null prototypes, dense arrays, refusing executable/toJSON/cycle domains, and the *distinct* exported `stableStringify` behavior for arbitrary JS values. Do not replace it with the State/CSV canonical serializer by name. Candidate Rust would still require JS admission to preserve descriptor semantics; graph hashing alone already calls native crypto. Proposed disposition: retain now; if concrete graph size/repeated-submit cost warrants, Services media owner may evaluate one admitted-data capture→digest→substitution operation. Prerequisite exact admitted graph/mapping contract, output parity through actual `.submit`, acceptance original digest, failure order, graph immutability and no provider call on failure, plus end-to-end cost and installed-host evidence. Context `AD-media-graph-digest`/`stable-json-identities`; no new task or accepted port.

`judgments/systemone.ts:690–792` is another real pure kernel: source-number JSON lexemes, exponent expansion into portable Decimal, int64 usage, probability range, exact distribution sums, selected-max/tolerance and weighted-score checks. `evaluateStatic` uses it after actual HTTP response classification. `judgments/specification.ts` derives source order/revision and delegates runtime options to Values validation; declarations bound it to 32 questions, 26 choices/10 score levels, 24,000 total caption scalars. Finite evaluation, if later selected: Services judgment owner consumes released Values numeric/error ABI; produces one pure response-text/spec→result/refusal candidate; accepts original exact lexemes, order, strict legend/answer identity, tolerance, counts and classification through `.evaluateStatic`, with TS fallback chosen before evaluation and no semantic retry. `mail/redact.ts` applies JS regex scrubbing but production `specificOrGeneric` emits fixed authored messages from exact bounded allowlists. This is not an open-ended safe disclosure sanitizer; porting regex engines changes semantics and does not strengthen that boundary. Request validators, completion projectors, pagination, scenario tables and harnesses are small policies/host adapters; retain TS.

### UI: real parsing exists, but full rendering is the wrong boundary

CSV grammar already imports `csv-parse/browser/esm/sync`, shared with authoritative `interfaces/src/http/csv.ts`. The custom preflights enforce UTF-16 validity and UTF-8 byte budget before quote syntax, then syntax before row/cell ceilings and materialization. Preserve BOM, lone CR, CRLF/LF, blank records, raw cells, count mismatch flags, safe error text, optional byte/cell limits and fixed 1,000 data-row cap. Advisory parsing does not replace authoritative review/commit. `csv/parse.ts` header/cell mapping carries nullable/omission/boolean/default ownership; preview/confirm are fetch/consent/DOM lifecycle. Existing `C01–C03` plus library integration disposition cover this outcome; `C04` CSV export remains separate. Retain now; no independent Rust CSV packet without measured whole review/commit or browser parse benefit and retained consent/replay identity. A full new parser duplicates already adopted grammar, browser asset delivery and error preflight work.

`messages.ts` contains a real recursive ICU-profile parser, exact decimal canonicalization/grouping/digit substitution, locale lookup and render interpreter. Host `Intl` supplies BCP47 normalization, number-system probes, plural category, date/time and currency patterns. Parse offsets and JS strings are UTF-16; apostrophe quoting, nested `#`, exact `=N` cases and ordered operand validation are observable. `formatMessageResult` normalizes/resolves locale and validates operands **before** parsing the pattern. A parser-only Rust port incurs pattern/AST copies and leaves Intl/callback rendering; precompiling or caching unchanged patterns in TS is a fair alternative. Retain now. Finite optional UI evaluation: profile actual descriptor-heavy `renderPage`/collection output, then compare unchanged TS, bounded parser reuse and private Rust parse once. Owner UI; prerequisite exact pattern/UTF-16/error ordering and profile; output adopt/retain decision; acceptance identical resolved locale/text/errors and total SSR/browser startup/bundle/memory benefit. Do not import a different ICU grammar or locale database incidentally.

`components.ts:245–316` (`stampStyledHtml`) and `internal/action-groups.ts` contain real quote/comment/raw-text-aware HTML scans. They stamp CSS ownership boundaries and aggregate only canonical completed direct action roots; they are not general HTML sanitizers. They have a feasible pure string→string seam, but changing to a standard HTML parser can normalize bytes, parse malformed markup differently or steal nested owners. Current promise/null wrapper behavior and exactly-once child rendering remain TS. Treat as low-priority conditional evaluation only after actual large/repeated SSR evidence; compiler-emitted structure or TS pass reduction are alternative solutions. Any candidate must retain byte output, raw text/comments/quoted `>`, existing ownership/action boundaries, malformed-input disposition and first-authored-position order through `styledComponent`, `renderActionScope`, generated view and page consumers.

`forms.ts` is mixed, not merely markup: `wallToInstant` probes host Intl offsets, handles gaps/folds, returns canonical instant spelling; generated field/projection logic preserves delivery non-submission, omission, explicit null, bound record/version and file order. These are host/policy boundaries; retain. Browser bootstrap/client/polling/export/gallery/print/instrumentation own DOM, protected fetch, mutable File/URL/AbortController resources and cleanup; Rust has no demonstrated advantage there. Collections/navigation/readable selectors mostly map declared policy metadata and row queries into ordered callbacks and escaped markup; their computational pieces are small. CSS/theme/catalog/build scripts remain their natural owners; the JS browser builder already invokes esbuild and native crypto, so a Rust wrapper does not replace its actual work.

**`runtime/sourcemap.ts`, `deploy/module-imports.ts`, `deploy/module-maps.ts`: existing overlap, retain/adopt existing owners.** D02–D04 already replaced scanning/VLQ/composition mechanics with `es-module-lexer`, MagicString and jridgewell libraries, with accepted staged/installed diagnostics. A metadata-only index plan returning selected indices/version overrides could avoid row transport, but that is a new carrier with no demonstrated performance gap. Keep host live authority, callbacks, stage legality, histories and commit ordering outside; broad invoke port is not supported by this finding.
