## Contract before implementation

[REQUIREMENTS](../../specification/REQUIREMENTS.md):202,223 requires MCP connections to resolve a real app user and authorized team, recovery and sign-out, verified email where email ownership matters, and removal ending team access while preserving history. [DESIGN](../../specification/DESIGN.md):406–410 distinguishes public/authenticated/member/owner/declared-role authority, protects the last owner, limits invitation grants, and says completed removal prevents new admissions while already-admitted work may finish; D1 fencing also detects intervening membership changes. DESIGN:1136–1142 makes team tools canonical business operations, leaves login/recovery/consent as runtime interfaces, binds MCP consent to one team (or app-only for a non-team app), and rejects argument-supplied identity/roles/team grants. DESIGN:894 requires context changes to recheck access and clear previous private presentation data. REQUIREMENTS:225,252 explicitly prohibits assuming transactions across D1/DO/R2/providers.

These contracts do not establish retroactive cancellation of all work after session logout, or a transaction spanning Identity and State. Local lifetimes, token sizes, cookie mechanism, public OAuth client restriction and consume-before-mint failure policy are authored implementation contracts. Their source comments are evidence of that mechanism, not independent language requirements. In particular `authentication/revocation.ts` describes credential checking as commit-time, whereas its actual interface callers label and implement **pre-invoker admission**. The actual checkpoint must be reported accurately.

## Ownership and strongest supported alternative

Retain Identity as the defining asynchronous TypeScript owner of account/session/grant/team lifecycle and bounded SQL commands; Interfaces owns browser/MCP transport, origin/CSRF admission and safe errors; State owns business admission/fence/replay/query authority; Cloudflare owns physical bindings and original-removal-to-State staging. Retain exact authentication/session/team leaves named above, `identity/src/{ports,testing}.ts` and `storage/d1.ts`; no extra identity database, role service, bearer DTO authority or new process is selected. Atomic commands remain beside their authoritative Identity schema. SQL is an essential defining part of their guarantees, not incidental glue to relocate into a generic orchestrator.

The strongest already-supported alternative is Rust/Wasm for pure token/codecs/comparison or complete lifecycle logic behind the existing JS host, using the repository's real Rust/Wasm toolchain. The pure pieces are small and already delegate cryptography, encoding and cookies to WebCrypto/native host, `@scure/base` and `cookie`; a port gains no demonstrated workflow correctness or storage atomicity. Full lifecycle port still requires async D1 batches, mail, WebCrypto/random/clock, browser cookie/origin handling and JS error/ordering equivalence through a new ABI. Conditional Node/workerd comparison modules already preserve the native host seam and fail closed when workerd lacks it. Retaining TS/SQL is the lower-complexity technical recommendation on present evidence, not proof of performance superiority or an unrestricted language policy. The decisive improvement is a truthful atomic storage command where required, independently of language.
