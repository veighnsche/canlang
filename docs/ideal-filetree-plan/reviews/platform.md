## Findings and evidence limits

### P-F01 — Activation refusal is bypassed by production grant issuance

[Worker main](../../../packages/cloudflare/src/worker/main.ts), lines 521–526, dispatches `POST /mcp/grants` directly to `grantsResponse`; this path does not call `getStaged`, `workerFor` or `assembleWorker`. The main's outer binding check is not an activation verdict. [Assembly](../../../packages/cloudflare/src/worker/assembly.ts), lines 1297–1320 and 1336–1360, promises that a failed verdict serves nothing and imports no pages. An absent/failed staged artifact can therefore leave grant issuance reachable once the production binding and grant handler load. This is a route-ordering defect, independently confirmed by runtime review, not a conclusion from execution.

The owning fix is the main serving/activation packet: gate every route before grants or assembly effects, preserve deterministic refusal and distinguish broken runtime dependencies from a negative verdict. Existing [activation refusal tests](../../../packages/cloudflare/test/activation-refusal.test.ts) construct `assembleWorker` directly; [main tests](../../../packages/cloudflare/test/worker-main.test.ts) prove the binding/grant seam, not inactive main-grant refusal. Acceptance must call the real main with inactive and absent staged inputs and prove zero grant issuance and zero serving side effects.

### P-F02 — The pre-session bearer does not bind a login attempt to the victim browser

[Pre-session source](../../../packages/identity/src/sessions/presession.ts), lines 3–17 and 35–70, stores an opaque token hash/expiry only. [HTTP auth](../../../packages/interfaces/src/http/auth.ts), lines 180–209 and 295–318, returns the token from a no-store descriptor GET, accepts it in the POST body and sets a session cookie after password login. It has no Origin/browser proof check. An attacker can mint a token in their own client and submit that transferable bearer with attacker credentials in a cross-site URLencoded form. Preventing the attacker from reading a victim token does not exclude this attack. Runtime review independently confirmed the trace under the source's own login-CSRF threat statement.

Identity owns the anonymous browser proof and expiry/use semantics; interfaces owns request/cookie/header validation and UI owns the canonical login form. Choose and ratify the minimum browser-bound proof/origin contract before implementation; preserve failed-attempt token spending, safe errors and rate limits. The current tests reject missing/tampered/spent tokens sequentially, but have no attacker-minted-token cross-site case. The handbuilt TeamTasks login remains explicitly a fixture exemption, not proof of the new production guard.

### P-F03 — Credential use and membership mutation are not atomic in the production identity adapter

`consumePreSessionToken` finds a row and then calls a void delete ([presession](../../../packages/identity/src/sessions/presession.ts), lines 65–70; [D1](../../../packages/identity/src/storage/d1.ts), lines 726–738). Both concurrent readers can return true. Expired tokens which are never presented also have no bounded cleanup path, despite the header's retention claim.

The new D1 adapter exposes broader existing check/write races. [Roles](../../../packages/identity/src/teams/roles.ts), lines 44–79, and [membership](../../../packages/identity/src/teams/membership.ts), lines 24–49, read owners/roles before separate unconditional writes ([D1](../../../packages/identity/src/storage/d1.ts), lines 582–618). Two owners can both observe two owners and then remove/demote both; simultaneous disjoint role grants can overwrite each other's complete role arrays. [OAuth exchange](../../../packages/identity/src/authentication/oauth.ts), lines 224–251, ignores the void conditional-consume result before issuing a grant; [D1](../../../packages/identity/src/storage/d1.ts), lines 889–895, supplies no winning-consumer result. [Recovery](../../../packages/identity/src/accounts/recovery.ts), lines 77–105, changes the password before establishing a consume winner and performs dependent revocations separately. Runtime independently confirmed each interleaving.

[Production environment assembly](../../../packages/cloudflare/src/runtime/env-assembly.ts), lines 333–343, now actually binds `createD1IdentityStore` to `env.DB`; the README's claim of a fenced J2 binding is stale. Sharing the physical DB does not put identity SQL inside the state owner fence. One packet must ratify and implement conditional credential winners, last-owner/role concurrency and dependent identity mutations/revocations within the declared storage authority. The state/identity fence interface must be handed off explicitly; do not mechanically port these races or create a second database/permission engine. Test acceptance needs independent D1 handles and forced interleavings, not only sequential memory-store cases.

### P-F05 — Accepted artifact module names can overwrite staged runtime modules

[Artifact parsing](../../../packages/cloudflare/src/runtime/artifact.ts), lines 189–195, adds names to a Set without rejecting duplicates; module validation requires a nonempty path but does not reserve the deployment namespace. [Bundle staging](../../../packages/cloudflare/src/deploy/bundle.ts), lines 466–503, validates escape safety but preserves the original key. Local filesystem staging additionally needs `.map` and file/directory collision checks.

This is reachable through accepted artifact input even though normal compiler output uses predictable names. Define a canonical module-key contract once and validate raw/normalized duplicates, reserved system/vendor/generated keys and local sidecar conflicts before any write or bundle build.
