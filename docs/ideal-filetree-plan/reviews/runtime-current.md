## Actual workflow traces

1. **Mutation and replay:** `invocation/invoke.ts::invoke` freezes the clock, constructs canonical context, calls `admission.ts::admit`, then opens the actual execution lifetime. Admission reads the revision before state-dependent reads, hashes raw supplied inputs, looks for the original receipt, applies receipt-only recovery authority where selected, then unseen-ID age/authority/normalization/reference checks. Execution effects are captured inside a private genuine-call lifetime; executor-supplied saved associations are rejected. Commit revalidates authority, guards, transitive calls and the revision fence; conflict retries re-admit up to the existing bound. Business rejection receipts contain empty domain effects; non-business exceptions are not converted into successful business results. Retained disclosure uses current grants/membership and saved original images, not re-execution.
2. **Query and page:** `invokeRead`, `invokeReadScenario` and `invokeReadPage` enter the canonical engine. `query/engine.ts` separately handles owner rows and viewer candidates, ancestor/source policy, exact typed ordering, page continuation and final current-authority/revision checks. `orderSourceReadRecords` is called after original source predicates/lazy reads, not as authority to scan or disclose. The source-policy two-valued post-projection predicate and Memory/SQLite three-valued storage predicate are deliberately different domains; consolidation into one generic evaluator is rejected.
3. **Source SEND and due Work:** compiler-installed source declarations bind through `scenario-receipt.ts::bindScenarioReceiptFrameworkProducer`; shape/source/model/Rule census and explicit evaluation mode are checked before private installation. `stageScenarioReceiptSend` evaluates the actual source predicate and stages through the genuine Work producer, or records a logical skipped delivery in the private ledger. A receipt association is materialized only when the source stores/associates that delivery; an unassigned skipped SEND is not evidence of a missing persisted association. Due admission checks the genuine Work event/scope/head/payload against current admitted Model identities. Private retained-due refusal state ties failed terminal status/code/message to actual branded authored refusal; successful Work cannot substitute for it. Explicit `when_at=source` preserves the original staged verdict; ordinary/current `when` remains live.
4. **Claim and provider attempt:** Work's `runDispatchGuardPhase` issues a private execution/phase only within the actual State stage, records revalidation callbacks, closes evaluator lifetime and consumes revalidation once. Claim checks original row/intent, supersession, authority and source custody before provider invocation. Unknown/uncertain acceptance is not automatically treated as failure or safe resend. Provider-specific reconcile and cancellation stay under the owning adapter contract. Host File/source revalidation is still required even for a staged true verdict.
5. **Recovery:** `recovery/index.ts` bounds due/stale inventory, classifies pending/claimed/failed/uncertain states, consults reconcile evidence only for required uncertainty, preserves last-wins claim lookup and deterministic output ordering. The selected `work-kernel/bindings/recovery-planner.ts` transduces host iterator/property/ABI facts; registered Rust decision functions do not imply all Work callers use native implementations. Retry exhaustion, unavailable evidence and terminal outcomes remain distinct.
6. **Identity:** account registration/recovery/password flows persist through the Identity store. `sessions/presession.ts` mints a hash-only token and consumes through atomic `consumePreSessionTokenByHash`; expiry is checked after consumption. Node/Worker constant-time comparison adapters remain host-specific. `teams/removal-occurrence.ts` captures own immutable fields and binds an occurrence digest/envelope to the exact stored removal; the envelope is nongrant data, not authority to execute a handler. Full OAuth/browser and cross-store failure branches remain unqualified here.
7. **Files:** bridge/upload validates receiving request context and bounded actual bytes. `finalize/index.ts::finalizeUpload` loads the actual intent, checks current caller ownership, handles exact retry finalization, verifies content/digest/provenance and publishes receiving-owner finalized identity. Provider output uses the same receiving path; no provider URL becomes an attachment by naming it. State later authorizes record attachment. Retirement walks complete domain/framework reference inventories and actual original opaque lifetimes, then closes the real storage publication/removal barrier; archived references and duplicate positions are not silently discarded.
8. **Migration:** transition/validation map actual old/new declarations; stage/retain/activate/recover distinguish mapping, file publication, atomic flip and retained-work compatibility. Compiler declaration checks and installed State predecessor/snapshot checks overlap but are not established equivalent. Their common shape alone is insufficient to move live activation authority into a compiler or pure Rust kernel.
9. **Values and providers:** public schema calls enter canonical TS validation for arbitrary callers; only supported prevalidated/native routes enter selected backends. Ordered getter/default/null/omission/error behavior is part of the API. HTTP origin/redirect/deadline/byte/stream handling is shared Services infrastructure. Mail's idempotent request/reconcile, model stream terminal parsing, judgment answer/schema mapping and media job/bytes/cancel lifecycles remain adapter-owned; generic completion envelopes cannot erase those differences.

## Independent challenge and resolution

The language reviewer examined compiler source/provenance semantics and objected that optional serialized source metadata is nongrant evidence; a split must preserve one actual owner/call/session identity and State budget derivation. The initial broader session-state decomposition was narrowed: no WeakMap/session extraction or new capability API is selected, and State retains all budget issuance. The reviewer accepted the exact three pure closure targets on condition that helpers move rather than copy and actual error/order/authority joins are checked at cutover.

The runtime reviewer challenged the platform's broad `dispatch-driver.ts` interval because `nativeEmailPreclaims` issuance and consumption join checked `nativeSourceSendGuards`/State definitions outside that interval. The platform reviewer accepted that it is not mechanically ready and kept the native preclaim closure together until a real private boundary is specified; no getter facade or reconstructed authority handle is approved. Further inspection also narrowed the platform callable proposal to read-only `runtime/invocation-errors.ts`; `invokeWith` and actual callable execution retain their assembly/row-policy closure in `invoke.ts`. The proposed UI helper move was accepted only as one defining implementation with existing public re-exports. Conditional obsolete-executor retirement still needs pinned/staged installed-payload closure, not only absent direct imports. The runtime reviewer also compared CF `readDispatchExecutionRow` with Work `readDispatchRow`: Work validates original sourceGuard/opaque File/queue/generation/user-mail profiles that the lifecycle mirror omits. Reusing the Work owner is a supported C candidate, not a behavior-neutral M; error type/message/order, valid legacy rows and consumer projections need an explicit compatibility decision. No authority exploit was reproduced.

The language reviewer separately found the compiler currency allowlist mirror, with no reproduced current mismatch. Its canonical finding belongs to the language review; it is not a new Values correctness failure or a mandate to move excluded-currency diagnostics prematurely.
