## Defining duties and source workflow

**Discovery and identity.** `analysis/generation.rs` traverses the lossless CST with saved model/field/view/host context, collects definitions before uses, and scopes composed app/package modules independently. It extracts static prompts/profile, signatures, checked constant argument text without changing quoted whitespace, target and source spans; built-in/duplicate/unknown names, dependent field ownership/type, required/unknown args and style cycles are diagnostics. Identity-bearing definitions differ from definition-reusing applications/uses. Semantic containment selectors and first anonymous duplicate-region certificates supplement legacy anchors; overlapping duplicate runs share one exact interval and deeper duplicates cannot hide ambiguity. Formatting/comments do not identify the output; local structural evidence and occurrence within its exact certificate are not nearest-offset guessing. Public `discover_program` parses every checked source, not only the selected declaration.

`generation_intake.rs` owns ABI1 unit IDs, kind/required-primary mapping, association and minimal contract/provenance records. `UnitRecord` persists source owner/kind/label/anchor/optional selector/region plus bind path/revision/span; target/profile/prompt hash/signature; original file/prompt hashes; generator/adoption provenance. ABI/directory identity and region shape are checked. Current files have separate hashes. `associate_inner` compares complete supplied source/record sets, rejects duplicate IDs/claims, displaced same-kind output and one ID satisfying multiple source slots, and retains only uniquely supported current correspondence. Explicit legacy location evidence is exact revision/span only; new duplicate regions require certificates. Prompt-only freshness never invents new ownership.

`apply_bind` checks the inspected revision and same kind; existing bind preserves original bytes/provenance, new bind allocates128 random bits before mutation. Legacy bind recognizes the narrow handwritten family, checks kind/label/current primary presence, preserves bytes and may add a canonical `implementation.js` copy of legacy `server.js`. In-memory legacy compile adoption is restricted to style/view with truthful adopted provenance and no persistence. `read_saved_group` recursively returns sorted current files and refuses symlinks; required primaries gate usable groups, while bound/no-original preparation records may exist without outputs. The pure intake APIs do not acquire leases themselves.

**Frozen build custody.** `generation_store.rs::FrozenGeneration::capture` canonicalizes/deduplicates nested roots, acquires membership/binding read leases, enumerates all source claims and unit groups, rejects nonregular group trees, snapshots consumed paths, checks source membership again, and creates a task-owned temporary mirror. Source bytes, descriptors, association evidence, records and exact source-path mapping are retained there. Resolution never follows later live file replacement: it selects an exact/containing uniquely claimed descriptor, associates against the mirror and returns current saved bytes. Multiple roots qualify artifact IDs ephemerally; persisted IDs/directories remain unchanged. RAII releases held leases; temporary snapshots are not a second persistent binding store. `FrozenGeneration` plus `leases::snapshot_inputs` prevents mixed participating build input, while uncooperative filesystem writers remain outside CAS guarantees.

**Given contracts.** `types/given.rs` separates declaration checking from JS behavior. Carriers use ordinary parsed Given model shapes with only missing When/Then notes filtered. Operations/policies/locks/retention/rules/contracts/events/roles/derivations/presentation/nested generation/migrations in a trait carrier refuse. The chosen native leaf profile permits supported scalar/enum, one array and outer nullability; exact native scalar/default/bound checks, static literal caption/ICU admission, no server/machine/unique invention and contradiction checks apply. Named carriers select one template named for the trait; inline carriers select the attached model. Model applications require explicit defaults, reject declared/previously contributed fields and saved executable checks. Field attachments require a single matching-type template, compatible defaults/bounds and no sibling expansion. Executable checks attach only to nonnullable native text fields, with source-fixed check/text/bool/validate-fields/no-effects contract. Clean units alone contribute contracts; pending missing saved entries remain discoverable. Shared conflict maps and source order are real checker state, not independent per-file registries.

The v1 keyword producer is `state.unique-key@1`, exact model/dependent text-field signature, text input/result, `canonicalKey` source default, `commit-keys` lifecycle and compiler-owned field/rule dependencies. Known producers are explicit compiler integrations, not metadata registrations. Source-derived declaration is default; optional legacy `declaration.json` has strict shape, requires producer/export, and its reads/effects/authority pass the existing effect checker. Keyword contributions carriers, unknown producer and built-in unique conflict refuse. Named applications bind canonical owner/model/field and reuse a unit; arbitrary generated JS is neither executed nor parsed for schema/authority. The contract hash length-frames root/import bytes with UTF-8 path ordering, retaining root-only historical hash when imports are absent. That fingerprint authenticates bytes, not the function's semantic correctness or application purity.

**CLI validation and compile.** `cli/generation.rs` owns positional bind/status and versioned JSON admission, concrete source/group paths, status/inspection/freshness/recipes, bind leases/journal publication, per-kind validation and the lexical JS scanner/closure resolver. Entire body was inspected, including native admission-only lifecycle branches. Unit validation resolves current source correspondence, target/signature drift, Given contracts or view lowering/CSS ownership, expected export and complete imports, then reports consumed paths/hashes separately from original provenance. Files validation is deliberately narrower: a contribution carrier parse is not its unit contract check; keyword implementation files require legacy declaration metadata while unit validation can derive the new source-owned declaration. Target labels in `runtime_targets` are static admission/reporting, not execution in workerd/browser.

The finite scanner blanks comments/strings, retains template interpolations as code, recognizes declared exports/static/reexport/literal-dynamic imports, rejects require/nonliteral/unresolved/bare/Node/file imports and resolves a deduplicated transitive unit-local UTF-8 closure with lexical POSIX normalization. It is not a full JS parser, target executor or hostile-code sandbox. Missing/escaping/import-skew fails with exact unit/file. The matching runtime closure scanner remains an independent consumer of the defined byte protocol, not proof that arbitrary JS has no hidden effects.

`cli/compile.rs::prepare_saved_given/join_saved_given` consumes only applied definitions from the frozen snapshot, checks saved units/carriers/closures, rechecks the semantic program with contributed facts when the real catalog is present, and refuses errors before artifact publication. `given_saved_unit` reads carrier/JS and derives or parses declaration; `attach_saved_given` lowers checked contracts, merges fields, adds field-validation capability, packs one exact closure per unit/fingerprint and rejects disagreement. `ir.rs::lower_given_contracts` creates per-application trait/rule records with canonical target/owner/source order while shared definition identity remains. `artifact.rs::assemble_given_contracts`, `merge_given_trait_fields`, `pack_saved_unit[_closure]`, `stage_saved_unit_modules` and owner manifests preserve exact schema/wire values, verified executable bytes, saved-JS maps plus separate Can owner links, reject staged path collisions and do not invent executable prompt lines. Existing `types::*` reexports name the private Given definitions explicitly.

**Actual Then and runtime consumers.** `then_views.rs` lowers same-module prompted stored-row views, canonical controls/leaves/gates/root style and source binding names; cards remain complete owning bindings, button keeps button identity, local gates stay local. It walks definition/use edges and complete Then prompt sets without a persistent index. `js.rs::ThenBuildJoin` gathers modules, identifies emitted/consumed views, skips styles strictly inside unconsumed views, resolves frozen saved groups, prevents one staged unit serving two definition keys, binds exact style hosts and records missing inputs. Standalone library callers capture the same source/saved boundary and check agreement with already checked source. `attach_saved_then` verifies render/mount exports, packs view imports and owned CSS/assets, and publishes generated-view module metadata. Full UI rendering/lifecycle qualification remains its own owner; source lowering constants alone do not prove once-only runtime behavior.

`packages/cloudflare/src/runtime/given-unique-keys.ts` resolves the actual staged `server.js` and complete transitive closure, recomputes the same byte fingerprint **before** verified import, requires a callable export, and reuses one evaluator per unit/export/fingerprint. `runtime/invoke.ts:6482–6500` joins those rules/field checks into State models; generated evaluators receive projected text rather than Store/commit/identity. State's existing `validateGivenFields` and `createGivenUniqueKeyScope` own strict true/exact text results, sequential call lifetime and failure retention, and fenced claim/release pipeline ownership. The earlier [migration review](state-migration.md) retains the distinct activation/claim-cycle limits; generation acceptance does not migrate deployed rows or release those gates.

## Real public generation, acceptance and reset

Public executable `can gen` JSON calls `cli/generation.rs::run_gen_platform`, forwarding structured request/stdin to existing Node `can-platform gen`. The Rust internal dispatcher intentionally stops generate/refine/retry/accept/reset after admission with not-implemented; this is not public CLI absence. `packages/cloudflare/src/cli/gen.ts` invokes `dispatchControl`, prints its envelope and assigns its returned code unchanged. Internal compiler requests select the compiler-native route to avoid recursive delegation.

Selected actual host duties inspected in `generation/controls.ts` are request ledger/dispatch/error mapping; compiler status/preflight; capture/by-ID scope and current records; handle issuance/prompt rendering; snapshots/context; complete-recipe job grouping/Given preparation; generate/refine/retry/composed acceptance; candidate set/record construction; scratch validation/app checks; promotion leases/fences/closure/journal/markers; separate accept; reset/cancel/edit/recovery. `lifecycle.ts`'s job grouping, current versus fresh baseline, executeJob/finishTries, attempt/fence/session records and reset/cancel joins were read. `acceptance.ts`'s actual compile/build/example/browser commands and input/report checks were read. These are real consumers, not replaced test implementations.

- Capture serializes the bind sentinel and participating source reads, obtains compiler association facts, rejects ambiguity before allocation, records source revisions/current file hashes/record semantics and preserves fresh reuse only in prepare. Full retry includes retained successful outputs in the selected source closure; refine requires a real current baseline plus exactly one instruction carrier. Job prompts carry source-owned interfaces; fresh/retry omit current code as design baseline, refine includes edited files. Complete effective recipes group stage-pure jobs; Given validates before frontend launch, whose context includes the complete Then set. Saved dependency context is copied under read leases and later compared again.
- Each planned attempt records all sibling attempts/units before launch, source digest/revisions, current groups/record, handles/required roles, recipe, fence, instruction and context. `executeJob` looks up request ID/input hash, rejects changed requests, preflights adapter transport/enforcement, creates host-owned MCP session, launches bounded finite tries against readonly snapshot, records process/session state and stops automatic repetition on unknown/cancel. Missing executable produces failed outcome; clean exit alone produces candidate with completion separately reported. No inference from chat text can promote files. Detailed per-adapter network/SDK/process behavior is outside this packet.
- `promotionScopeFromAttempts` requires all nondiscarded required handles, reads actual candidate bytes and constructs replacements plus truthful refreshed record. Multiunit and parent sets cannot be accepted singly. `validateCandidateSet` checks current bindings, creates a scratch source/current-plus-candidate overlay, normalizes records to that closure, validates each unit through the real compiler, then runs the actual app gate for acceptance. `acceptance.ts` requires compile, platform build, at least one executed example, app-local Playwright tests, successful unskipped browser results and candidate session closure; missing browser/tools/tests refuses. Input digest/test-definition rechecks reject mutation during checks. Injected host-test gates do not establish those public outcomes.
- `promoteSet` obtains participating scope/source/context write leases, checks unresolved journals, declaration bytes/fence, captured current membership/record semantics/dependencies and all source revisions. `commitAndFencePromotion` stages one patch journal, commits/applies, then advances attempt fences and writes accepted/index markers. `journal.ts` stages old/new groups and hashes with fsync-backed replace files, marks committed before applying atomic per-file renames, refuses unexpected bytes, retains one previous group and resolves only completed work. Uncommitted recovery retains the complete old set; committed recovery finishes the new set or leaves conflict. Build snapshot readers refuse unresolved journals. No filesystem CAS or arbitrary-writer guarantee is claimed.
- Reset/cancel do not write current saved groups. Full attempt reset advances its fence before deleting pending candidates/binding/schema; cancellation signals recorded/live execution best-effort and advances fence. Reset of one unit in a multiunit capture explicitly removes its handles/candidates, records discard/rescope and leaves the remaining acceptance set complete; it does not claim to kill every process. Edit begin/end coordinates exact existing source/group paths and token-owned locks. Recovery requires the request's stopped-writer confirmation, removes that holder/token's locks only, then recovers journals under leases. No permission prompt, automatic expiry/lease stealing or scheduler is introduced.

## L-GEN-01: composed acceptance returns success for incomplete output

BGEN14 defines code0 as requested outcome succeeded and says requested acceptance cannot succeed after candidate production alone. In actual `controls.ts::composeAcceptance:2562–2604`, a nonempty incomplete job set under `accept:true` returns `code: EXIT_OK` and `okEnvelope`, state candidate, `accepted:false`, `complete:false`, `qualified:false`. This body truthfully discloses incompletion and **does not promote** current files. Its success exit/envelope violates the stronger requested-outcome contract; scripts following the specified exit semantics can treat an unaccepted request as successful.

The source path is reachable without inventing candidate data: `lifecycle.ts::finishTries` returns candidate after a clean runner exit even when MCP required submissions are missing; missing executable also returns failed/incomplete outcome. `controls.ts::executeCaptured:2325–2363` computes completion from required-handle inventory and returns these job facts. A Given-only generation/refinement request reaches `runGenerate`/`runRefine`→composeAcceptance without the separate frontend Given-preparation refusal. The incomplete branch also masks a failed/unknown job's own nonzero outcome. `cli/gen.ts:346–353` sets `process.exitCode` to that0; Rust's public `run_gen_platform` returns child status. `dispatchControl` records the same code/envelope for identical-request replay. In contrast, separate `acceptUnit` reports EXIT_VALIDATION/incomplete-set.

Recommendation: correct the existing composed result/error/exit contract, preserving exact failure/unknown classification and candidate/current preservation, at `controls.ts::composeAcceptance` and its direct assertions. No additional promotion state machine is needed. No runtime reproduction or new test was executed. Exact correction and existing verification are future work only.
