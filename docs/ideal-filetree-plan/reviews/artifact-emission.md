## Open finding and assertion limits

**EMIT-C1 — decimal arithmetic can omit its scalar capability requirement.** `js.rs::lower_temporal_arithmetic` emits and records `addDecimal`, `subtractDecimal` and `multiplyDecimal` for their checked arithmetic operators. `artifact.rs::compute_requires` (526) recognizes only `divideDecimal` and `compareDecimal` for `values.decimal`. An add-only module therefore has an emitted helper without the promised decimal-family requirement unless another import happens to select it. The always-added `canlang.builtins` major is a distinct capability; the source contains no rule making it a substitute for the scalar-family requirement.

`compiler/tests/codegen.rs::gap_helper_add_decimal` checks the actual addDecimal import, while `requires_pins_catalog_and_families` checks a fixture with no scalar imports. Neither inspected assertion closes this producer/consumer combination. Root and migration_review independently compared the producer and separate supported capability names. This is a missing inventory pin, not a demonstrated installed bypass. Correct the existing consumed-helper family census, preserve separate catalog/scalar requirements and refusal semantics, and verify the genuine compiled arithmetic artifact against the actual compatibility consumer. No new registry, public capability constructor or file split is selected.
