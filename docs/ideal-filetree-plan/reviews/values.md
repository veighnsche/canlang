## End-to-end source traces

### Exact representation and operation semantics

`numeric/integer.rs` requires raw BigInts before computation, compares unrestricted values without narrowing, and narrows arithmetic results once. Signed minimum modulo minus-one is calculated on BigInt and returns zero. `numeric/rounding.rs` uses exact quotient/remainder and symmetric half-even ties. `numeric/decimal.rs` retains stored coefficient/scale (including signed-zero scale), aligns add/subtract, rounds multiplication only above18 places and repeating division at18 using guard/sticky digits, and distinguishes construction range errors from computed-result overflow. A finite terminating quotient keeps its minimal scale. Numeric equality ignores scale; the public carrier still exposes stored scale.

Money distinguishes `makeMoney` structural construction (no minor narrowing), shape-only `isMoney`, checked currency-table membership, and arithmetic result checks. `divideDecimal` has a deliberately weaker structural money/money ratio branch than `moneyRatio`; normalizing both through one stronger constructor changes accepted errors/domain. `money(value,currency)` checks currency before value, computes exact minor rational and rounds once. Addition/comparison demand matching currencies; equality across currencies is false. `sum_int`/`sum_duration` collect exact totals before one narrow; decimal sum first validates every element, selects scale, then sums; explicit money currency validates before elements, while inferred empty money refuses. Public `array.ts` remains responsible for actual JS iteration and original objects: the owned Rust vector cannot prove callback/custom iterator/accessor equivalence.

Temporal civil math uses proleptic Gregorian floor division, year1–9999 range checks, month-end clamping and ascending half-open iteration. Equal `dates` endpoints still check limit type before ignoring its value. Public datetime constructor accepts explicit offsets, lowercase t/z and arbitrary fractional precision only when all submillisecond digits are zero; scalar wire accepts exactly uppercase UTC with three millisecond digits. Leap seconds and nonzero submillisecond precision fail. Duration division by int requires exact milliseconds; a duration/duration decimal ratio has its separate operand narrowing rule. Do not collapse public parser and wire grammar or result-only and entry-narrowing rules.

### Public exact route, ABI and errors

`src/wire.ts` parses type IDs before payload/backend work when a general exact backend is selected. Only six **bare** exact scalar names route natively; arrays, nullable forms, nominal types, text/bool and schema/reference-resolver encode stay in canonical TS. `int` has its own ASCII profile: nonstring/non-ASCII stays TS, selected ASCII has a1MiB text gate before tag/JSON allocation, and the native int codec checks complete grammar then signed lexical magnitude before BigInt construction. Signed zero/leading zeros normalize on successful encode. Selected oversized decode and huge encode have explicit bounded diagnostics; they are profile behavior, not proof that every arbitrary legacy error byte is equal.

`bindings/exact-route.ts` defaults to null selection; canonical TS backend sets a synchronous reentry marker so routed helpers can call their original bodies without recursion. Selected `wasmBackend.call` rejects unknown ops before arguments, runs its operation-specific before-tag gates, tags arguments, serializes one request, calls the actual glue once, parses one response and reconstructs public frozen carriers. A semantic native failure does not retry TS. Failure layers distinguish `ValueError`, ordered `SchemaError` violations and transport faults. UTF16 strings/keys use code-unit tags when needed; native lossy guard text is repaired from original string/path occurrences, including colliding ill-formed keys and truncated diagnostics. That repair is host responsibility, not evidence that Rust String can represent lone surrogates.

Native `transport/exact.rs::handle_line` uses selected-int pre-serde admission before ordinary serde/tag decode; its selected cap is derived from the fixed envelope and worst-case escape expansion. Other exact calls retain legacy decode-first transport order, serde nesting/resource behavior and strict operation arity. This is not the structural interpreter's iterative parser/budget domain. The broad operation registry is not evidence that arbitrary JS objects have become inert; V-ORDER-1 demonstrates the distinction.

`bootstrapWasm` copies typed-array internal storage, rejects proxy storage, accepts only nonempty byte arrays or native compiled modules, checks ABI/export/memory/table shape and pins the initialized asset. Repeat bytes compare the private copy; compiled modules compare identity. It detects prior external glue initialization because initSync otherwise reuses its first module without consuming the argument. Initialization does not install selection. Generated glue allocates request strings, converts response strings and frees returned allocations in finally. Native request-string borrowing and response ownership are separate from structural plan/request retention. No OOM/trap-free guarantee is inferred from comments calling semantic failures data.

### Intl, timezone and presentation boundary

`timezone.ts` validates through the current host Intl database on every call and preserves the original accepted zone string. Its two LRU caches retain at most64 calculation formatters each, without changing validation or spelling. `local_date` range-checks milliseconds before Number/Date; the supported UTC range is below2^53, so this bounded conversion is exact. `local_instant` parses closed wall time, validates explicit fold and probes nearby offsets, retaining round-trip candidates; zero is nonexistent-time, earlier/later selects sorted candidates. This is a host tzdb algorithm, not native civil equivalence for every historical zone transition.

`locale.ts` canonicalizes BCP47 with Intl, performs deterministic whole-message lookup across requested/default/source candidates and renders with the **selected** variant locale. `icu.ts` checks placeholder usage/type compatibility and captures resolved args before rendering. Exact plural selectors compare coefficient/scale before category lookup. Category lookup is explicitly bounded to safe JS numeric operands; unsupported magnitudes/decimal spellings refuse rather than guess. Exact display digits remain assembled from bigint/decimal parts; Intl supplies grouping/decimal/minus symbols. Date-only display uses UTC and setUTCFullYear (avoiding year0–99 constructor reinterpretation); datetime display uses configured zone and supported exact millisecond range. Full ICU grammar/parser and all locales/numbering systems remain unqualified here. The actual release must identify Intl/ICU/tzdb/CLDR data; compatibilityDate or native arithmetic success is insufficient.

## V-ORDER-1 — Selected general exact route reads a rejected value before its owning error

**Contract:** the accepted exact-values port contract:13,96,293,364 requires ordered guard/property reads and raw getter exceptions to remain with the original public path; arbitrary objects cannot be eagerly inspected to establish inertness. This obligation is independent from the closed-data native ABI.

**Concrete source chain:** `src/decimal.ts::addDecimal` routes through `routeExact` before `toDecimalParts`. In the canonical TS body, first argument `{kind:'money', minor:1n, get currency(){throw sentinel}}` fails `isDecimal` after reading kind and throws `ValueError('invalid-construction','addDecimal must be a decimal or bigint')`; currency is never demanded. With an explicitly selected Wasm backend, `backend.ts::admitBeforeTag` has no add-decimal branch. `args.map(tag)` enters `carriers.ts::tag`, fails isDecimal, then calls isMoney, whose currency read throws sentinel before the decimal error. The right argument can be ordinary1n. This is an observable failure/read-order discrepancy at the public host entry, before native execution; it is not a wrong arithmetic result inside Rust.

**Scope and correction:** default selection is null and retains canonical TS. The defective path requires the general selected backend, not the parser-owned structural validation path or selected ASCII int. No installed deployment exposure or executed reproduction is claimed. Correct at operation-specific admission/compatibility routing with the original order, or restrict native admission using genuine constructor/parser provenance while retaining the structural public path. A global arbitrary-object scan or blanket native retirement would violate the same contract. Existing poison-specific admission fixes do not prove every operation's domain. Coordinate `backend.ts`/`carriers.ts` with the public decimal owner; establish a focused public TS-versus-selected-backend trace before expanding adoption.

**Independent challenge:** the coordinator independently read `isDecimal`/`toDecimalParts`/`addDecimal`, route selection, `admitBeforeTag`/Wasm call, tag/isMoney and the explicit compatibility contract.
