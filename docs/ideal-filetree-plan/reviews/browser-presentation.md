## Source to current authorized rendering

The compiler emits one source-owned descriptor per page, including static owner/path/title/navigation and callable admission/render functions. Interfaces `handlePageRequestCore` checks method/URL/query/path, matches the actual descriptor, resolves credentials and selected team, loads the current preference/source context and runs the page's admission before rendering. Discovery independently admits static candidates; unavailable discovery marks navigation incomplete and denied candidates are omitted. `buildNavigation` requires an outcome for every candidate, preserves authored order within equal order values and groups by real owner/static group identity. A sidebar entry cannot authorize a route or manufacture an admission result.

The page's read scope is opened lazily after genuine source setup, retains a caller resolver bound to the original credential request, checks request/scope liveness and binds the query runner to the resolved identity. Collection renderers call that bound query, not an invocation/identity supplied by arbitrary child markup. Closing the scope in the owning `finally` invalidates later callbacks. UI row fields and File/delivery projections arrive through these canonical readers. This packet establishes those real joins; it does not replace the remaining review of every State/source predicate and sensitive field projection with a blanket correctness claim.

`buildPresentationContext` derives the comparison key from origin, page/query URL, CSRF and this caller's actor/team IDs. It is client-visible equality data, not an authorization seal. `renderPage` emits the exact main region and poll metadata for poll pages, bounds cadence to whole seconds from 1s to 1h, and returns only main for partial requests. Full responses include the common shell/account/settings and browser module. `fragments.ts` recognizes the HX header and preserves canonical status/error mapping; no independently authored fragment route or second page policy exists.

Collections use current authorized rows and column metadata, validated filters/order/cursor/page bounds, escaped labels/URLs and source-specific selection identity. `controlHref` serializes known query keys; selection helpers modify only the original occurrence's `can-row:` key. GET query/selection state influences an authorized read, not its privileges. Split collections retain their real selected row within the returned result; modal/drawer enhancement does not create a second data fetch or selected-record authority. Gallery URLs are supplied by checked File presentation, not reconstructed from arbitrary IDs. Arbitrary reference and final disclosure profiles remain their owning review subjects.

## Form request identity, drafts and outcomes

Interfaces source form preparation derives checked inputs and protected bindings. `form-binding.ts` separates the exact binding identity from a draft-comparison identity based on the admitted binding context, bound IDs and editable set. UI `forms.ts` emits checked metadata, operation/operation ID/CSRF, canonical action and protected hidden source binding. Browser `bindGeneratedForm` captures the current context and actual connected form, prevents concurrent submission, collects native successful controls before disabling the activated submitter and uses the existing DOM-free submit client. This installed binder explicitly refuses picked Files without a supplied intake route; the public client has the separate upload flow. Native no-JS submission of generated bracketed forms is not qualified.

`submitGeneratedForm` projects the existing flat controls through checked input metadata; it does not interpret arbitrary bracket syntax as business input. The action passes the existing operation-path guard; submission uses same-origin POST, CSRF, exact operation identity and source binding. The Interface operation recipient parses/caps/validates inputs, checks source binding/current source, rereads current session facts before invoking the actual canonical mutation/retained mutation. State remains responsible for ordinary current authority, revision/receipt/replay and commit. No browser abort retroactively cancels admitted business work.

Success must be the canonical JSON mutation result. Error/retry envelopes are validated; a durable rejected attempt alone can receive a new operation ID/binding pair. Unknown transport outcomes retain original request identity for recovery. The binder checks the exact live hidden fields and response pair before updating either retry field; conflicting live metadata cannot be partly adopted. JSON denials become text feedback and retain current drafts. Late results require the same connected form/context; disposal aborts its signal, removes listeners, releases choices and restores only the state acquired by that owner. A stopped old occurrence cannot later restore temporary state over its replacement.

`compatibleNode` compares actual node/tag, control ID/name/type and exact form identity. An identical form occurrence keeps its submitted nonce/binding/CSRF/lifecycle while unrelated poll updates arrive. A changed protected binding replaces the form; matching **draft** identity may transfer dirty editable values and focus into the fresh authority. Hidden values and File selections are not transferred by that draft path. Removed server fields/subtrees disappear. Dirty/select/focus preservation does not itself prove renewed authorization; the fresh server projection and binding inventory must supply it.

Committed local forms trigger one authorized GET of the current page. The refresher captures region/document/context/controller identity, invalidates existing poll bindings around application, and rejects stale results after either fetch or body await. A failed GET cannot undo the confirmed mutation or invent a replacement outcome. This **one-shot reread** is distinct from the authored periodic refresh mutation contract discussed below.

Input-choice assistance reuses the same controls/projector and never owns submission. Parent changes clear dependent values recursively, abort/supersede pending lookups and debounce a new read. Requests capture current action, CSRF, operation identity, bound input arguments and source binding; after reading the body, delivery requires the same sequence and recomputed request key. Response candidates have bounded admitted scalar/ref/enum shapes and safe text labels. Selecting a choice changes existing controls; the eventual canonical operation revalidates everything. Missing/unsupported choice shapes remain unavailable rather than creating an alternate arbitrary-ID submission path.

## Poll, mount, preference and disposal lifetimes

`PollRegion` owns one accepted request sequence per region. Each strict-cadence tick aborts/supersedes the previous fetch, so an uncooperative transport's obsolete result still cannot paint. The wrapper forwards abort and races a transport that ignores it; cancellation of delivery is separate from cancellation of remote work. Context/logged-out/region/visibility conditions are rechecked after fetch and body awaits; stop is terminal for that controller, clears its timer and aborts the owned request. The client explicitly constructs a new current controller on rescan. Strict cadence can supersede a slow read repeatedly; this is not a Work scheduler or authorization to retry mutations.

`applyPollResponse` accepts a successful body only when it contains one main with matching ID/context/poll-context and no nested script/full-document shell. The bounded morph reconciles controls, retains permitted drafts/focus and releases mounts/dialog state on removal. Generated view roots invoke a registered saved mount with the server-embedded view/use/row presentation; cleanup is tracked by use ID and guarded so an old unbind cannot release a newer mount. In-place morph marks/rebinds the mount; late mount registration can replace the acquired callable. A saved mount is application code over already projected data, not another row grant or canonical mutation issuer.

`startBrowserClient` has one live owner per document. Rescan uses a binder snapshot and per-element signature including context, poll URL/context, form metadata/action and view identity; unchanged bindings remain, changed ones release before replacement, and detached/stripped elements are swept. Cleanup attempts every owned release and preserves the first failure rather than abandoning later listeners. Split modal cleanup captures its actual acquired nodes and avoids erasing a replacement's selected state. Native dialogs/popovers own their native dismissal; menus/panels add placement/activation/focus and remove their listeners on disposal.

Gallery previews require same-origin admitted URLs and current actual root/dialog/image/state/button identities, URLs and sequence after each fetch/blob/decode await. Invalidating/closing/disposal aborts the request, removes image/link references and revokes object URLs. Thumbnail decode callbacks also retain exact source/outlet identity. This is a real resource-clearing implementation for its **owned preview**, not proof that all static thumbnails/page text have been erased on access loss.

Preferences use the canonical page URL/form body, native CSRF/version and current identity/descriptor admission. Interfaces validates known fields, current preference version and self/app/owner/team key before a compare-and-save; success redirects to a new authorized page GET. The enhancement follows that response, checks the returned main plus settings field/action identity and current form/context, adopts only the settled settings field while preserving neighboring drafts, then restarts reads. Cancel resets only settings drafts/errors when no save is pending. Unsupported reference/text/date preference leaves do not acquire save controls merely because they exist in descriptors. This is an existing owner boundary, not an app-authored business CRUD route.

Native bootstrap observes relevant context/poll/logout attributes and child replacement, rescans after swaps/popstate/visibility changes and unregisters observer/events when stopped. Ordinary pagehide stops all owned resources. Persisted pagehide marks visibility suspended and restarts scans without arming polls; persisted pageshow clears suspension and resumes scans. These actions preserve a cached document's DOM; they are not a history/private-data clearing implementation. Native login/team-switch/logout POST/303 navigation remains the authority review's real existing flow.

## Concrete source gaps and requirements for correction

**BROWSER-F01 — definitive denial/private-context invalidation is narrower than the required clearing.** On current-context 403, `withdrawPollRegion` removes forms/inputs/buttons/selects/textareas/once and mutation hx controls and polling, while retaining old noncontrol text/images. Stop/context rescan retires callbacks and resources but does not clear all old private DOM. This is observable source behavior against DESIGN:894/993's prior-context/private-value requirement. Preserving authorized drafts through a correctable failure is different from retaining a page after authoritative denial. Source callbacks correctly suppress late deliveries; that does not erase content already painted.

The necessary future correction belongs to existing browser/Interfaces context and refusal owners: specify the trusted current invalidation response/state, withdraw affected private content and retained input state, and require renewed authorization before restoring a cached private projection. Keep available-public content versus invalid private scope explicit. Browser history/BFCache, already-returned generated mount data and another tab's session change need real supported-lifecycle decisions and assertions; this audit does not invent universal immediate session cancellation, retroactive erasure of user copies or a remote permission bypass. Root's authority trace already establishes native auth navigation; it is not invalidated by this narrower presentation gap.

**BROWSER-F02 — default reread failures have no visible stale-state recipient.** `PollRegion::noteFailure` increments failures, optionally calls `onError` and reschedules. `bindPollRegion` supplies no error callback and the one-shot committed-page refresher catches read failure silently. The `htmx.ts::staleMarker` factory exists, but these default recipients do not apply one. DESIGN:993's visible failed/stale authorized read is therefore not established by the installed path. Preserve the existing authorized projection on correctable failure while visibly marking its read freshness; do not change business/source status or use the marker as authority. Existing poll/bootstrap owners should own the feedback, with real response/body failure subjects when implementation is authorized.

**BROWSER-F03 — checked/emitted periodic source refresh has no runtime recipient.** The compiler checks `poll=/refresh=` and `codegen/js.rs:14600–14607` emits exact cadence plus canonical refresh mutation. Current contracts `PageDescriptor` exposes `poll` but no refresh field; UI shell emits GET polling attributes and browser bootstrap consumes GET polling plus the one-shot committed-page reread. No retained-arguments/repeat-trigger consumer is established in UI/Interfaces. Thus a checked emitted attribute is not completed DESIGN:987–989 behavior. The implementation/contract join must either explicitly refuse unsupported refresh at the owning publication boundary or implement the required source-form-armed repeat with ordinary current CSRF/authority, fresh per-repeat IDs, retained same-repeat retry identity, one outstanding occurrence, missed-tick coalescing and context/visibility/logout argument clearing. It must not turn ordinary poll GET into an implicit mutation or fabricate the authored inputs. This is an unavailable producer/recipient capability, not unfinished source inspection waiting for a passing run.

Root independently challenged these conclusions against DESIGN:894/993, actual `withdrawPollRegion/applyPollResponse` and rescan/lifecycle, `PollRegion::noteFailure`, the missing `bindPollRegion` error callback, refresher silent catch and existing stale-marker declaration, and the compiler refresh emitter versus actual UI/contracts/Interfaces recipients. It accepted BROWSER-F01 as a denied-page projection gap distinct from native 303 authentication navigation, BROWSER-F02 as absent visible feedback while transient-error content retention remains valid, and BROWSER-F03 as an unimplemented source-to-runtime join. Future correction has one browser bootstrap/poll writer coordinated with Interfaces current refusal/projection and compiler/schema handoff; it reuses the canonical operation and adds no business scheduler. This was source-only independent challenge, not an observed browser failure or passing qualification.

## Owner decision and completion boundary

Retain TypeScript for DOM identity, FormData/Fetch/AbortController, native dialog/history events and server HTTP/render integration. The shared generated submit/projection client, current identity/session logic and State mutation owner already prevent a second form authority. Bootstrap's repetitive cleanup/liveness checks serve different acquired resources and await boundaries; replacing them with a generic capability object or splitting by text length would obscure which original node/controller/context owns each callback. Existing neutral field-binding and collection-selection helpers are appropriate shared stateless units. No new code split is selected by this review.

The strongest supported alternative is a maintained browser reconciliation/lifecycle framework with JS/TS bindings: it may reduce custom morph/event machinery but still must preserve Can's source binding/draft split, denied-content policy and exact context/input/currentness. Rust/Wasm could own pure transforms but cannot remove DOM/Fetch callback and authority joins; it would add serialization and lifetime interfaces. Keep semantic descriptors/compiler facts in their actual owners and the live browser recipient in TS. No new package/process/library mandate follows from the gaps above.

P-R03 and the named browser follow-up can complete their bounded source tracing while BROWSER-F01/F02/F03 remain concrete correction/contract work. Exact retained files and real consumers are identified above; unsupported features do not keep the review perpetually unread. Independent challenge must preserve the distinction between implemented callback suppression, missing private-content/freshness/refresh recipients and separately unperformed browser qualification. Root alone reconciles shared findings/tasks/tree/status; this document starts no implementation or browser run.
