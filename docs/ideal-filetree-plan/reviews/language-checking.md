## Requirements and actual workflow

The governing contracts are [GRAMMAR](../../specification/GRAMMAR.md) and [DESIGN](../../specification/DESIGN.md), especially §3 expression/context/default semantics, §5.1 independent typed example expectations, §7.1 row-only retention and §9 UI grants. Syntax acceptance, semantic acceptance and executable-profile support are separate. Arguments evaluate once in authored order even when mapped into named parameter slots; defaults see earlier inputs and admitted context; narrowing uses lexical identity and cannot grant authority. Examples vary declared inputs/fixtures and submitted request envelopes without manufacturing production identity, audit fields or authorization.

`syntax::parse_source` admits bounded source offsets, then lexes, lays out and parses lossless CST; semantic analysis indexes declarations before resolving bodies, types declarations before executable bodies, then collects effects and checks examples. `check_program` merges parse → resolve → types → effects → examples diagnostics. `check::{dedup_diagnostics,sort_diagnostics,has_errors,exit_code}` keeps the earliest identical report, stable `(file,start,code)` ordering and signature-order ties, and error/warning distinction. `CompleteInputs` is a caller assertion that passes ran, not an independent execution receipt; a clean/complete check is not itself proof of an installed runtime journey. Shipping/cohort refusal remains the separately reviewed emit/CLI boundary.

## Open source findings

**CHECK-C1 — retention helper extraction can lose the contextual ban.** DESIGN §7.1 excludes sliding `now`, caller and operation context from retention; §3 preserves consuming restrictions through helpers. `types.rs::check_retain_until` (7584) checks datetime/null shape, scans its immediate expression subtree for `actor`, `now` and `operation`, and gathers nonpure catalog calls. It registers a strict root, but `check_strict_membership_closures` (8396) follows selected helper/member bodies only for membership reads. `resolve_derive_function`/`resolve_derive_rule` (4493/4540) use `with_facts` with clock/operation available, and `phase2_derive` (8897) permits ordinary pure helpers using those facts. Thus extracting an otherwise forbidden clock expression into a datetime-returning helper can avoid E3017 at the retention consuming site. `effects::walk_rule` transports the until NodeKey, and IR's model/retention registry lowering carries the anchored expression; it supplies no second contextual closure check.

This is a source-supported analyzer restriction gap, not a demonstrated installed expiry bypass or executed reproducer. Correct it in the existing retention/type dependency closure, following resolved selected helpers/members/default dependencies with their actual owner identity. Preserve legitimate pure row-dependent helpers and direct/imported equivalence; do not ban all helpers or introduce another proof store. A meaningful future integration assertion should compare direct and extracted forbidden dependencies alongside accepted row-only retention.

**CHECK-C2 — expected example values receive inference without a compatibility check.** DESIGN §5.1 requires independently authored *typed* expected values and exact typed equality. `types.rs::{check_example_table_rows,check_example_assert}` (6325/6396) type observations and call `expr(expected, observed_type)` for expected cells, but never validate the returned actual type against that observation. `expr` records/returns the actual type; `type_string_literal` (15274) keeps a string as Text when the expected type is Int. The supplied expected type is contextual inference, not an assignment check. An integer observation with a text expectation therefore has a source path without the required mismatch diagnostic. `examples::check_sequence_assert` checks result availability rather than closing this typing gap.

Correct the existing expected-value boundary, preserving enum/numeric contextual inference and independently authored values. Example contexts use `strict:false`, so merely inserting the existing strict-guarded `assign_ok` call is insufficient. Keep negative submitted inputs/request overrides possible; their runner-typed failure cases are distinct from mistyped expected values. Runtime equality failure cannot substitute for required checker typing. No reproduction or product regression was run.

## Assertion evidence and allocation

Source inspection of `compiler/tests/syntax.rs` establishes recursive corpus parse/CST byte coverage, not semantic acceptance. `b4_parse.rs` asserts actual recovery/description spans and separates accepted invocation syntax from semantics. `analysis.rs` checks exact diagnostic codes/primary locations, sibling recovery, default scopes/operator cases and actual CLI JSON/error exits; real-catalog cases can skip when their generated catalog is absent. `b4_resolve.rs` checks canonical CRUD aliases and contextual facts in failed declarations. `ui_guard_narrowing.rs` checks production analysis/IR gate scope across siblings/child rows. `checked_query_facts.rs` checks alias identity and complete clause facts, not native query execution. Callback tests inspect actual emitted owning descriptors/read grants and generated syntax; these are not universal runtime authorization assertions.

`effects.rs` asserts source-ordered model/rule inventories and direct `row.created+30d` retention shape, not transitive clock exclusion or installed expiry. `default_read_dependency.rs` has a real generated/native invocation subject: it asserts admitted context identity, omitted read/count versus explicit override, exact values and unchanged domain rows/history. This audit read those assertions without running them. `b4_examples.rs` checks selector channels, canonical fixture identity, expected/error exclusivity, stored-versus-value metadata and altered metadata refusal. Its `emit_test_only` explicitly bypasses ordinary completeness admission; generated JS inspection is not ordinary shipping qualification. `typed_bdd.rs` uses constructed IR/output assertions, not an independent source semantic oracle. No inspected assertion establishes either CHECK-C1 helper extraction or CHECK-C2 incompatible expected-cell diagnostics.

Retain these exact Rust syntax and analysis leaves in the compiler crate, with `check.rs` owning aggregation and existing `types/given.rs` owning its private contract contribution. The strongest supported alternative is a TypeScript checker near runtime/catalog/SDK consumers, which could reuse host-facing data handling; it would transfer lexical identity, offset recovery, imported ownership, narrowing, pass/error ordering and native CLI/LSP tables or leave two competing authorities. The two defects require corrections at current semantic owners, not such a transfer. Keep host execution, leases and provider enforcement in their existing TypeScript owners. This is a bounded maintenance/authority decision, not a language-performance claim or a new split/port/process.

Root independently read both finding chains: retention's immediate-name/nonpure checks versus membership-only helper closure, resolver contextual facts and IR/JS retention transport; and expected-cell expression typing, Text-versus-Int behavior and sequence availability. The challenge accepted the narrow gaps while rejecting installed-expiry and runtime-execution claims, and highlighted `strict:false` and preservation of negative inputs.
