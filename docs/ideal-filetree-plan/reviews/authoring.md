## Actual producer and recipient chains

**Native intake and lifecycle.** `transport::read_message` bounds complete headers, including terminator, to 64 KiB and declared bodies to 64 MiB. Header/body growth is incremental and fallible; an absent body does not preallocate the declared size. CRLF and LF headers, split reads and interrupted reads are supported. Equal repeated Content-Length values are accepted; conflicting lengths, missing/bad lengths and over-budget sections fail. `server::run_stdio` closes on framing failure because no reliable next boundary exists; torn EOF retains the existing clean-disconnect result. Within a complete frame, malformed UTF-8/JSON yields a parse error and later well-framed messages remain usable. These are distinct failure classes.

`transport::parse_call` rejects duplicate reserved JSON-RPC keys, illegal IDs and malformed envelope/params before method dispatch. Integral numeric IDs are interpreted exactly within i32 without floating-point rounding or exponent-sized allocation; response ID lexemes remain intact. Unknown extension fields are tolerated. The synchronous server enforces PreInit/Ready/Shutdown, ignores sync outside Ready, answers unknown methods, clears queued diagnostics on shutdown and distinguishes exit-before-shutdown. Its request cancellation notification is deliberately a no-op because requests execute synchronously; client cancellation still suppresses delivery. This does not promise preemption of expensive analysis while the process is blocked in a callback.

**Sources and project ownership.** URI strings remain protocol document keys. `uri.rs` projects only supported file URIs to native display paths without filesystem reads; unsupported authorities, invalid paths and non-file schemes keep their URI spelling. Workspace roots select local discovery and catalog owners; the longest matching root separates nested workspaces. `discover_sources` caps files/directories/aggregate bytes, bounds actual reads after metadata admission, skips hidden/build/vendor directories and directory symlinks, and reports incomplete intake instead of supplying a partial project. Overlays win against disk. Watch/save/root changes refresh disk and per-root catalog selections; closed imported diagnostics are published separately and cleared when their source disappears.

`RealAnalysis::snapshot/project_files` selects the checked connected provider/consumer graph, reports ambiguous providers instead of guessing, and uses ordinary parser/checker/catalog facts. Its metadata cache stores path/hash-qualified names/byte coordinates, not reusable SourceIds or checked programs. A private SourceDb rebuild retains only live texts, cancels obsolete queued work before numeric IDs can be reused, remaps current tasks and reconstructs spans against the current owner. Caches therefore do not establish authority for a stale owner by numeric coincidence.

**Version and epoch.** Open/change retain immutable text and a source ID; same-text changes can reuse the source while still updating the version. Pending diagnostics require the exact URI, version **and SourceId** still be current. Closing removes ownership, cancels its queue entries, clears diagnostics and restores current disk as applicable. `apply_did_change` accepts the last full-text change in an admitted notification; incremental-only changes are ignored. It validates exact i32 version shape but does not independently require a larger version than the prior one. This is observed last-arrival behavior, not a newly claimed monotonicity defect: the repository's own client sends increasing wire versions and process tests assert increasing revisions; a separate typed-output public batching subject deliberately reuses a version on a fresh open and still suppresses the obsolete source. A proposed stricter duplicate/decreasing-version policy needs an explicit contract choice and compatibility subjects first.

The TS client associates each URI with the actual TextDocument object, host version and a monotonically allocated wire version. Reopen at the same host version gets a new wire epoch. `requestDocument` captures that owner and rejects cancellation, document replacement, changed version or retired transport before converting the result. Waiting-for-startup requests check the original host version before synchronizing. Open diagnostics require the exact current wire version; unversioned closed diagnostics are limited to the appropriate local folder and cannot replace an open overlay. This protects source ownership across asynchronous callbacks rather than relying only on request IDs.

**Unicode and presentation.** Shared `LineIndex::to_lsp` clamps invalid byte positions to scalar boundaries and counts UTF-16 units, handling CRLF versus bare CR explicitly. `ide::queries::offset_at_position` performs the inverse request mapping: missing lines refuse, excessive columns clamp to line end, and a mid-surrogate coordinate clamps to the scalar start. Tokens use that same index and UTF-16 lengths; folding/selection derive from current CST nesting and return sorted/deduplicated folds or expanding selections. The TS client computes outgoing UTF-8 frame lengths separately from UTF-16 edit positions; Node string decoding preserves multibyte chunks and `takeUtf8Prefix` counts bytes for complete bodies. No declaration that byte length equals JS string length is used for production framing.

## Rename, formatting and actions

`Snapshot::rename_at` collects actual resolved symbol/import-alias/local uses. `safe_rename_at` reparses/rechecks a candidate with the edits, rejects poisoned duplicate/shadowed declarations, requires each replacement remain one name token, and compares declaration identities of resolved names **outside** the changed set to catch capture. Existing unrelated partial-buffer diagnostics may survive only within its retained diagnostic comparison; unresolved same-spelled uses refuse rather than being silently omitted. Imported provider names and explicit local aliases have separate identities. This is stronger than text replacement, but does not prove arbitrary exported identity changes safe for installed deployments.

`RealAnalysis::rename_files` additionally rejects invalid names, ambiguous/incomplete project evidence and source/hash mismatch. The LSP server refuses a rename when any affected target is closed, because it has no overlay version for that target; cross-file renames require negotiated `documentChanges`. The extension first requests references, opens affected local files through the editor, refuses cross-folder routing, rechecks the initiating document, then requests rename. The server recomputes the complete edit set; preflight references alone do not authorize the rename. `toWorkspaceEdit` checks every target's current wire version and valid ranges, rejecting the whole result rather than applying only a partial set. It converts those checked changes to VS Code WorkspaceEdit objects; it does not carry an LSP version into the later VS Code edit object. Delayed application of an already returned/cached action after subsequent edits remains an editor-host qualification boundary; this source review establishes response-time rejection, not a fresh observed late-click guarantee.

`format_source` parses first and returns no output for syntax errors. It uses physical lexer lines with delimiter/schema/option context to normalize whitespace and line endings, preserving token ordering, literal bytes, description content and inline/suite shape. It does not reorder imports or repair policy. LSP formatting returns one current-buffer replacement only when changed; its API returns no edits on invalid syntax, while CLI formatting has a diagnostic error outcome. Thus the library's error is not proof that the editor visibly explains every no-op. The editor's common request owner check suppresses late formatting results.

The lint driver runs on the program's actual checked files and current reparsed CST, sorts diagnostics canonically, and keeps warnings/info separate from compile-blocking errors. Rule selection, not text appearance alone, owns deprecation metadata, literal-false unreachable execution, conservative unused-binding/query-alias attribution, opt-in nearby shadowing, proven non-null marker redundancy and description nits. Names bound elsewhere intentionally suppress uncertain deprecation/unused attribution; contextual facts are not generic shadow warnings. Unused declarations and descriptions have no automatic deletion fix. Shipped lint fixes are narrow: remove whole-line code proven unreachable after exact `require false` while retaining comments/refusing description detachment, and replace `?.` only for a checker-proven non-null receiver.

`ide/fixes::fixes_for` supplies no analysis-diagnostic repairs; permission/default/identity/migration decisions are not guessed. Lint fixes get the actual source hash, valid byte spans and deterministic order. The IDE fix applicator recomputes the text hash and validates all ranges/overlaps before building output. Lint's lower-level `apply_fix/apply_fixes` compares the **caller-supplied** current hash with expected hash and validates spans/overlaps; its documented precondition requires that argument actually hash the offered text. The live LSP producer uses the snapshot hash and discards unrelated-file/hash fixes before conversion to versioned actions. Do not describe the raw lint helper as independently authenticating arbitrary caller text, or invent a hostile-caller exploit from violation of its explicit precondition.

## Client process lifetime and concrete framing debt

The extension admits native tools only in a trusted workspace, selects one client per local folder with a separate loose-document identity, and routes providers once through that live owner. Startup waits for successful initialize/capabilities and initialized write before document synchronization. Restart coalesces, retires old clients before recreating them and replays current text. Root changes dispose removed/nested owners and reroute overlays. Request and initialization deadlines settle unavailable work. Synchronous write failure and asynchronous stdin error retire document ownership and pending requests; child error/exit clears diagnostics and onExit notification is once-guarded. Stop withdraws admission immediately, requests shutdown then exit, closes stdin and kills stragglers after bounded deadlines. `stop()` resolves at forced-kill request/finish; actual OS process exit/reaping is separately asserted in the process integration. This is narrower than a guarantee that every descendant or pipe has closed.

**AUTHOR-F01 — client framing failure containment.** `client.ts::onData` appends to its string buffer before finding CRLF/CRLF, with no aggregate header cap. A peer sending an unterminated header can retain unbounded text even after ordinary request deadlines settle. Its first unanchored `/Content-Length:\s*(\d+)/i` match neither validates the exact header name nor compares repeated lengths. Missing-length garbage is dropped with continued parsing; for an oversized frame whose body has not arrived, it clears the prefix and later treats remaining bytes as candidate headers. Subsequent bytes cannot generally identify a safe frame boundary. The native reader's explicit close-on-framing-error rule and finite header acquisition do not extend to this recipient.

The concrete observation is local failure-containment debt in the configured native-server client, not a demonstrated remote permission bypass. Native 64 KiB is an explicit local support budget, not a universal protocol requirement or an automatically ratified editor budget. Root independently read both actual readers and the write/finish lifecycle, confirmed the missing bound, unanchored-name/duplicate ambiguity and unsafe partial-oversize resynchronization, and accepted retaining the client owner. Future repair belongs in `editors/vscode/src/client.ts::onData` and its existing lifecycle/process subjects: choose an explicit finite header policy, preserve UTF-8 byte boundaries, admit only unambiguous lengths and retire transport/pending/doc ownership when framing is no longer trustworthy. No new façade or library is necessary to make that result concrete. Malformed-peer tests have not been executed or added by this audit.

## Ownership decision and follow-through

Retain the current Rust crate's `lsp` transport/session/output/URI leaves and IDE/query/fix/token/structure, formatter and lint owners. They share physical source IDs, CST, resolve/type/catalog facts and diagnostics; moving the semantic layer to TypeScript would create another checker or require a new complete protocol for immutable sources and declaration identity. TS remains the VS Code host adapter. The strongest supported alternative is a maintained LSP client library: it could remove handwritten framing/lifecycle code, but does not supply Can's document epoch, project preflight, safe-edit policy, catalog ownership or installed behavior automatically. The current zero-dependency build gate is an implementation constraint, not a user policy proving custom code superior; reconsider it if library adoption removes real maintenance burden after preserving these joins. AUTHOR-F01 can be repaired within the existing owner without waiting for that architectural choice.

Exact retained leaves above already occupy the desired tree; old monolithic `ide.rs`/`lint.rs` selectors should resolve to their landed successors, not become new extraction tasks. Root owns shared tree/task/findings changes. AUTHOR-F01 is a concrete future client repair with existing process/lifecycle verification recipients. Remaining installed editor, delayed action application, full shell-engine and broader language-shape qualification are bounded evidence work, not permission to rewrite the compiler or a claim of completed release readiness. This packet runs none of that work.
