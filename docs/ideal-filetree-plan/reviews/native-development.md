## Contract and reviewed boundary

[can-dev-server.md](../../design/can-dev-server.md), particularly its supported Miniflare contract, subordinate protocol and state-transition table, establishes the requirements independently of the implementation: Rust alone owns admission/publication/session lifetime; source/check/serving freshness/cleanup are separate facts; a failed candidate preserves the previous preview; source changes and cancellation must be checked at owner selection. Stop closes admission before acknowledgement, joins owned jobs, retains failed release authority and retires the claim only after confirmed cleanup. Private transport permission is separate from ordinary application Identity, membership, Origin and CSRF. Scratch stays owned until its consumers terminate. Neither a log nor an exited host alone proves readiness/release. AGENTS requires coherent owners, permission/failure preservation and real integration subjects.

## Established workflows and limits

The public compiler `can dev` dispatcher forwards fixed arguments and child status to the native `can-dev` binary. Native `app` builds the selected configuration, attaches only to the matching verified owner or starts that owner. `Owner::start` claims control readiness before application readiness. `check` binds a recaptured ticket; unchanged exact admitted inputs may reuse the serving generation. Otherwise the worker stages and runs the captured compiler, retains its result, obtains owner candidate admission, runs real preview preparation, rechecks captured inputs and sends `Prepared`. The owner verifies lifecycle/input/admission again and selects the candidate. Old serving resources are retired afterward; compiler errors, source incompleteness and preview build failure preserve their separate outcomes and last good serving handle. Late source hints prevent the owner from certifying confirmed currentness. The missing cancellation check at that final fence is L-DEV-01.

Stop first changes `SessionState`, cancels check/service/queued example work, closes all gateway access and the watcher, and acknowledges only the stopping transition. Cleanup waits for actual workers; generation release requires host `Released`, SDK scratch removal and gateway shutdown, or verified host-group termination followed by local cleanup. Failed release keeps the generation/host/claim and blocks resource growth. `stop.confirm` reports resource release before endpoint retirement; `control::retire_when_drained` waits for the full final response, and public CLI stop then confirms endpoint/process retirement. Attached UI cannot dispatch its own stop action; explicit external control stop remains a supported owner command.

Runtime supervision and compiler supervision have different completion subjects. `runtime::shutdown` retains the unreaped session leader as its signal anchor through TERM/KILL, then requires direct-child reap, private process-group absence and both stream-reader completions; after reap it sends no further signals to a potentially reused PID. Compiler `await_owned` creates a private group and escalates cancellation/timeout/output overflow, but completion observes the direct child and both pipes; it does not certify private-group absence. Neither mechanism promises arbitrary escaped/`setsid` descendants. The supported Miniflare API can internally restart Workerd; native transport health plus preparation probes are implemented, immediate continuous inner-runtime restart observation is not. These are explicit existing bounds, not new guarantees or a reason to invent another supervisor.

## Source findings

**L-DEV-01 — observed request cancellation is absent from the final owner publication fence.** The controlling transition table requires cancellation recheck at owner selection and no late publication for cancelled request work. `control.rs::serve/await_handler` marks the request token cancelled on disconnect/timeout; `owner::check` passes that token to the worker and retains it in `Loop::cancel`. `check_worker.rs::prepare` performs its last cancellable `capture::is_current_with_phases` and then queues `Event::Prepared`. `owner.rs:663` `prepared` calls `select`; `select` at line 687 checks inputs, installs the observed backend, calls `runtime_ready` and `state.publish` without inspecting `self.cancel`. `state::current_ticket/publish` checks Running, active operation, confirmed capture and input/revision identity, but no cancellation token. In contrast, `Loop::reuse_serving` explicitly checks cancellation.

Consequently, cancellation already set after the final worker check and before owner handling can still publish while the owner remains Running. Stop is separately protected by lifecycle admission; this finding does not claim stop bypass, stale-source admission or universal instantaneous cancellation ordering. The worker queues `Prepared` before `Joined`, so the owner still has the check token at this fence. Correct at the existing owner selection boundary: reject observed cancellation, retain the old preview, finish with the existing typed cancelled outcome and release the candidate through the existing custody path. Do not move publication to the worker/host or add another controller. Root independently read the worker send, owner select, state gates, reuse cancellation, control token producer and contract, and accepted this bounded source finding. No race experiment was run; the inspected integration assertions do not cover this final publication interval.

**L-DEV-02 — fixture staging scratch is removed after an unconfirmed SDK join.** `preview.rs:886` `stage_closure_fixtures` creates `can-preview-stage-*`, passes it as `testkit.stage`'s `workDir`, then unconditionally attempts `remove_dir_all` at line 902 before propagating the result. This directory is not registered through the existing generation `resource.paths` custody path. `sdk.rs::call` returns `CLEANUP_REQUIRED` if a failed/cancelled request's subsequent cancel/join cannot be confirmed; it correctly retains its own payloads and parent resources, so that return does not prove the host operation ended. The real fixed `host/sdk.mjs` `testkit.stage` calls Cloudflare `runtime/example-bindings.ts::stageClosureFixtures` → `assembleClosureContext` → `runtime/modules.ts::assembleModules`, which asynchronously creates/verifies staged module files; subsequent fixture imports and suite loading consume those file URLs. Host release waits outstanding operations, but that wait can exceed the SDK cancel deadline.

On this actual failure branch, Rust may remove staging while its host consumer remains active; the operation can then fail on missing files or race recreation, and the native resource registry cannot clean a later recreated tree. The ordinary successful/joined path may remove scratch safely. Retain this directory under the existing generation resource registration until confirmed join/release, and report cleanup failure without dropping ownership. This is a scratch-custody correction, not a proposal for new storage/process ownership or transactional fixture replay. Fixture staging's documented partial-write semantics remain; cancellation must not blindly retry uncertain fixture writes. Root independently read the scratch creation/removal, SDK unconfirmed-join retention, fixed host call and actual assembly/import consumers, and accepted this bounded custody finding without a reproduced run or transactional-fixture claim.
