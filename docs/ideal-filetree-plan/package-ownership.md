# Package, language and hosting ownership

The exact [inventory](catalogue/inventory.md) and primary source-unit records define each retained leaf and selected successor. Retain **13 JS workspace packages**; package count is not slice count, crate count or process count. No package merger, language port, new binary, daemon, sidecar or database is selected.

| Defining owner | Current / selected substrate and hosting | Strongest supported alternative / concrete tradeoff | Governing source and cutover |
| --- | --- | --- | --- |
| Compiler / authoring | Rust compiler library, `can` binary, CLI/LSP; TS VS Code host and active Python syntax tool retained | TS compiler could share JS libraries but must recreate native source identity, diagnostics, lowering, CLI/LSP and installed delivery. Standard editor client may remove custom framing but needs package/currentness/install proof. | L01–L03; one fresh private source context and unchanged public compiler APIs |
| Native development | Rust `can-dev` serialized session/claim/generation owner; fixed Node SDK/browser bridge | Node-only removes IPC but transfers actual claim/current-generation/process cleanup authority. Recommendations are technical judgments under current contracts, not a user-imposed Rust-only/TS-only policy or measured performance superiority. Primary/challenger arguments and evidence limits are in the current [reviews](reviews/index.md).
