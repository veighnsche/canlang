# Implementation work

Use the [remaining-work list](../implementation/REMAINING-WORK.md) for functional gaps and dependencies. The [architecture guide](../ideal-filetree-plan.md) and [ownership boundaries](finished-product/ownership.md) explain where behavior belongs.

A task should describe a useful outcome and the concrete prerequisites needed to implement it. Coordinate overlapping edits, preserve behavior at producer and consumer boundaries, and check the affected workflow and relevant failures. Routine work does not need a formal packet, owner form, review round or merge checkpoint.
