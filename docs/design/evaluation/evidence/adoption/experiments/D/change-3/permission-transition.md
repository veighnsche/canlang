# Prospective permission schema/setup

Builds on ../change-2. Add nullable Company.owner (PROTECT) and Company.stewards M2M; create ReviewGrant with company/member, fixed A code constraint, explicit expiry, grantor/granted_at and revoked_by/revoked_at. Owner/steward authority has no automatic staff/superuser inheritance and no broad Request read access. Operator must explicitly pin company owner/stewards from current members; absent owner/steward assignments deny grant administration. No deployed predecessor/role population is asserted. Generate exact migration dependencies only against an identified project schema.

Every new scope query uses fresh current user/membership plus ReviewGrant SQL predicates revoked_at IS NULL and expires_at > admission time. Expiry is aware with explicit offset, USE_TZ=True. Historical granted/revoked metadata is retained, with no deletion route. Repeat revoke preserves the first revoker/time. Multiple grants are additive: revoking one removes that grant; remaining independent manager/owner/temporary grants still apply. To remove all temporary access, revoke all active grants for that member (visible to owner/steward). No immediate cancellation of an already-admitted/ongoing export or recapture of downloaded data is claimed.

Current-member eligibility is checked at creation and again via principal at every read/tool; operator changes to company authority are checked freshly for each new grant/revoke. Runtime, concurrent revocation/admission races, clock synchronization, grant migrations and browser/MCP integration remain unverified. The data-transition blockers described in transition.md are inherited.
