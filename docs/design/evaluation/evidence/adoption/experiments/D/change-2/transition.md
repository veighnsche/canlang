Source predecessor is ../change-1/equipment/models.py (a saved draft, not an installed schema). That field is note TextField(blank=True,max_length=4000,null=False); its empty string and nonempty text values remain byte-for-byte through RenameField(note,details), with no strip/coalesce. No actual null records are asserted. If an installation instead permits null, first pin that schema and retain its null setting on details; this draft must not convert those nulls to empty strings or activate against unknown state.

Title stays captioned Request but max_length narrows from160 to120. transition_operations.py gives exact supported RenameField/AddField/AlterField/RunPython notation without an invented Migration class/dependency/history. The operator generates/pins actual dependencies against the verified old artifact; stopping app/MCP writes prevents a new long title between preflight and schema activation. Run preflight with historical Request on the selected DB alias; any stored title >120 blocks. Owners must explicitly correct open titles through change-1's old 160-character/versioned contract, then repeat preflight. Do not truncate, rewrite claims automatically or run the new app first. Archived long titles cannot be corrected through that old artifact; they remain a blocking unresolved policy case requiring an explicit business-approved historical correction contract, which is not invented here.

Active Intake JSON rows receive a preserving note→details key rename and optional empty cost_centre; preview version advances so users must review the new120 limit before committing. Immutable Evidence JSON and completed Intake outcomes keep historical note keys and text; they are evidence of the original operation, not rewritten claims. Completed intake disclosure uses a copy/projection to current details/cost_centre keys without altering stored evidence. A migration is deliberately irreversible for this intake adaptation without separately pinned rollback semantics. Fresh installs may build directly from current models after an empty-population proof; no installed population is claimed.

Evidence required before activation: actual migration graph/schema/nullability, saved predecessor source hash, request title preflight outcomes, resolved long-record corrections, backup/rollback plan, writers stopped, PostgreSQL migration execution and post-transition text/empty/null equivalence plus browser/MCP/CSV checks. None of those deployment proofs are established by this syntax-only draft.
