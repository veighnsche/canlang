# Primary interface documentation facts

Retrieved 2026-10-04. These facts describe underlying tools, not executed Can behavior.

- The pinned [MCP tools specification](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) supports paginated discovery, named JSON-schema tools and tool-list change notification. Names should be unique and case-sensitive, 1–128 characters, using letters/digits/underscore/hyphen/dot. Structured results should also include serialized text for compatibility. The protocol leaves interaction patterns to clients and recommends human oversight. Can's namespaced canonical registry fits that contract; human confirmation is not a new source permission or code-edit grant.
- [MCP authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization) requires protected-resource/OAuth discovery and resource audience validation. Can still owns per-call current principal/team/row/field checks. Provider OAuth is not business authorization. A pinned supported protocol version needs an installation/update policy; no upgrade is silently assumed.
- [HTMX documentation](https://htmx.org/docs/) describes full/partial response exchange, focus restoration using stable control IDs, history restoration and configurable status swapping. Its ordinary defaults do not swap most error responses. Can DESIGN:591 already explicitly assigns that configuration to the shared runtime. Preserving unsaved input, focus and safe conflict values requires that shared implementation; an imported helper does not establish successful UX.
- [daisyUI Drawer](https://daisyui.com/components/drawer/) provides responsive sidebar/drawer component patterns. Can's shared UI must add actual keyboard/focus/label/accessibility behavior. Bounded primitives can reuse its presentation; the CSS library alone cannot prove staff task completion.
