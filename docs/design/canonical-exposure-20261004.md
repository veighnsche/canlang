# Canonical operation exposure — 2026-10-04

## Verified issue and decision

Add one optional generated-CRUD publication allowlist, `expose=create,update`, while retaining the current default when omitted. This is an applied shared draft contract and new syntax. It changes public exposure, not enabled lifecycle, authorization or the canonical operation identity. DESIGN/GRAMMAR/REQUIREMENTS now define the exception; the standalone witness specifies its translation without implementing a compiler, dispatcher or library.

The immutable evaluated [change-1 source](evaluation/evidence/adoption/experiments/C/change-1/app.can) sets a trimmed archive reason and calls its existing canonical Request.delete in the same transaction. Owner/open guards, the final archived-reason invariant and the established-reason lock retain the evidence. The nested call still checks ordinary membership/current Employee admission and versions. Direct delete has no writable reason input, so a normal reasonless open request fails and rolls back. No successful authorization bypass was found. The demonstrated problem is an extra unusable public operation under the selected-package default, as [the original review](evaluation/evidence/adoption/experiments/C/review-changes.md) states. The evaluation artifact remains unchanged.

Existing rules were read before selecting an extension: DESIGN §1 and §12 publish enabled CRUD from selected packages, keep import-only executable dependencies internal unless explicit selected interfaces expose them, and do not publish a target merely because an internal call uses it. §5 makes `delete=none` a lifecycle prohibition, including the documented delete effect/internal call; it cannot preserve this archive action. Its one registry and unchanged call admission already provide the needed execution mechanism. GRAMMAR's closed CRUD attributes currently have no exposure control.

## Exact canonical draft contract

A CRUD declaration may author one optional `expose=` attribute. Its value is a comma-separated closed selector list containing only `create`, `update` and/or `delete`, or the single sentinel `none` for no public generated CRUD. Unknown selectors, duplicates, combining `none` with another selector, or naming a disabled operation are errors. Omission permits public exposure of all enabled generated CRUD, preserving the current default. There is no second `hide` spelling, `all` spelling, operation manifest or per-package wrapper requirement.

The allowlist constrains publication of that owner's generated CRUD through product selection, explicit selected UI references, MCP discovery and generated external routes. A nonlisted operation is not advertised, mounted or externally invocable through those interfaces. An explicit public form/action/edit/delete reference to it is a checked source error; an imported type or another product cannot override the owner's exception. An unselected dependency still needs the existing positive selected-interface exposure rules for a permitted operation: listing it in `expose` does not by itself publish it. Read/list exposure and field grants are unchanged. A bound external interface cannot use this exception to advertise a route its owner excludes; normal binding compatibility must validate availability.

Every enabled generated operation remains in the same canonical registry for normal internal execution. Excluding delete does not remove its definition, change archive/remove mode, disable the owning delete effect, prune hooks/resources, or prevent a normal canonical `call` to it. `delete=none` continues to disable deletion and cannot be overridden by `expose`. Export/import name visibility likewise stays distinct from public publication. Internal calls retain the original actor/team/owner transaction and recheck `by`, inputs, typed references/expected versions, `when`, locks, final invariants, replay and disclosure; exposure confers no privilege and supplies no app-controlled authority mode. No alternative deletion method is introduced.

Lower an excluded enabled operation to `expose:false` on its existing operation registry entry. Omit the property on permitted entries, keeping the existing default. The registry still carries the same handler/kind/model/by/inputs/when/mode. UI, MCP and generated external routing apply that one owner property alongside their existing selection rules; canonical internal dispatch does not treat publication as an extra business guard. It must not bypass any ordinary admission because publication is false. An unavailable external target stays outside the generated interface; this proposal does not invent a transport error code or a second business error catalogue.

Inline operation examples exercise canonical business admission in the isolated test harness, including nonpublished operations; they neither publish a tool/route nor change its authority. Interface-discovery acceptance below separately tests publication. Neither an inline example nor a client-supplied target/mode can turn an unavailable public entry into an external interface.
