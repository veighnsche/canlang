# Source-checked contained mutation loops

`CanPropose.offer_alternative` is the next original cross-model call refusal after the CRM, Desk, and Purchase paths. Its child `propose.revise` first scans `proposal.Revision` with a `where` filter, sets every selected old revision to withdrawn, and conditionally sets `hold_state`. The caller then receives the new Revision, sets `alternative_to`, and copies up to 100 `revision.Item` rows into new Items parented by that returned Revision. These effects must share one owner transaction and one original read checkpoint.

## Current boundary

- Source closure in `compiler/src/analysis/scenario_disclosure.rs` (`bounded_input_loop`) accepts an original array or an unfiltered contained-member domain. Its body is direct SETs only; a filter, nested IF, or CREATE refuses. `DisclosureEffectKind::ForMember` carries a domain, bound, item, and SET-node list, with no predicate or per-row branch lineage.
- `compiler/src/codegen/scenario_receipts.rs` checks that `ForMember` is a whole contained collection with no `where`, order, or query limit. Its site collector visits only that domain's root parameter. A filtered loop query falls through to the ordinary query walk, which recognizes inline selections or transcripts but no mutation-loop domain. Nested CREATE has no loop-specific source correspondence or result linkage.
- `compiler/src/codegen/js.rs` emits an ordinary awaited `records(...)` array for a loop unless a checked query occurrence routes through `executeScenarioReceiptQuery`. The ordinary path has no native query observation or original-domain commit recheck for this mutation proof.
- The State receipt query executor already issues opaque per-candidate slots, validates source fields and owner read policy, and rechecks the full original domain before outer commit. Its existing query plan has no effect-loop profile that binds selected slots to repeated SET/CREATE sites or their resulting rows. The owner session does stage child calls and writes atomically, but that atomicity alone cannot prove which source row justified each write.

## Required end-to-end carrier

1. Add a distinct checked filtered-contained-loop effect proof. It must pin the original required parent parameter, child containment edge, typed `where` predicate and its checked per-candidate reads, literal bound, one source loop occurrence, and the exact body tree. For `revise`, the body profile needs a direct SET on each selected old Revision plus an IF whose true arm may SET the same row. Empty and populated paths must retain separate decision/influence records; the bound must cover all possible selected rows and repeated observations.
2. Publish that loop's query occurrence in the native `ScenarioReceiptQueryPlan` inventory. The compiler must match source predicate, parent, model, field dependencies, and IR query, then lower the loop domain through `executeScenarioReceiptQuery`. The returned selected views, not a fresh `records(...)` call or caller-supplied IDs, must drive iterations. False candidates still require visibility and control authority; State's existing full-domain recheck should guard the original selection at commit.
3. Bind each effect execution to an opaque selected-row slot. A repeated SET must target the exact selected row for that iteration; the conditional SET must record its actual branch choice and use only that row. The receipt should reject extra writes, skipped required writes, duplicate iteration, reordered source rows, and a SET after the loop's owner stage closes. The compiler's source and IR inventories must agree on every repeated site and branch, while State retains its final staged-write equality and revision fence.
4. Add a separate per-element CREATE proof for the caller's Item copy. Each created Item must have `parent` equal to the exact `CallAs` Revision result from `revise`, and each copied field must come from that iteration's selected original Item (or an explicitly admitted constant). The proof needs a one-to-one source-slot/new-row relation, a finite count, and the same outer transaction. It must not grant generic nested CREATE or allow a different original Item with matching field values to substitute.
5. Only after `revise` has a complete native child receipt should `offer_alternative` bind its exact CALL site and returned model, then its subsequent SET and Item-copy loop. The CALL result and every parent effect must be checked under the same owner session, with rollback on a failed child, predicate, create, or final revalidation.

An installed regression should cover zero and multiple selected old Revisions, mixed `hold_state` branches, zero and multiple original Items, hidden/unreadable candidates, a changed predicate field or parent collection before commit, stale input versions, and rollback after a later copy failure. Until the query, per-row effect, and copy carriers exist together, the original `E6008` remains the correct refusal.
