# C09P independent medium escalation review

Disposition: retain dependency-free position/path mechanisms; release two finite correctness repairs separately. Production source, Cargo, packages and shared documentation were not edited.

## Executed evidence

`replay.py` freshly extracts current defining functions and links the actual newest debug rlib. All 27 current-source/rlib results agree. Ten forward vectors cover raw byte columns, UTF-16 and UTF-8 LSP columns, scalar backoff, CRLF, LF, bare CR and EOF clamp. Eight inverse vectors cover missing line, UTF-16 surrogate interior and line-end clamp. Nine public identity vectors cover absolute/relative operands, existing symlinks, lexical missing paths and relative roots. Four mismatches are independently expected: `a\r` inverse `(0,2)` and `(0,99)` must both be byte 2; missing root `../missing` plus operand `../../x` must preserve lexical `../../x`, and root `../../missing` must preserve `../../../x`. These relative outputs qualify parent preservation only, not the separate public absolute-external promise.

`fixed.rs` is an extracted-source probe, not production. Its two bounded changes produce all 27 fixed expected results. `supplement.rs` executes ten fixed lexical assertions, including leading parents, ordinary cancellation, dot removal and literal absolute parents. `identity-probe.rs` separately observes existing symlink canonicalization, missing-suffix fallback and absolute/relative root behavior. No filesystem canonicalization oracle was used for lexical expectations. Read `vectors.json`, `*-results.txt`, `review-pins.json` and `candidate-build.json` for raw evidence and exact current pins.

## Caller closure and units

`source::LineIndex` is exported through public `source` in lib.rs. `LineIndex::line_col` owns one-based byte columns; diagnostic.rs and cli.rs rendering use it, as does codegen/sourcemap.rs::build for original source byte columns. `LineIndex::to_lsp` owns zero-based UTF-16 (or explicitly requested UTF-8) positions; lsp/server.rs::span_to_range and ide/tokens.rs use it. SourceDb stores exact original bytes/content hashes; neither repair changes text, spans or mapping units.

`ide::queries::offset_at_position` is public and UTF-16 only. Exact production direct closure is lsp/server.rs: hover 323, completions 329, definition 347, references 365, rename 385, code_actions range start/end 421/425. Each receives the unchanged snapshot text. Bare CR is a lexer error, but source.rs expressly counts it normally for accurate positions, and IDE/LSP snapshots still contain those invalid bytes. The defect is reachable even though ordinary valid Can files do not need bare CR. Existing tests/ide.rs::offset_at_position_cases covers CRLF and surrogate backoff but not trailing bare CR.

`docs::portable_source_id` is public. Production callers: cli.rs::run_docs at 929 uses current_dir root; docs.rs::workspace_revision at 972 and reference source-location extraction at 1021 use docs_project_root/current_dir. Normal roots are absolute. Their error fallback is `.`. External public callers and docs integration tests can pass any Path, including missing relative roots. `lexical_normalize` is private, invoked on joined path and fallback root only. No second root policy is needed.

## Finite repair proposal (unreleased)

P09-P1 writer compiler/src/ide/queries.rs::offset_at_position: guard strip_suffix('\r') with `text.as_bytes().get(line_end) == Some(&b'\n')`. Independent test writer compiler/tests/ide.rs::offset_at_position_cases: fixed EOF `a\r` at exact/overlong character -> Some(2); bare internal CR counts; `a\r\n` exact/overlong first-line -> Some(1); non-BMP surrogate interior backs off; trailing LF last empty line exists; missing line returns None. Source owner forward tests should assert bare trailing CR still counts, without changing it. This is a definite documented inverse-contract defect. Direct public-function integration tests establish the exact shared seam all seven LSP uses call; a server behavior test is optional because no request dispatch or backend conversion changes.

P09-P2 writer compiler/src/docs.rs::lexical_normalize: in ParentDir branch use `matches!(out.components().next_back(), Some(ParentDir)) || !out.pop()` before pushing `..`. Consecutive retained parents must never cancel each other. This is a definite private comment/lexical traversal defect. Test writer compiler/src/docs.rs private unit tests for lexical normalization plus compiler/tests/docs.rs public missing-relative-root regression witnesses. Accept `../..`, `../../a/../..`, `a/../../x`, `../a/../x`, normal `a/../b`, dots, ordinary absolute cancellation, and existing public symlink/external tests. The probe preserves literal parents above an absolute root; do not substitute path-clean root clamping in this repair. Private absolute-parent expectations require explicit review as documentation of the existing literal policy, rather than accidental dependency policy adoption.

Separate boundary issues: public docs promise `external:<absolute>` and relative/absolute agreement, but missing relative roots still produce relative external identities after P09-P2. Anchoring roots to cwd changes public output and needs its own scoped caller/contract review. Existing symlink aliases canonicalize identically; missing suffix under a symlink falls back to authored lexical spelling and can differ from its physical spelling. Prefix canonicalization would change identity policy and filesystem work. Neither should be silently bundled into parent cancellation. Root clamping above `/` is likewise separate; no new clamp policy is selected.

## Existing-owner inverse and library qualification

Moving the existing prefix-scanning inverse to a module-level function in source.rs with a compatibility delegating wrapper in queries.rs would preserve costs but saves no mechanism or lines; it is organizational consolidation only. Invoking a new LineIndex::new inverse at hover/completion sites changes O(bytes through requested line/column) scans to an O(whole-text) allocation/index build. Snapshot has no reusable LineIndex field. Existing definition/references construct an index, but hover/completion/rename do not construct one before conversion, and code actions have two inverses. Therefore the single conditional fix is simpler than migration/cache work here.

Pinned line-index 0.1.2, text-size 1.1.1, nohash-hasher 0.2.0 actual crate sources compiled with rustc (no Cargo/network); only nohash std feature is enabled, text-size serde is absent, line-index has no feature gates in its manifest. `line-adapter.rs` executed all 27 vectors and exactly matches fixed results. API: try_line_col rejects offsets beyond end or inside scalars; offset accepts unbounded columns; to_utf8 needs surrogate backoff and line-end checks; line includes newline; CRLF exclusion is adapter policy. The adapter preserves raw byte line_col even inside a scalar separately from LSP backoff. It does not replace SourceDb or source-map units.

The candidate indexes newline offsets plus non-ASCII character tables across the entire text, whereas current Source.LineIndex stores newline offsets only. Our adapter adds EOF/UTF boundary clamps, CRLF policy, UTF-16 backoff and inverse line bounds; reverse builds a whole index per call. Measured native debug compile cost and three rlib sizes are in candidate-build.json (695440 aggregate bytes; not downstream incremental/full compiler cost). No performance claim from this tiny harness, and no cross-host cost claim. It demonstrates preservation but no simpler adapter or measured workload benefit. Retain current mechanism and apply released local fixes; no new library dependency recommended.
