# C09I recommendation: retain the bounded scanner; repair finite parity defects

The published FormatJS candidate fails required API, exact-selector and parse-time depth gates. Retaining the scanner is the simpler executable option for the current contract after the finite repairs in `correctness-packets.md`. This does not certify the existing scanner as correct: eight type vectors expose two defects, and fifty syntax/coverage/depth vectors expose eleven owner mismatches. All 58 public-owner source outcomes equal the corresponding built-export outcomes. Six independent rendering witnesses also preserve large/fractional exact branches, all decimal digits, nearest plural pound through select and nested plural, and fail-closed unsafe category selection.

Version qualification is pinned, not inferred from documentation defaults. The official [FormatJS tooling page](https://formatjs.github.io/docs/tooling/rust-icu-messageformat-parser/) advertises 0.2.4; [docs.rs latest](https://docs.rs/formatjs_icu_messageformat_parser/latest/formatjs_icu_messageformat_parser/) resolves 0.3.1; GitHub main advertises 1.0.0. The fetched [published sparse registry entry](https://index.crates.io/fo/rm/formatjs_icu_messageformat_parser) contains versions 0.1.0–0.3.1 only, all with no declared features. The exact [0.3.1 source archive](https://static.crates.io/crates/formatjs_icu_messageformat_parser/formatjs_icu_messageformat_parser-0.3.1.crate) has SHA256 `d0909dd9d16e47e4c6edb7e0e118c2afecef3ccffab077e20597d84b373bec33`, matching the registry checksum. Both are saved here. No released `parse-core` feature exists. A hypothetical upstream split is unimplemented and unexecuted.

Caller closure: check_program runs types then examples. Named messages supply resolved parameter types to examples.rs IcuType; anonymous descriptors get structural checks. types.rs phase2_message/check_message_value validates slots across source and present variants; message_slots recurses through branch bodies with malformed fallback. `call_message` (`types.rs:13802`) binds/checks expression arguments and retains ResolvedType::Message until sinks, and `check_format_call` bypasses plain-template validation for message overloads. No syntax library replaces that ownership or provides disclosure authority. This pass does not claim newly implemented provenance/anonymous typing, localization execution, or generated interface behavior.

Fair simpler alternative: a focused compiler parser/type/coverage repair keeps zero new dependencies and existing diagnostics, while matching the finite public owner profile. Library strengths are a typed AST, source locations, duplicate checks, maintained full ICU grammar and reusable syntax work. Those could be useful if future consumers genuinely need a common exact/bounded parser. Here full grammar is not a user requirement, and an AST alone neither supplies exact admitted selectors nor enforces depth. Adoption needs a released or separately qualified bounded parse-core API with decimal exact selectors, apostrophe/pound policy and consumer tests; it remains deferred.
