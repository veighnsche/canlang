# C09C — retain current CLI mechanism; repair bounded completion defects

The released comparison is executed on Darwin arm64 with the existing compiler binary (SHA-256 matches the packet), Bash 3.2.57 and Zsh 5.9. Fish is absent. No production source, package, repository Cargo/lock, Git state or shared documents were changed. This assessment retains the scanner and embedded scripts; it does not accept every current completion behavior as correct.

## Actual closure and independent outcomes

`main.rs` calls `cli::run` under its panic boundary; `run` writes the captured dispatch streams and ignores broken pipes. Production `dispatch` scans once for catalog configuration, constructs `CatalogAnalyzer`, and `dispatch_with` scans again before help/version/business dispatch. The pure parser is private. Known commands, thin commands, flag admission, global help, individual help, and three embedded completion files repeat portions of command metadata. Completions output is literally `include_str!`, so shipped byte identity is an existing `compiler/tests/exe.rs` contract, separate from shell behavior.

`command_help("help")` and the exe alias tests fix the distinction: `can --help run`/`can help run` are compiler help, but `can run --help` belongs to the producer. `command_help` for thin entries fixes exact argument passthrough (including flags and `--`), direct child streams, child exit-code passthrough and signal-to-2 mapping. `cli` module/`lib.rs::exit` fix stdout diagnostics with exit 10, tool failure E7001/E7002/E7003/E7004 on stderr with exit 2, and successful help/completions on stdout with exit 0. `CatalogAnalyzer`/catalog owner fix explicit catalog precedence. Parser-only malformed/help precedence has no separate declarative promise in install docs; it is therefore frozen compatibility characterization, not an invented new policy.

Read-only platform owner is **`packages/cloudflare/src/cli/platform.ts`**, not a hypothetical platform package. Its `main` parses `process.argv.slice(2)`; docs rendering and prepared build/deploy have separate producers. Platform parsing owns `--artifact`, `--env`, `--preview`, `--yes`, locale, duplicate rejection, and its help JSON/stdout + human/stderr envelope. It does not treat `--` as its own terminator: unexpected `--` is a platform usage failure. Compiler passthrough must still preserve `--` exactly rather than reinterpret producer grammar. No real producer service or deploy was invoked. The established `CAN_PLATFORM_BIN` seam ran an executable Python fixture that reports argv including empty strings/spaces, writes stderr, returns 7, or self-terminates with SIGTERM.

## Process and shell evidence

`probe.py` / `process-results.json`: **60 fixed-expectation actual binary cases pass**. They include all compiler help forms; help alias and prefix help for all five thin commands; 15 exact thin-tail captures covering child flags, spaces, empty strings and multiple separators; unknown commands/options; arity failures; no-format commands; separator filenames; read/lookup failures; child status 7, signal 2 and missing producer; last valid format wins in both orders; last catalog overrides an absent earlier catalog. All three completion outputs exactly equal shipped bytes (2,428/3,014/3,876 bytes). Eleven additional rows characterize malformed/help/version interactions: invalid/unknown/missing flags beat help regardless of order; command-specific applicability checks can beat help; `fmt --help --format=json` returns help before dispatch-only prohibition; `--catalog --help` consumes the help token as a catalog value; empty catalog plus help is permitted; version beats unknown command after successful parse.

`completion-probe.sh` / `bash-results.txt` execute Bash completion functions, not text search. Commands, format values (split and equals spelling), help commands and shell choices complete. Thin entries offer files only. `--fix` is missing, and Can options are incorrectly offered after `--`. `zsh-pty.py` / `zsh-pty.txt` run a real interactive Zsh completion engine in a PTY with system-only fpath, `compinit -D`, `compdef`, and tab-bound `expand-or-complete`. It proves format equals spelling expands, `can completions b` fails to expand, lint `--fix` is absent, and flags are suggested after separator. This supersedes earlier `zsh-probe.zsh`/`zsh-interactive.txt` exploratory zpty output whose initialization/read synchronization was unreliable; those files are retained transparently, not counted as extra passes. Fish exact byte identity and syntax declarations were inspected; no actual fish engine result is claimed.

The two concrete defects are independently queued in `correctness-queue.md`: missing lint `--fix` in all scripts; Zsh shell operand indexing. The separator behavior is a characterized completion gap with a finite repair boundary, not a CLI policy redesign. Root owns repair release.

## Pinned library experiment

`clap-prototype.rs`, `candidate-Cargo.{toml,lock}`, `clap-results.json`, and `candidate.{bash,zsh,fish}` preserve an actual buildable **clap 4.6.7 / clap_complete 4.6.7** builder/AOT experiment. `args_override_self(true)` handles last valid format/catalog wins; `allow_hyphen_values(true)` preserves values such as literal `--help`; thin operands use `trailing_var_arg(true)` and disabled child help. Completion metadata includes lint's flag, shell value choices and path hints. The program is intentionally a parser/metadata prototype returning matches, **not a complete compiler replacement**: business dispatch, precise E7001 wording, manual help prose, catalog IO and child streams remain owned by Can. Exit comparisons involving business dispatch are not candidate failures. Candidate `kind=...` stderr is probe instrumentation, not clap's required protocol.

Actual candidate evidence exposes preservation work beyond metadata:

- Built-in clap help terminates before later malformed arguments: `check --help --format=wat`, `check --help --wat`, and `check --help --format` return help; current compatibility returns tool errors. Replacing help with a normal flag and post-parse rendering is necessary. Existing exact explanatory help stays authored (including producer boundaries, warnings, docs overwrite refusals and LSP lifecycle).
- Clap global format/catalog options remain recognized inside thin entries; `run --format=json --catalog A -- --help ...` loses the first flags from operands. A raw-argv split before clap admission is required; trailing-variable operands alone do not provide verbatim first-flag passthrough. Clap also removes the first child separator. Prefix flags and child flags have different ownership.
- Current flags can precede command selection, including command-specific flags whose applicability is validated after parsing. A normal subcommand-local clap declaration changes this grammar; global declarations require retained Can applicability validation. Unknown command plus version and unknown command plus help require Can ordering rather than default clap unknown-command behavior.
- Error kinds/messages and output streams must be adapted to Can E7001/exit-2 conventions. Repeated boolean flags need self-override admission. Help aliases and their operand validation remain explicit; forbidden flags are rejected at different parse/dispatch stages.

`candidate-bash-probe.sh` / `candidate-bash-results.txt` actually source the generated Bash script. Consolidation correctly adds `--fix`, but this direct global schema offers `--format` for thin commands and after separator, does not complete `--format=j` on Bash 3.2, and lacks `help li` completion. Generated text is not byte compatible (a deliberate migration would have to update shipped files and their goldens together). The richer candidate is not presented as accepted shell parity. Its Zsh/fish generated files were inspected; only current Zsh was engine-tested, and fish remains unavailable.

The minimal builder is short because it does not implement these adapters. We do **not** compare its line count with the existing completed CLI and declare simplification. A full preservation adapter has not been implemented; the exact observed gaps are sufficient to reject this candidate as an adoption proof. Completing that adapter would need its own finite follow-on packet if there is evidence of a payoff.

## Decision boundary

**Retain** the current mechanism for this released lane. Repair the two executed defects with focused scripts/acceptance coverage. clap provides useful command metadata and generation, but preserving actual ownership/error/help/argument behavior still needs a raw scanner/admission adapter, authored help and Can dispatch checks. A separate accurate completion view is needed if parser-global flags remain accepted for compatibility but invalid per-command suggestions are excluded. Shared small capability metadata could reduce the repeated command/flag lists without adding a third-party parser; that is a proposal, not implemented or measured here. No consequential language/CLI policy alternative is introduced, so no JEV decision gate is manufactured.
