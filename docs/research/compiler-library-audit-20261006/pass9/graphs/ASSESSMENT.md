# C09G graph comparison

Recommendation: **retain the current production mechanisms; defer a shared routine/petgraph migration**. Both candidate mechanisms executed. SCC filtering has a substantial synthetic benefit on long acyclic/upstream chains, but no measured whole-compiler/editor benefit or production compatibility adapter exists. A separate finite correctness repair is warranted for nondeterministic E3005 witnesses. This packet selects no new diagnostic policy and changes no production source.

## Actual caller closure and scopes

`cli::CatalogAnalyzer` calls `analysis::check_program`; `ide::queries::Snapshot::analyze` calls it and then repeats `resolve_program` to obtain lookup tables (discarding that second resolve's diagnostics). Policy has a test-only check_program caller. `check_program` parses, resolves, checks types/effects/examples, deduplicates `(file,start,end,code,message)`, and sorts `(file,start,code)`. The resolver invokes composition from resolve_imports, ownership after imports, then resolves declaration/body bindings, and fixture/derive checks in finish. Types check_cycles runs after phase1/phase2. Fixture edges also become ordered `FixtureRecipe.seeds` in examples; replacing that graph cannot reorder/deduplicate seeds differently.

Related production chains must remain separate policies: types field_type_guarded is a context-dependent resolution stack producing E3008 at the encountered path; effects check_every_scopes traverses scenarios, treats CRUD as model leaves, and retains first app/team model witnesses; effects scope_is_app walks ownership and returns false on a repeat in an already invalid program. These are not interchangeable SCC diagnostics.

SymbolIds are appended to symbols during ordered file/tree/module/section declaration indexing, with nested/generated symbols interleaved. Sorting SymbolId would be **indexing order for the same supplied file order**, not globally canonical source-path order or guaranteed textual source-position order. This is a possible repair choice requiring separate release, not a choice made here.

## Executed outcomes

`compiler_probe.rs` links the existing hash-pinned native debug rlib; raw actual diagnostics are saved in compiler-raw.txt and 12 fresh process repeats in compiler-repeat-raw.txt. This is actual existing compiler behavior, with honest limits: the rlib does not embed independently verifiable graph-section hashes, so this is not a rebuilt-current-source qualification. Live graph sections are saved and pinned separately from the changing ICU section in types.rs.

Independent fixed outcomes confirmed by this compiler: upstream U is clean for app cycles; duplicate selections generate duplicate raw E2007 but only one public finding per origin; ownership upstream U, A and B all diagnose; upstream fixture/derive u is clean while a/b diagnose. Scenario upstream u gets no cycle witness. A two-branch overlap produces two call diagnostics rather than one SCC diagnostic. The initial malformed call fixture used parentheses and was corrected to the actual `call target {}` syntax before retaining results.

The standalone graph probe executes a shared iterative per-origin scanner and petgraph `kosaraju_scc` (nonrecursive DFS passes). It independently fixes membership/reaching expectations for acyclic, upstream, independent/self cycles, duplicate edges, overlap and diamond. It also fixes exact witness path/closing-edge index/order under forward/reversed origins and duplicate-close counts. All 512 three-node directed graphs × two root orders preserve the legacy call witness/multiplicity/closing-edge/order with an SCC **prefilter** while retaining original adjacency and legacy DFS. SCC iteration/order is never used to choose a witness. Upstream reach policy uses reverse reachability seeded by cyclic SCCs: membership alone explicitly fails ownership semantics.

Median of nine optimized native probe runs; 1000 vertices; call origins restricted to nodes with outgoing edges; times include SCC graph construction, membership and reverse reachability, plus retained DFS for call gate. Allocations/path cloning remain included. These are synthetic graph workloads, not whole compiler or editor results.

The independent-cycle call case is slower with SCC overhead (~30%). The dramatic chain speedups establish a bounded synthetic opportunity, not workload prevalence. A simple sharing refactor would keep repeated-origin complexity and no measured speed benefit is claimed for it. Production integration must preserve raw duplicate composition findings, fixture seed vectors, original edge order/spans, callable filters, whole-program diagnostic aggregation and origin enumeration; that adapter is **unimplemented**. SCC membership as a direct replacement is rejected because it loses upstream ownership diagnoses and call witness multiplicity.

## Finite correctness finding (reported to root)

G09-1: Identical source in calls_upstream yields either `E3005 141..142 call cycle: a -> b -> a` or `E3005 98..99 call cycle: b -> a -> b` across 12 fresh processes. calls_overlap yields three distinct public diagnostic sets. Source cause: `types.rs::check_cycles` enumerates randomized HashMap keys and globally dedups witness vertex sets. This defeats the declared deterministic diagnostic surface (`diagnostic.rs:100`, `analysis/check.rs:10`); sorting existing findings cannot fix their changing content/spans. Source writer scope: only check_cycles caller-order policy; test writer scope: compiler/tests/analysis.rs exact repeated witness/message/span assertions. Acceptance: same input/file order yields exact stable diagnostic set/spans/order, preserves global vertex-set dedup, current adjacency order, callable scope and upstream exclusion; verify independent/overlap/duplicate/self cases. Uncertainty: desired stable witness orientation/origin ordering must be resolved in the separate repair packet. No witness policy selected here.
