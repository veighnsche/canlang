# Independent graph and position comparison review

Disposition: **retain the current mechanisms and defer library adoption**. The candidates were given a finite, substantive comparison: petgraph was executed with defaults disabled; line-index was executed through a preservation adapter; path-clean was executed through the existing identity owner. None establishes a simpler complete production replacement or measured compiler workload benefit. Retention does not close the separately identified correctness repairs or identity-policy questions.

This review read root `AGENTS.md`, `PACKETS.md`, `dispatch.md`, the graph and position assessments, saved raw observations, probe implementations, feature/build receipts and actual source caller seams. It made fixed computations on existing observations and did not rebuild, download dependencies, change production/Cargo/packages/shared decisions, select graph-origin ordering or invoke new policy advice. Existing `pins.json` and `positions-medium/review-pins.json` identify the historical inputs. During review, another writer's live `queries.rs` and `docs.rs` already contained the two local fixes; this report qualifies the saved comparison evidence, not that writer's integration tests.

## Graph scopes and candidate parity

The actual graph consumers impose different policies. `check_program` invokes resolution then type/effect/example checking and deduplicates/sorts public diagnostics; CLI catalog and IDE snapshot analysis consume it. IDE analysis also resolves again for tables. The separate policies are:

| Owner | Contract the adapter must retain |
| --- | --- |
| Composition (`resolve_composition`, E2007) | Composed-app origins and authored selections, including duplicates; composed apps expand, packages/implicit apps are leaves; return-to-origin only. Duplicate closing selections can emit duplicate raw diagnostics before public dedup. |
| Ownership (`resolve_ownership`, E2008) | Installed model parent links; repeat anywhere in the chain diagnoses every originating model that reaches the cycle, including upstream models. Rejected/self links are excluded before traversal. |
| Fixtures (`check_fixture_cycles`, E2017) | Valid app/package fixture descendants, local test owners, unique bound fixture references in descendant order; cycle membership only. Ordered edge vectors also supply `FixtureRecipe.seeds` and cannot be replaced by arbitrary SCC iteration. |
| Derives (`check_derive_cycles`, E2018) | Valid app/package derives with local single-name function owners and bound DeriveFn targets; membership only. `derive_owner` currently returns no owner for field derives despite its broader comment. |
| Static calls (`types::check_cycles`, E3005) | Only recorded current-operation calls with callable endpoints (Scenario/DeriveFn); capability/CRUD endpoints are leaves. `current_op` is assigned for scenario bodies, so standalone derive bodies do not supply outgoing static-call edges. Preserve occurrence adjacency/span order, visited-on-push DFS, global sorted vertex-set dedup and closing-edge span. |

These conclusions agree with the saved source sections and checked live seams. The fixture/derive origin HashMap iteration changes raw ordering but public sorting restores these fixed per-origin findings. Static-call origin order changes which witness survives global dedup, so public sorting cannot restore its content. E3008 guarded field-type resolution and effect/ownership scope walks have additional contextual policies; this comparison does not authorize folding them into SCC membership.

`graph_probe.rs` has 512 three-node directed graphs (all nine possible directed/self edges) and two root orders. Its `assert_eq!` compares full `Witness` vectors: path, closing edge `(source,target,adjacency-index)` and output order. That establishes exact parity for **SCC membership prefilter plus the unchanged legacy DFS**, not direct SCC reporting or production integration. The exhaustive set has no duplicate parallel edges; a separate fixed fixture checks duplicate-close count, and forward/reverse overlap assertions independently prescribe exact paths and edge indices. Fixed fixtures prescribe membership and upstream reachability independently. Reverse reachability seeded from cyclic SCCs is necessary for ownership: SCC membership alone fails the upstream contract. None of this freezes a new public witness orientation.

Fixed computation over `compiler-repeat-raw.txt` confirms 12 process runs: `calls_upstream` has six `141..142 a -> b -> a` and six `98..99 b -> a -> b` findings. `calls_overlap` has three exact diagnostic sets occurring 6/4/2 times. These are real process witnesses from the pinned compiler rlib; the live `check_cycles` still gathers randomized HashMap keys and deduplicates globally by sorted path IDs. The evidence supports the finite nondeterminism finding. It does not independently prove that the reused rlib was built from every current graph source section, a limitation already disclosed in `graphs/pins.json`. Origin order remains pending the separately requested JEV/release decision; sorting SymbolId means indexing order for supplied file order, not canonical source-path order.

The five timing shapes each use 1000 vertices, median of nine native runs, optimized probe code with recorded debug dependency rlibs. SCC graph construction, membership and reverse reachability are included; gated calls retain allocation/path cloning and DFS. Large improvements on long acyclic/upstream chains are a real synthetic opportunity. Independent two-node cycles increase call time from 224375 ns to 292458 ns (about 30%); high fanout also gains no call benefit. Workload frequency, full compiler/editor latency, memory, release size, downstream incremental cost and cross-host behavior were not measured. Source sharing alone retains repeated-origin complexity and has no demonstrated speed benefit. Deferral fairly acknowledges both the opportunity and the missing production adapter/workload qualification.

Petgraph's scratch manifest pins `=0.8.3`, `default-features=false`, `features=["std"]`. `features.txt` still contains fixedbitset/indexmap/equivalent, two hashbrown versions and foldhash: defaults-off is not dependency-free. Saved online/offline build receipts qualify this native Rust 1.99/macOS profile and existing shared target only; no broader MSRV or host claim follows.

## Coordinates, paths and candidate adapters

`source::LineIndex` is a public source owner with private newline-start storage. Its public methods and returned units must remain compatible: one-based byte columns for human diagnostics/CLI and original source-map positions; zero-based UTF-16 or explicitly requested UTF-8 positions for LSP/tokens. Source spans/content bytes are unchanged. This is public API/output compatibility, not a stable Rust binary-layout ABI claim. Re-exporting line-index's public `TextSize`/`LineCol` directly would change that API; the saved wrapper keeps existing signatures. No 4 GiB/cross-host qualification is present.

The shared inverse seam is public `ide::queries::offset_at_position`, used directly by LSP hover, completion, definition, references, rename and both code-action range endpoints. Bare CR remains addressable even in invalid text snapshots; CRLF CR is excluded. Saved baseline returns byte 1 for `a\r` inverse columns 2 and 99; the fixed inverse returns byte 2, consistent with the forward owner's explicit documented rule. Other fixed vectors preserve scalar backoff, CRLF aliasing/clamping, EOF, final LF empty line and missing-line behavior.

Fixed computation confirms each medium result file has 27 observations, and `line-adapter-results.txt` equals `fixed-results.txt` byte-for-byte. The replay includes ten forward, eight inverse and nine public identity vectors, plus ten explicit local lexical assertions. The line candidate uses pinned actual line-index 0.1.2/text-size 1.1.1/nohash-hasher 0.2.0 crate sources compiled with rustc; nohash std is enabled, serde is absent. The first low assessment's “not executed” limit is superseded by the medium execution, not silently erased.

Candidate APIs alone do not preserve the contract: `try_line_col` rejects excess/interior-scalar offsets, `offset` permits unbounded columns, `line` includes newline bytes, and UTF-16 reverse conversion needs backoff/clamping. The wrapper adds EOF/scalar handling, raw byte-column preservation and CRLF/inverse bounds. It demonstrates attainable preservation for the finite vectors. It creates the whole candidate index per inverse call, whereas current inverse scans only through the requested line/column and Snapshot has no cached LineIndex. Existing source index stores newline starts only; candidate also indexes non-ASCII characters. The 0.31 s debug dependency build and 695440 aggregate rlib bytes are scratch measurements, not production adoption costs or performance benefits. With no measured workload benefit and a longer preservation adapter, retaining the dependency-free owner and focused inverse fix is fair.

`portable_source_id` remains the canonicalize/join/strip-prefix/external-frame owner; private lexical fallback is not symlink resolution. Normal CLI/reference roots are `current_dir()` and absolute on the qualified host; `.` error fallback and the public function's arbitrary relative roots remain distinct reachable boundaries. Leading retained parents must not cancel one another: saved local fixed outputs `../../x` and `../../../x` repair the two missing-relative-root witnesses. Existing symlink targets canonicalize together; missing suffixes through a symlink fall back to authored lexical spelling.

Path-clean 1.0.1 has no runtime dependencies and its delegating primitive is shorter. Its executed public vectors preserve existing-path/symlink/missing absolute-root cases and fix consecutive relative parents. However, its source explicitly clamps parents above a root: `/../x` becomes `/x`, while the retained literal local policy produces `/../x` (and `/../../x` stays literal). Those rooted supplemental outcomes were executed for the local fix, not for path-clean in the public adapter harness; the candidate's differing result is directly established by its pinned implementation/test expectations. Adopting the one-line primitive would select that different root policy and cannot be called exact preservation. Retaining the small local fix is justified without claiming the library is generally worse.

The local parent repair still does not fulfill the public comment's universal `external:<absolute>` and relative/absolute identity promise for missing relative roots. Cwd anchoring, missing-prefix symlink canonicalization and root clamping require separately bounded contract reviews; neither candidate nor the two local repairs resolve them. They must remain visible gaps rather than grounds to silently expand this pass.

## Release conclusion

The finite comparisons support retention without mandatory migration or a new library policy. Carry the exact E3005 finding and the two independently justified local repairs through their existing release packets. Keep graph origin ordering pending its specific decision and keep the three identity boundaries separate. No new builds, production writes or shared-decision edits were needed for this independent review.
