## Once, order, context and identity

Arrays/objects, ordinary positional calls and scalar helpers generally emit one occurrence per operand, with target JavaScript evaluating the resulting argument/member expressions. And/or/coalesce use short-circuit operators and parenthesization. `lower_stmt(For)` captures a bounded domain once in a distinct generated temporary and tests its size before iteration. Guards/body statements remain in carrier order. These are source traces and selected golden assertions; no exhaustive side-effect-order execution is claimed.

The released binding test independently checks getter access exactly once at authored parameter intake, admission exactly once, restored outer branch/loop bindings, reserved query/lambda aliases and an authored `c` parameter alongside ambient actor/context. Hook scope now exits before later CRUD lowering. The actual CRUD helper trace checks model/input/record/changes provenance; helpers are strict host stand-ins, not the full state engine. The source-legal query and public-IR loop/lambda test have different admission scopes.

Three order leads remain explicitly unqualified: `order_builtin_args` rearranges syntax into signature order before expression emission; `lower_binary(In)` emits the right operand as the receiver before the left argument; scalar-first money multiplication in `lower_arithmetic` emits the right money argument before the left factor. Their generated order is inspectable, but this review has no independently settled general operand-order oracle plus clean legal-source effectful execution for those cases. Do not claim a new confirmed defect or silently introduce temporary/evaluation machinery from this trace. Qualify defaults, failures, short-circuiting and reordered operands under the owning language/runtime contract first.

Implementation identities now use one UTF8-hex codec with disjoint domains: `l` lexical declarations, `s` canonical source implementations/imports, `o` exported callable identity constants, `u` UI imports, `p` page bindings and `m` owning-module paths. BDD reuses it with `f` lexical recipe names and `t` canonical suite paths. Recipe dependency carriers publish local names, so the same exact local name is encoded for its declaration and every dependency reference inside that function; canonical fixture identity stays in artifact metadata. No second alias registry is added.

Properties remain authored: parameter destructuring maps wire key to encoded variable; shorthand objects become explicit authored key/value where necessary; computed `__proto__` keys remain own data properties. Callable registry keys are canonical IDs, consistently reflected in `registry_member`, actual handlers and `appDefinition.operations.handler`; hook members retain `hooks/<trigger>/run`. Module metadata retains authored names and source URIs while paths become portable distinct ASCII identities. Actual alpha/ALPHA owners execute without relying on a case-sensitive host filesystem. Page descriptor exports are encoded consistently with artifact records; live page rendering is not part of the repair witness.
