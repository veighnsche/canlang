# Pass6 input parser candidate

Read AGENTS.md, model-selection skill, current json.rs, Pass0 C06/protocol contracts, accepted Pass2 admission, Pass5 shared serialization receipt, cached published serde_json1.0.151 source. Existing pinned std/raw_value features sufficient; no repository files mutated.

Preferred small candidate is a single-pass bounded DeserializeSeed/Visitor using serde_json::Deserializer::from_reader with a borrowed Cell byte cursor. Seed records explicit root/object/array origin. Root starts at cursor0; object values start after consumed colon at cursor; array values start at peeked token cursor-1. Only whitespace is examined to classify the source token. Actual '-' or digit tokens deserialize through serde::de::IgnoredAny; other tokens use deserialize_any. Numbers copy the source slice from start to cursor (EOF/last digit) or cursor-1 (peeked delimiter). Serde owns the entire numeric grammar, literals, strings, keys, delimiters, trailing-input check. No full grammar scanner, floating conversion, arbitrary_precision feature, synthetic sentinel handling, RawValue input, or subtree reparse remains. Key/value strings decode through String/visit_str, so lone surrogates reject. Arrays/objects recurse only after depth check and accumulate ordered Vec pairs.

This relies on qualified pinned implementation behavior: IoRead owns reader.bytes() plus one-byte ch; SeqAccess peeks the next token before invoking seed; MapAccess consumes colon then invokes value seed without token lookahead. Cached source de.rs1061,1950,2026/read.rs141-310 confirms those rules. The reader adapter contains this coupling; upgrade witnesses must preserve it. A Box<RawValue> numeric-only variant also works but allocates more and adds no safety advantage. It remains saved in src/raw-prototype.rs.

Witness-ignored-cursor.log passes 297 explicit numeric lexeme/context expectations (11 legal numbers,3 whitespace leads,3 tails,3 root/array/object contexts),25 independently classified malformed grammar/Unicode inputs,3 ordinary private-sentinel/decoded-duplicate objects,28 old-parser array/object depth comparisons. Historical depths accepted:64 arrays with scalar;65 arrays with empty innermost;66 empty rejected. Observed deep20,001-byte input stops after66 read bytes. Large numbers and uppercase E/+000 preservation are exact. Current mixed360,001-byte input x30 scratch release:98.18ms candidate,50.21ms baseline; roughly2x slower,110MB/s. This is a bounded microbenchmark, not broad speed evidence.

Alternatives: (A) qualified pinned cursor adapter above, ~90 adapter lines instead of ~280 grammar/UTF8 lines, small private coupling and measured throughput regression; (B) strict bounded allocation-light serde visitor validation first with arbitrary_precision, followed by RawValue reconstruction (preserves original number spelling only via reparsing, up to65-depth traversal multiplication, additional feature and complexity); (C) retain proven handwritten bounded parser (best known compatibility/speed, fails full-parser-retirement requirement). Ordinary deserialize_any cannot preserve -0/E or enormous exponent without extra feature. arbitrary_precision alone still normalizes exponent casing/in-range negative zero and synthetic maps collide with real sentinel objects if distinguished only by key. Whole-tree RawValue alone bypasses strict Unicode and required depth enforcement.

Open policy: A/B/C selection; exact static error categories and byte-offset convention. Suggested public shape unchanged: ParseError{offset:usize,message:&'static str}, depth flagged explicitly, serde Error::classify() mapped to static syntax/EOF categories, cursor-based byte offsets. Never expose serde error strings. No observed production consumer depends on exact historical granular reason text/offset. Shared Json representation/get-first/as_i64/render/output formatter remain untouched.
