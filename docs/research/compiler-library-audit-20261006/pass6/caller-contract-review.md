## Freeze-ready behavior

- Ordered object pairs retain every duplicate in insertion order; decoded keys are compared; `get` returns first occurrence; render retains all. Catalog uses get-first throughout, tolerates unknown fields, rejects duplicate ENTRY IDs (not JSON member names). Do not silently map to last-wins or reject all duplicate members.
- LSP parse_call rejects decoded duplicate reserved envelope names jsonrpc/id/method/params; unique legal ID is echoed even for other invalid envelope fields. Duplicate ID or invalid ID yields null correlation. Unknown envelope duplicates accepted. Nested supported-method params use get-first; server currently has no known nested-field duplicate check. Unknown capabilities/extensions tolerated. Any stronger duplicate rule needs explicit decision.
- LSP IDs: strings or exact mathematical integer in signed i32 range; fraction/exponent spellings that equal integer accepted and echoed with original lexeme (1.0, 1e0, -0, 0ehuge). Arbitrary precision lexeme arithmetic rejects rounding aliases and avoids exponent-sized allocation. `Json::as_i64` separately admits only no-dot/no-e/E lexical integer within i64, -0 -> 0. Preserve distinction.
- JSON parses one complete document and JSON whitespace only. Full JSON numeric grammar; legal arbitrarily large integer/exponent/fraction spellings accepted without float conversion. Leading zeros, plus prefix, missing fraction/exponent digits reject. Strings decode escapes and surrogate pairs; unescaped control chars/unpaired surrogates reject. Input `&str` is already valid UTF-8; catalog loader and run_stdio reject invalid UTF-8 before parser.
- Depth check occurs at value ENTRY before whitespace skipping with root depth 0 and rejects depth >64. 64 arrays around scalar accepted; 65 reject. 64 arrays around empty []/{} accepted (65 containers total); 65 arrays around empty terminal reject. Equivalently 65 nested arrays with innermost empty accepted, 66 reject. Empty deepest container compatibility is explicit, not nominal library limit equivalence.
- Framing current bound is **64 MiB inclusive**, NOT 4 MiB. transport constant, Pass0 and Pass2 contracts/tests agree. Checked before body allocation. Split reads, Unicode byte count, CRLF/bare LF retained; unsupported charset ignored; duplicate length last-wins; signed +length accepted; malformed frame recovery remains deferred. Any user-required 4 MiB is a new intentional cap change, not legacy behavior.
- Params omission remains Option None distinct from Null; structured object/array envelope params; explicit null only shutdown/exit. Known method required projections validated before mutation; initialize requires processId integer/null, rootUri string/null, capabilities object. Position/length use exact nonnegative i32; document versions exact i32. Other required-field details belong to existing server::valid_params, not a new whole schema rewrite.
