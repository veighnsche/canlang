## Findings requiring controlled receipt joins

- **EC01 handshake:** `start()` makes `isRunning` true before initialize returns. Provider/listener messages can precede initialize response; initialize error resolves null and proceeds to initialized. Normal replay waits, but concurrent document events do not. LSP initialize expressly gates additional requests/notifications until the response. Probe a held initialize reply, then open/change/request, and an initialize error.
- **EC03/04 diagnostic freshness:** versionSupport is advertised; `onPublishDiagnostics` ignores version and open/closed state. Publish version1 after local version2 and publish again after close; inspect collection writes. Server-side task suppression does not repair these delivery boundaries. Current startup tests publish matching versions in order.
- **EC06 cancellation/stale requests:** all provider cancellation tokens are ignored; no cancel notification or captured document/version guard exists. Hold hover/rename, cancel or edit/restart, then release. LSP allows synchronous servers to ignore cancellation; its stale-result guidance is a recommendation, while `implementation/DIAGNOSTICS.md:25` expressly promises cancellation/freshness.
- **EC07 stale edits:** rename/quickfix convert `documentChanges` into a plain WorkspaceEdit, discarding `textDocument.version`. Probe a version1 edit while the document is version2. Server expected-content hash validation checks the source at computation, not the later host application. Providers return edits; this extension does not itself call workspace.applyEdit. Version-support capability is not advertised either. Mixed `changes` plus `documentChanges` processes both and can overwrite; malformed individual edits are silently omitted.
- **EC08 completion kinds:** direct numeric cast confuses LSP and VSCode enums. Current server Class7, Variable6 and Keyword14 should become host Class6, Variable5 and Keyword13. Ambient declarations repeat the wire numbers instead of host numbers. Compare provider output against pinned official VSCode1.91 definitions. Use an explicit symbolic mapping if implementation follows; subtracting one is not a general mapping across both enums. This is an API conversion defect, not evidence of rendered icons.
- **EC10 lifecycle:** graceful shutdown/exit has two-second kill fallbacks; process error/exit once-guard clears pending requests and diagnostics. Deactivate returns void rather than its stop promise; overlapping restart/open sequences are not serialized. stdout end/close alone does not finish pending calls. Probe independent process lifecycle events and two rapid restarts.

## Workspace and analysis limits

The selected active Can document's owning local folder becomes server cwd; otherwise the first local workspace folder is used. The initialize request supplies rootUri null and no workspaceFolders. All documents share that process and selected catalog. `RealAnalysis::from_process` reads inherited CAN_CATALOG and cwd candidates once. Only serverPath/trace configuration restarts the process; there are no catalog-file or workspace-folder watchers. Root can change catalog A to B while live, then restart, and open documents in two roots with different catalogs to distinguish this supported cwd selection from per-root availability.

`Snapshot::analyze` passes only `[file]` to check_program and only that file/tree to resolution. Definitions, references and rename stay in the current file. Holding several open documents in SourceDb does not produce a cross-file module graph. The existing import-member test has two modules in one source file. The project diagnostic promise explicitly says current-document; cross-file/workspace rename remains a capability gap, without inferring an unsupported workspace promise.

The URI sent by the client is document.uri.toString(); server identity is the authored URI string, with native path conversion accepted only on exact roundtrip. Client diagnostics and provider outputs call Uri.parse without a canonical open-document registry. Nonfile documents match the language selector, although cwd discovery only chooses local roots. Equivalent URI spellings, remote schemes, encoded paths and close/reopen identity need bounded controls before any broader support claim.

- [Initialize contract](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/general/initialize.md): initialization ordering and workspace metadata.

- [Official VSCode1.91 API](https://raw.githubusercontent.com/microsoft/vscode/1.91.0/src/vscode-dts/vscode.d.ts): host CompletionItemKind enum, independent of the local ambient declaration.

README/provider/package claims, current-document analysis, controlled mocked client receipts, direct native protocol receipts and actual editor-host acceptance must remain separate evidence categories. This audit proposes no policy or implementation change and does not claim fresh execution before root receipts arrive.
