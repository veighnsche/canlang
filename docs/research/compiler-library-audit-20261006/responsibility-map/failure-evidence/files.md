`run_fmt` reads every operand and parses all before any write. Missing/nonUTF8 input is E7002/2; parse diagnostics exit10 with no writes. Check mode writes nothing. Already canonical input does not invoke the writer; repeated/alias operands already equal to formatted output also skip it. Otherwise original read bytes are compared before staging and again after writing. Later write failure is E7007/2, with earlier operand commits retained. Docs has no equal-output noop and passes no expected input bytes to its output writer.

The shared writer creates random destination-local `.can-` staging, writes through its open handle, restores captured permissions after writing and persists the requested entry. Existing symlink/hardlink names are deliberately replaced rather than followed for mutation; the other name's bytes remain unchanged. Unix regular modes—including a followed symlink target's mode—are restored; missing/nonregular outputs request0666 filtered by umask. Readonly-file replacement is controlled by the parent. Current readonly/privacy/mode/link behavior already has real-CLI tests in `file_ownership.rs`; private replacement tests inject partial writes, directory persist failure and concurrent creation/content/mode/inode/target changes.

Do not turn owned staging into unconditional cleanup/durability. Installed [tempfile documentation](https://docs.rs/tempfile/3.27.0/tempfile/struct.NamedTempFile.html) and pinned source show persist returns the owned temporary file on failure; this caller extracts its error and drops the owner. Ordinary Drop deletion is best effort and ignores errors. Process interruption can bypass it. Persist does not synchronize data/directories. Noclobber does not overwrite an existing destination, but its unsupported-platform/filesystem fallback hardlinks then attempts unlink, potentially retaining the temporary name. macOS uses the Apple no-replace route when supported; that is inspected implementation, not a new filesystem witness.

Race detection observes Unix dev/inode/mode plus file kind, length, readonly and modified time; the nonUnix branch lacks inode/device/mode checks. Source-byte comparison adds a fmt-specific fence. Parent substitution and the final narrow race remain outside adopted trust guarantees. Permission change before writer entry is captured as current mode, rather than restored from initial source read. Docs source/output canonical identity checks occur before analysis/render and do not lock the path. Hardlink identity and lexical aliases do not constitute an inode-preservation contract.

Docs refuses case-insensitive `.can`, literal input names and equal resolvable canonical names before reads. It analyzes valid inputs before spawning a fixed-argv renderer; errors produce no reference write. Missing output parents are not created. Portable source IDs normalize relative/absolute/symlink spellings against one root, with external markers and lexical fallback. This is representation identity, not filesystem ownership or lock authority. CLI lint `--fix` only reports; pure apply helpers require a caller-supplied actual text hash and check expected hashes/spans/overlap before returning updated text. They are not filesystem application/CAS APIs.

CLI result output uses write_all and flush. BrokenPipe retains the command result code; other write errors panic and executable catch maps2/E7005. Thin producers receive argv without a shell and inherit stdio; exit code forwards, signals map2. PATH lookup chooses existing files and explicitly lacks Windows PATHEXT support; spawn detects an unexecutable first candidate. Renderer writes stdin then waits/captures; early pipe-write error has no explicit wait/reap and unbounded capture/timeout belongs root's failure lane, not a fresh observed failure here.
