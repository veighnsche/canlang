## Lexer, layout and parser boundaries

NAME is explicitly ASCII (`GRAMMAR.md:16`; `lexer.rs:416-422`), contextual rather than globally reserved. Unicode is valid in prose and JSON strings. Unknown non-ASCII code scalars produce E1007 over the whole scalar's UTF-8 byte span (`lexer.rs:666-675`); no normalization or Unicode identifier expansion exists. `lex_bytes` (`195-208`) refuses invalid UTF-8 with E1002 at `valid_up_to`; source APIs take valid Rust strings. CLI `read_to_string` failure is E7002, not the raw lexer E1002 entry point.

LF/CRLF source bytes are retained as trivia; bare CR gets E1001, indentation/code tabs E1003, and raw string tabs E1006. Tabs below #/## are prose. `lex_string` (`447-504`) does not cross a physical newline. Invalid strings remain String tokens with missing decoded payload, allowing local callers to suppress only missing-value consequences. JSON decoder (`692-812`) accepts the JSON escapes and valid surrogate pairs, rejects lone surrogates/controls and uses checked UTF-8 slicing for malformed digit sequences. Public decoder input assumes enclosing quotes; arbitrary malformed direct helper calls (such as empty raw input) are a separate precondition risk, not a production-source recovery regression.

Layout (`99-289`) emits E1101 at mismatched closers and pops one bracket to help joining terminate; E1102 at the final unclosed opener flushes pending tokens so coverage survives. An unclosed delimiter can join every subsequent physical code line through EOF. A declaration-looking line in that joined suffix never reaches parser as an independent sibling. This is a synchronization policy boundary distinct from effects suppressing already admitted sibling declarations: grammar says newline ends a logical line only at depth zero. No heuristic resynchronization policy has been selected.

Descriptions are preserved even when ineligible, malformed or dangling (`attach_level`, `373-469`; `decode_description_set`, `473-562`). Malformed reference/suffix helpers return empty reference/None locally. Full-line comments do not join logical lines, description prose within delimiters becomes inline schema/parameter metadata. Empty/dangling marker lines become Error nodes in place.

`parse_program` has no global error return: each top-level/root boundary advances independently. `Parser::attempt` (`625-652`) rolls back byte cursor, comment position and speculative diagnostics after Fail, then recovery repushes the source once. `error_for_line` (`533-587`) uses an iterative stack; expression/suite budgets bound valid parsing too. EOF token expectations anchor at zero-width end of the relevant piece (`piece_eof`, `185-190`), not necessarily end of file. Split-semicolon failures reject that logical line; subsequent logical siblings still progress. Syntax Error-token pieces are wrapped without repeating lexer findings. Invalid String tokens are distinct from Error tokens.

Builder gaps/comments and trailing `finish` preserve every byte; `SyntaxNode::verify_coverage` (`319-347`) verifies leaf partition of `[0,len)`. Coverage alone does not mean declaration admission or complete diagnostics. `SyntaxNode::has_errors` checks only Error nodes (`313-315`), unlike semantic `has_error` which also includes BadToken; invalid string E1006 need not yield either. Diagnostics are the compilation gate.
