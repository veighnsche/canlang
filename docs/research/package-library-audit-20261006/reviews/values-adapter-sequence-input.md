## CSV units (LIB-06)

Current manifest direction is **interfaces → ui** (`interfaces/package.json:53`); ui depends only on contracts (`ui/package.json:43`). A shared grammar adapter cannot be placed in interfaces and imported by ui. Contracts is neutral vocabulary, not a destination for a runtime CSV engine; values is not an appropriate generic CSV owner merely to avoid a cycle. No new package is justified solely for these two adapters.

Proposed default to evaluate: one pure CSV mechanics adapter under the existing UI CSV owner (new `ui/src/csv/grammar.ts`, narrowly exported package subpath), consumed by interfaces through a declared/exported boundary. Keep UI advisory shape and server authority/error mapping in their current wrappers. Interfaces already depends on UI, so this adds no dependency cycle. This placement/export is a **proposal** requiring UI/interfaces agreement, not an accepted ownership move. If its public surface/export cost exceeds the benefit, two very small library option/error adapters using the same locked parser are a fair alternative; compare net custom machinery rather than introduce another package or copy a custom grammar engine.

Never use columns:true to lose extra fields, skip blank/error rows, or stream past a malformed record while silently salvaging it.
