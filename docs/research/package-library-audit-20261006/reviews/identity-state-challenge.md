## 1. Token codecs and comparison: confirmed defect, bounded caller claim

[ECMAScript parseInt specification](https://tc39.es/ecma262/multipage/global-object.html#sec-parseint-string-radix). This contradicts the helper's malformed-input-false comment, regardless of exploitability.
- **Do not call this a demonstrated authentication bypass.** The function is publicly exported by `/Users/vince/Projects/canlang/packages/identity/src/index.ts:11`, but repository-wide non-test TS search finds no internal caller. Official current [docs](https://github.com/paulmillr/scure-base) and [source](https://raw.githubusercontent.com/paulmillr/scure-base/main/index.ts) provide case-insensitive strict `hex` and `base64urlnopad`. - `tokens.ts:35` base64url decoder currently ignores unused tail bits (e.g. source inference 'Zh' aliases canonical 'Zg'). A strict library changes malformed/noncanonical acceptance. Actual decoder callers are stored password salt/key parsing (`accounts/passwords.ts:78`), while opaque session tokens are issued unpadded then hashed as **text**, not decoded during lookup (`tokens.ts:119`, `:121`). Generated stored password encodings are canonical (`passwords.ts:62`); legacy/imported stored encodings still need compatibility evaluation. Do not tighten token semantics silently through a purportedly byte-neutral refactor.

Acceptance controls: strict hex syntax including partial prefixes, signs, whitespace, case, empty/odd lengths; false instead of thrown parse errors; canonical/unpadded base64 golden bytes, trailing bits and malformed input policy; SHA digest/text-hash preservation; whole Node22/Worker calls/import closure and error/length semantics. ## 2. Cookies: Domain validation gap confirmed; library default parse changes fail-closed semantics

- `/Users/vince/Projects/canlang/packages/identity/src/sessions/cookies.ts:34` and `:46` concatenate optional domain verbatim. Embedded semicolons can append attributes at helper-string level; CR/LF/control rejection is absent. Inspected production HTTP login/logout callers (`/Users/vince/Projects/canlang/packages/interfaces/src/http/auth.ts:202`, `:219`, `:222`, `:231`) pass secure/maxAge only, no domain. The option is a public helper surface (`identity/src/index.ts:12`) rather than a demonstrated attacker-controlled request field.
- jshttp/**cookie** supports domain syntax validation and codec options. [Official current source](https://raw.githubusercontent.com/jshttp/cookie/master/src/index.ts), [README](https://raw.githubusercontent.com/jshttp/cookie/master/README.md). Current source calls APIs parseCookie/stringifySetCookie; pin actual selected release rather than assuming an older parse/serialize signature. Its domain guard rejects invalid nonempty domains, but falsy empty domain is omitted; any change from today's explicit `Domain=` must be decided.
- Current Can parsing takes the **first named occurrence**, including empty/malformed, then returns null; it never proceeds to a later duplicate (`cookies.ts:63-70`). The library default returns raw text after percent-decoding failure. Returning undefined from a custom decoder lets it try a later duplicate. Both would violate Can's fail-closed behavior.
- Thin adapter candidate: parse with raw identity decoding (retain first raw target, including empty), then apply decodeURIComponent **once only to that target** inside existing null-on-error handling. Returning a non-undefined failure sentinel is another possibility. Do not throw on malformed unrelated cookies or skip malformed first target. Differences in quote handling and whitespace remain: Can trim() recognizes wider JS whitespace than current library SP/tab trim; pin the selected library behavior against current rules. Header arrays still join in caller order.
- Serialization must keep fixed HttpOnly/Secure/SameSite=Lax/Path=/, positive set maxAge vs zero clear, original IdentityError classifications, encodeURIComponent behavior and intentional attribute order. Library default encoding preserves some cookie octets whereas Can always URI-encodes token; preserve explicit encoder or adjudicate behavior. Exact cookie strings are pinned in `identity/test/sessions.test.ts:56`, `:64`.

Acceptance: malformed first percent value followed by valid duplicate, first empty then valid, duplicates across header arrays, unrelated malformed values, encoded delimiters, quotes and whitespace, no-throw parsing; Domain controls/attribute separators/empty/leading-dot names; secure clear/set parity and exact output/error contracts. This is transport mechanics reuse; keep credential/cookie security policy in Can.
