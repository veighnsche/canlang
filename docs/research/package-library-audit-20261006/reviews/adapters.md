### A1 — Replace CSV grammar engines with one library-backed adapter

Evidence: /Users/vince/Projects/canlang/packages/interfaces/src/http/csv.ts:166 and /Users/vince/Projects/canlang/packages/ui/src/csv/parse.ts:118 implement separate character scanners for comma/quotes/doubled quotes/record boundaries. They currently match on preserving blank records; no observed blank-row disagreement. /Users/vince/Projects/canlang/packages/interfaces/src/http/export.ts:165 implements CSV serialization escaping. The sizable CSV consent, authority, candidate binding, duplicate/replay and per-row outcome logic belongs to Can and should remain custom.

Recommendation: **replace** the scanners with a shared **thin adapter** over csv-parse; consider csv-stringify for export grammar. Official [browser ESM distributions](https://csv.js.org/parse/distributions/browser_esm/) include a sync import. [relax_column_count](https://csv.js.org/parse/options/relax_column_count/) retains inconsistent field counts in array mode; avoid columns:true because extra/unmatched fields can be discarded. Set explicit [record delimiters](https://csv.js.org/parse/options/record_delimiter/) rather than autodetection. Browser ESM documents bundled polyfills, so evaluate delivered size/Workers compatibility rather than assume a free dependency.

Acceptance: match CRLF/LF, multiline fields, double quotes, lone-CR-as-literal, blank rows, trailing virtual record, empty header errors, malformed-row flags, 1000-row cap, strings with embedded unexpected quotes, BOM behavior and public error mapping. Current scanner treats any quote as quote-mode entry; a mature strict parser will not necessarily match this odd edge. Decide whether to preserve or deliberately reject those inputs; do not quietly change consent digest identity. Existing cases: /Users/vince/Projects/canlang/packages/ui/test/csv.test.ts:131,138,153,160,171; corresponding interfaces CSV route/review suites were inventoried, not run. /Users/vince/Projects/canlang/packages/ui/scripts/build-browser.mjs:20 restricts installed browser module imports; determine whether the advisory parser actually belongs in delivered client assets and bundle any new imports where required.

Keep Can's formula-neutralization policy around csv-stringify: /Users/vince/Projects/canlang/packages/interfaces/src/http/export.ts:160 protects formulas after whitespace; /Users/vince/Projects/canlang/packages/ui/src/escape.ts:73 protects a broader leading whitespace/control set. Library [escape_formulas](https://csv.js.org/stringify/options/escape_formulas/) has different leading-character coverage. Accept exact newline/trailing-record/header/order/neutralization bytes and no double-prefixing; replacing quoting does not authorize narrowing spreadsheet protection.

### A2 — Replace manual signal composition with platform AbortSignal.any

Evidence: /Users/vince/Projects/canlang/packages/services/src/http/client.ts:182-206 manually registers/removes listeners and creates an intermediate controller. Package hosts already use native Fetch and Node>=22 (/Users/vince/Projects/canlang/packages/interfaces/package.json:62 and /Users/vince/Projects/canlang/packages/ui/package.json:51).

Recommendation: **replace** signal fan-in with [AbortSignal.any](https://nodejs.org/api/globals.html#static-method-abortsignalanysignals), available since Node20.3/18.17. It preserves the winning abort reason, unlike the current empty merged.abort(). Retain controllable/released timeout timer, full-response-body deadline, fixed-origin redirect checks, byte caps and Can error classification. Acceptance: already-aborted signals, cancellation-before-send, timeout-vs-caller priority/races, stream cancellation/reader release, no lingering deadline, actual Workers host support.

**Retain** native-fetch wrapper as policy; bulk Ky/Axios substitution is not yet supported by net complexity evidence. [Ky's documented defaults](https://github.com/sindresorhus/ky#retry) retry network/status failures for several methods; Can's delivery/idempotency/retry ownership would require disabling/qualifying this behavior. Same-origin validation must precede every redirect request; header/body timeout and max bytes apply across hops. Review acceptance should include redirect bodies: /Users/vince/Projects/canlang/packages/services/src/http/client.ts:267 currently calls response.arrayBuffer() for redirects without the normal byte cap. A library name alone does not resolve that gap.

### A3 — Evaluate file-type behind byte-policy adapter, not unconditional replacement

Evidence: /Users/vince/Projects/canlang/packages/files/src/upload/index.ts:92-148 hand-recognizes three binary signatures and strict nonempty UTF-8/no-NUL text; checkContent:155 keeps labels as evidence and judges actual bytes against an allowlist/max bytes. The source explicitly declares structural parsing out of scope at127.

Recommendation: **evaluate** [file-type](https://github.com/sindresorhus/file-type) when expanding supported binary formats; library owns signature catalog, Can retains allowlist/provenance/quota rules and custom plain-text recognition. Official README says binary only, best-effort signature detection, not structural validity. Current package manifest [source](https://github.com/sindresorhus/file-type/blob/main/package.json) is ESM and Node>=22; async detector integration and installed Worker bundling need qualification. Do not substitute extension/header-based MIME inference for inspecting bytes.

Acceptance: old PNG/PDF/JPEG fixtures (including truncated signature-only inputs), ambiguous UTF-8/PDF, empty text, NUL and invalid UTF-8, unknown binary formats, exact detected MIME/allowlist equality, synchronous-to-async call contract, parser limits/host memory. With only three accepted signatures, keeping the tiny implementation is a defensible smaller dependency choice; no demonstrated format-correctness improvement was measured.

### A4 — Evaluate official Ollama client; retain strict stream verdict ownership

Evidence: /Users/vince/Projects/canlang/packages/services/src/models/ollama.ts:490 serializes chat body and parses NDJSON lines manually; :564 performs buffered newline splitting, while :370 classifies progress/final/error into Can states and validates terminal reply. Can freezes requests, tracks delivery identity/cancel races and refuses HTTP200 partial streams as success.

Recommendation: **evaluate** [official ollama-js](https://github.com/ollama/ollama-js) as a protocol codec/SDK behind the adapter, not a drop-in. It offers chat streaming, browser entry and configurable fetch. Its [actual parseJSON implementation](https://raw.githubusercontent.com/ollama/ollama-js/main/src/utils.ts) catches invalid JSON and console.warns the raw line (279-315), while Can immediately fails invalid JSON; upstream also documents instance-wide abort, recommending one client per stream. These are material compatibility/privacy differences.

Acceptance: preserve malformed-line fail-closed behavior without raw provider logging, chunked UTF8/newline handling, final done validation, maxBytes/full-stream deadline/fixed-origin redirect rules through injected transport, per-run cancellation, first-terminal-wins, request freezing, incomplete EOF, error redaction and exact delivery-state mappings. If SDK cannot supply this without another parser and duplicated controls, retain current adapter.
