## Findings and proposed disposition

### ND1 — Replace import lexing/rewrite mechanics with a thin library adapter (strongest current TS candidate)

Evidence: `/Users/vince/Projects/canlang/packages/cloudflare/src/deploy/bundle.ts:373` regex import collection, `:425` rewriting, `:454` runtime and `:498` vendor rewriting; `/Users/vince/Projects/canlang/packages/cloudflare/src/runtime/modules.ts:69` repeats collection and `:90` rewriting. Candidate: **es-module-lexer** for actual import/reexport ranges plus **MagicString** for range edits. Official docs verify decoded escaped specifiers, literal dynamic imports, import attributes, comments/templates/regex grammar handling; lexer is deliberately not a complete validating parser. [Lexer docs](https://github.com/guybedford/es-module-lexer), [MagicString docs](https://github.com/Rich-Harris/magic-string).

Keep Can's allowed specifiers, producer mappings, path containment, module-key resolution, duplicate-last-wins layering and first-fault policy. Prefer one existing Node/Bun host adapter if that fits native ownership; do not add a second independent Rust JS stack merely for mirrored convenience. Ownership is an evaluation proposal, not an accepted move. Node-only build use avoids Worker dynamic Wasm compilation constraints; library supplies JS builds if the environment cannot compile Wasm.

Acceptance: static/side-effect/reexport/literal dynamic imports; escaped names; regex literals and quoted/commented false positives; nested template expressions; attributes and binary imports; explicitly refuse or classify computed/glob imports instead of silently admitting them. Offsets must remain UTF-16, edits non-overlapping, lookup names decoded while emitted quoting stays valid. Preserve existing import policy/error order, staged key set, no file-URL/bare import leakage, deterministic bundle bytes and changed-byte review/digest behavior. Current `runtime/modules.ts:180` rewrites JS but writes the original map at `:183`; prove columns after length-changing same-line edits or compose transform maps into compiler maps. MagicString generates transform maps; composition is a separate control, not solved merely by adopting its editor. Current **@jridgewell/remapping** supports composition through a loader or newest-first map array: [maintainer monorepo API](https://raw.githubusercontent.com/jridgewell/sourcemaps/main/packages/remapping/README.md), [manifest](https://raw.githubusercontent.com/jridgewell/sourcemaps/main/packages/remapping/package.json) (repo version 2.3.5, MIT, ESM export; not a verified npm-release choice).
