# Economical implementation and review allocation

Planning only. All 48 packet labels remain refinements of existing tasks; statuses, scope, files, dependencies and acceptance are unchanged. Three implementation lanes take finite packets; their model changes with the packet. No implementation, timer, API experiment or global model/tier setting is started.

These are task-informed starting choices, not a measured optimum for Can. Choose the least expensive supported reliable pair over the full task, including failures and review. The previous uniform Sol/high field records completed planning work; it is not the implementation default.

## Cost policy

- Luna low: specified receipt/index/record updates.
- Luna medium: seeded fixtures and exact frozen mechanics; no contract or acceptance judgments.
- Sol low: tightly specified technical leaves with released witnesses.
- Sol medium: ordinary bounded code and debugging.
- Sol high: actual ABI, authority, lifecycle, resource, durable or installed joins; split already frozen leaves when that saves complete-task cost.
- Astra: required finite critical/expert stages only, preserving existing approval, security and source-current scope gates.

Use compact task-specific context, independent risk-matched review, unchanged accepted receipts and actual failure evidence. Do not pay for repeated broad prompts, busy polling or full-history forks. Model allocation alone does not release a blocked packet.

Official guidance identifies Luna as efficient for scoped work, Sol as a cost/quality technical choice, and lower reasoning as generally using fewer tokens. API prices are only a comparison aid; subscription usage and actual Can savings are unmeasured. ## Critical review gates

Ordinary local Sol review does not replace mandatory security/authority/timing/diagnostic/final joined review. These gates are deduplicated stages, not an additional Astra run for every linked packet. Existing review/source/host limits and pending approvals remain binding.

- **existing-critical-security-review — gpt-6-astra / high:** Existing critical review remains approval-pending; preserve its actual selected scope and required effort. No invocation or egress retry here. One matched scope/source-current critical review covers its associated packet crosswalks; ordinary Sol review does not replace it and rows do not create separate duplicate Astra obligations.

- **persisted-security-and-timing-contract-if-changed — gpt-6-astra / high:** Preserve existing I01 persisted security/I03 timing guarantee stage when its actual contract is changed or a consequential guarantee is selected; unchanged accepted codec/cookie/library evidence is reused at its exact scope. Single finite contract/guarantee stage; pure later frozen adapters use their local allocation. Owner/JEV release precedes coding.

- **consequential-owner-store-contract-if-selected — gpt-6-astra / high:** Only an evidenced consequential new owner/store security topology decision calls for this expert judgment; current alternatives are unreleased. Share a matching existing critical review when its scope/evidence genuinely covers the decision; otherwise name one finite new stage and preserve access/approval rules.

- **C03-critical-consent-authority-review — gpt-6-astra / medium:** Existing required authoritative review-to-commit critical join, after actual selected producer/consumer release. Local source-row ordering and canonical helper changes do not each create an additional consent-critical review.

- **D04-critical-staged-diagnostic-review — gpt-6-astra / medium:** Existing required actual changed-length staged/installed diagnostic join when affected; reuse unchanged previously accepted source-current critical evidence. No blanket repeat of all map/source/API reviews merely because a namespace leaf changed.

- **R03-final-selected-critical-review — gpt-6-astra / high:** Existing finite independent critical combined-invariant review after actual selected required scope and writer/command release. One final selected joined review. No implementation worker on this review-only packet; do not re-review unselected/held work as accepted.

## Dispatch and escalation

Every packet records exact implementation/review model and effort, reason, admissible cheap scope, prepared-record/fixture choices, special review references and escalation triggers in [model-allocation.json](model-allocation.json). Recheck before each finite dispatch. Stop if the oracle or contract is unreleased, the negative witness contradicts the chosen recipe or new policy/representation/lifecycle work is needed. Escalate the actual unresolved stage, preserving completed evidence and live command handles; do not restart a whole lane.

Known risk is handled upfront; a cheap model is not required to fail before a critical join gets the right model. No guarantee of zero retries or minimum dollars/wall time is claimed.
