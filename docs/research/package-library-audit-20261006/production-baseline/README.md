# Package production baseline

Step 1 source baseline, completed 2026-10-07. This records size and declared
boundaries; it does not authorize implementation or establish production
adoption. The native preparation hold and existing acceptance limits remain.

The comparison is the **pre-library-adoption source** at
`309644a6881909d8dba32560bc6711f67e00a7ab` versus
`8f33aa5e29d25bf3ea4d6035c7b2e3ddc0427854`. The original already contains Rust
port candidates: this is not a before/after comparison of the entire Rust-port
programme. Both snapshots include every committed blob under `packages/`.
Compiler and editor work is outside this denominator.

## Reproduce

From the repository root, with Python 3.11+ and the existing TypeScript 5.9.3
dependency available:

```sh
python3 docs/research/package-library-audit-20261006/production-baseline/measure.py \
  --out /private/tmp/canlang-package-baseline
```

No dependencies are installed, modules resolved, product code emitted, builds
run or Git state changed. The script reads immutable Git blobs. Its output is:

- `summary.json`: totals, owners, languages, dependency declarations and root input hashes.
- `files.tsv`: every file, blob/SHA-256, bytes, category and exclusive source/test counts.
- `classified-ranges.tsv`: inline Rust test and reviewed scaffold ranges.
- `manifests.jsonl`: exact package exports/imports/bins and dependency/Cargo feature declarations with source hashes.
- `interfaces.tsv`: exported source declarations and reexport candidates, retaining type/signature distinctions.
- `moves.tsv`: reviewed implementation transfers with identical-line matching.

Only the small [summary](summary.json), classification rules, tool and
[mechanism inventory](mechanisms.jsonl) are committed. Detailed indices are
regenerated on demand; source, fixture and manifest contents are not copied
into another evidence tree. [Verification](verification.json) records output
hashes and independent classification checks.

## Measurement

All lines are **LF-delimited physical source lines**, including comments and
blanks. They are maintenance-size units, not counts of executed statements or
installed bundle size. Bytes are exclusive too. Runtime candidate source is
`implementation + definitions`, with tests, generated text, data, scaffolds,
tooling and documentation counted separately.

Implementation-bearing source excludes whole test/example/conformance paths,
inline Rust `cfg(test)` items and pure top-level TS type declarations, overload
signatures, ambient declarations and type-only imports/exports. Embedded type
annotations remain part of their implementation line. Mixed physical lines
remain implementation conservatively. Definitions are maintained interface
source, not additional runtime instructions.

## Moves and scaffolding

Schema's 1,964-line old implementation moved into the 1,978-line internal core,
retaining 1,950 identical lines. Wire's 1,766-line implementation moved into a
1,766-line core, retaining 1,755 identical lines. The old paths retain small
facades. These are two implementation transfers, not two new duplicate engines
and two deleted engines. Git `-M` alone reports no rename because the old paths
remain. Import rewriting was extracted and rewritten; CSV grammar was
centralized from two callers. Those are responsibility changes, not literal
file moves.

The old six-line version-only work-kernel Rust root is scaffold; the current
root registers real decision modules: its runtime candidate contribution is
0 → 9 lines, with three other current lines excluded as an inline test module.
The native preparation probe
script and fixed six-operation values smoke table are separately measured
scaffold ranges. They still contain executable, maintained compatibility
behavior. Other native preparation stages and structural validation remain
implementation; a stale “scaffold” header does not erase real code. Likewise,
the authored currency table is data, while its emitted Rust lookup and
wasm-bindgen glue are generated. Generated code can execute and ship.

## Dependencies, interfaces and duplication

Declared external runtime npm dependencies grew from two distinct libraries
to nine: added `@jridgewell/remapping`, `@jridgewell/sourcemap-codec`,
`es-module-lexer`, `magic-string`, `@scure/base`, `cookie` and `csv-parse`.
`ryu-js =1.0.3` was added to two Rust crates; values enabled serde_json's
`float_roundtrip`. Exact specifications/features and package-local lock hashes
are recoverable from the output. Root `package.json` and `bun.lock` hashes are
recorded separately. This is declared dependency accounting, not an installed
transitive graph, license audit or runtime reachability verdict.

The 13 npm packages expose 154 → 156 export subpaths: added Cloudflare
`./runtime/invoke` and UI `./csv/grammar`. There is one new internal import key
for the identity host comparison and one unchanged CLI bin. Types/default or
Node/Worker conditions are variants of one key. Export maps include testing,
distribution and generated asset boundaries; `private: true` does not remove
their internal contract. Source declaration candidates grew 3,997 → 4,044;
these are not deduplicated semantic public APIs. Barrels, overloads, methods,
restricted Rust visibility and unresolved star reexports require caller and
namespace analysis in the next audit step.

The mechanism inventory records eleven bounded families with source locations:
six TS donor/kernel overlaps, deliberately coexisting TS/Rust decision and
preparation responsibilities, repeated Rust JSON/UTF16 support, and the CSV
grammar duplication that has been removed. Namespaced producer/error profiles
and required fallback paths remain relevant. These are observed maintenance
overlaps, not permission to delete code or proof of interchangeable behavior.
The list is a baseline of verified families, not an exhaustive semantic clone
detector; unknown overlaps remain for the responsibility/caller audit.

## Limits and review

Luna low extracted manifests/markers; root verified both immutable snapshots
and corrected an initial original/current labeling error. Sol medium checked
ambiguous classifications, exact Rust test ranges, generated versus authored
tables, transfers and repeated mechanisms. Its overload/type-export and
snapshot-specific assembly corrections were incorporated. The baseline's
category sums reconcile to every scoped blob and byte, and two runs reproduce
the committed summary and output hashes.

Ignored `dist`, `target`, dependency caches and temporary evidence are build
outputs, not this source denominator. Existing tracked generated assets are
included. A publication-time check separately verifies package dirty/untracked
overlays and package equality with the pinned current source; other agents'
compiler/editor commits do not change these package counts.

Runtime candidates have not all been demonstrated shipped or reachable.
Values' opt-in six-operation backend, broader Rust validation/work consumers,
native preparation and installed/durable/rollback qualifications keep their
existing limits. Planned catalog entries are not implemented APIs. No task
parent, release checkpoint or whole-programme acceptance advances from this
measurement. Product simplification proposals belong to subsequent audit
steps; this step changes audit artifacts only.
