# Change and migration requirements

No migration or implementation is authorized by this audit. Per-rule records
identify affected consumers, stored/wire artifacts and uncertainty. Their
`required_if_changed` applies to the described incompatible change; equivalent
library substitution with identical outcomes/bytes needs relevant qualification,
not automatically a new protocol or database transformation.

## Transition gates

1. **Identify authority and the actual change.** Name the rule ID, current and
   intended domain/outcome/bytes, accepted source stage, real public consumers and
   genuine stored artifacts. Current source names alone do not establish deployed
   data. Keep incomplete desired behavior separate from existing format promises.
2. **Inventory the predecessor.** Use exact deployed owner/release/schema,
   credential format, pending-work inventory and retained producer contract where
   applicable. Missing evidence is a blocker; do not infer old meaning from a
   convenient current declaration or reconstruct erased original inputs.
3. **Select a bounded transition.** Preserve compatible readers or introduce an
   explicit profile/version/namespace/deprecation route. Security revocation,
   authority and disclosure cannot be weakened for convenience. Do not rehash
   mutable current objects to pretend an old receipt or occurrence has migrated.
4. **Check real producers and consumers.** Include old/new reader controls,
   errors/order/identity, replay/current access, partial failure and actual selected
   installed host. Test fixtures and narrow helper receipts do not prove a joined
   workflow, concurrent winner or durable migration.
5. **Define rollback and retirement.** Retain a compatible old reader/release
   while needed, without resurrecting expired credentials or replaying effects.
   State what irreversible data changes preclude rollback. Remove superseded
   mechanics only after their actual callers switch; preserve TS/backend retirement
   and native preparation HOLD gates.

## Boundaries to keep separate

| Boundary | Required transition if changed | What equivalent simplification may change |
| --- | --- | --- |
| Identity token/password/email/cookie formats | Exact credential text/hash and password parser compatibility; account/email collision inventory; current expiry/revocation; explicit new issuance/read profile. Strict alias decoding cannot silently reject old salt/key records or change bearer equality. | Platform crypto/codec/cookie mechanisms within the released profile; no requirement for a hand-written duplicate encoder. |
| Atomic identity admission | Winner, recovery all-or-none, last-owner and principal/source/expiry outcomes. Reconcile existing owner/storage APIs and actual conditional-update result consumption before choosing the proposed fence. | Transactions/conditional statements/fence implementation, once the supported storage guarantee is demonstrated. |
| Receipts, input digest and defaults | Keep old namespace, pre-fill/normalized-input distinction, expected versions, frozen defaults, status/projection and same-ID replay. A new profile requires explicit reader/version handling, not digest recomputation from newer inputs. | Hash/serialization implementation preserving the chosen profile; error prose separately assessed. |
| Work occurrence/outbox/fanout IDs | Inventory both actual ID producers, queued rows, claim/revision lineage, retained handler contracts and recipient authority. Preserve missing historical evidence as missing; no inferred current handler backfill. | Percent encoding, digest and state-transition mechanics behind one owning boundary. |
| CSV review/consent | Delimit accepted grammar from richer typed mapping/business review; bind the selected private source/candidates/context/lifetime, row IDs and explicit renewed consent. Expired or changed review cannot be accepted merely because a render-created operation ID is recent. | Shared parser mechanics and schema adapters; no alternate business invocation engine or client-authoritative validation. |
| Files and private exports | Keep digest/key/retry/provenance/attachment identity and authorization; inventory stored objects and active lifetimes before encoding or cleanup policy changes. A provider byte capability is not business authority. | Host streaming, hashing and storage-client mechanisms; preserve owner-issued identities and bounded cleanup. |
| Compiled source/deploy digest/native wire | Exact producer source identity, reviewed bytes, predecessor/installed manifest and compatible paired protocol; separate temporary frames from historical business data. Document partial publication and actual invoked-binary integrity. | Lexer/map/hash/process mechanisms; fewer coarse seams are permitted when input/profile/consumer proof survives. |
| Public input/error/library profile | Survey declared/current supported callers and any stored input before narrowing. Separate structured codes and deliberate refusal from exact prose/host-object traces with unresolved authority. Announce/version/deprecate real breaking changes. | Replace mechanics directly where existing callers need no adaptation; don't emulate every historical quirk only to claim library use. |
| Required but incomplete product joins | Select the missing finite producer/consumer/host contract, preserving refusal until real capability exists. No historical prototype success is inferred. | Remove deliberate scaffolds after actual replacement and support callers qualify. |

## Unresolved does not mean preserve forever

The open classification is a finite decision obligation, not a reason to build a
permanent adapter. Obtain concrete domain/caller/persisted evidence, compare the
simpler alternatives against the same outcome, and consult repository JEV for a
new difficult choice. Record that later decision with its owner and uncertainty.
Do not turn this audit into an adoption, TS deletion or implementation command.
