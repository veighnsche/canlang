# Evidence cleanup proposals

No cleanup is implemented. Before deleting or factoring evidence, map its real
readers, distinct oracle and historical scope; preserve decisive negatives and
immutable provenance. Size alone does not justify replacing an independent golden
with output computed by the implementation under test.

| ID | Candidate | Disposition and gate |
| --- | --- | --- |
| EC01 | Original donor and negative witnesses | Retain frozen gzip/source captures, astral/UTF16 mismatch, excluded layout-red run, stale-map coordinate and pristine/patched pilot identities. Never regenerate a golden to make a mismatch green. |
| EC02 | Repeated 10,213-number projection | Conditional: one immutable primitive donor and deterministic materialization after every JS/Rust/public reader is mapped. Keep distinct Values/Work callers, profiles, errors and version provenance. |
| EC03 | Old flat native corpus and huge Rust fixture bodies | Conditional: prove current Cargo selection, registered coverage, generator/byte identity and historical pin mapping. A 153-module frozen fixture need not equal a current 161-module graph. |
| EC04 | Repeated arithmetic/schema setup | Conditional: factor pure test construction or the independent test-only digit-string algorithm, preserving literal/order/getter/clone/proxy assertions. Do not use production machinery to manufacture expectations. |
| EC05 | Six repeated JSON array sections | Conditional immutable references after reader/provenance review. Equal pins/checks are not equal complete receipts; original failure and repaired result stay inspectable. |
| EC06 | Four exact duplicate groups, 770 bytes | Retain now: bad/good environment/descriptor/target metadata deliberately isolate different artifacts. Empty logs save zero bytes; no new helper layer for this saving. |
| EC07 | Runtime assets and public/type frontiers | Retain Wasm/currency runtime inputs, public conformance APIs and independently authored export/type/hash pins. Runtime true arrays need enforced compile-pin coverage before mechanical removal. |
| EC08 | Scratch ownership and reset domains | Conditional harness cleanup after child/loader ownership ends and failures are compactly preserved. Reconcile omitted reset tables; never clean foreign resources or shared caches. |
| EC09 | Receipt status/count/observation fields | Annotate historical scope rather than rewrite it: actual backend path, input bytes, named command, byte units, effect domain, source/handcrafted/emitted/mounted/installed stage and residuals. |
| EC10 | Real transaction/host/installed controls | Retain D1/workerd/DO fences, independent SHA/RFC/Decimal/BigInt, localhost limits/redirects and written diagnostic/asset refusals. A helper test beside a real test does not invalidate either. |

[Machine list](cleanup.json) provides claim cross-references and retention gates.
[Inventory summary](inventory-summary.json) and [scanner](inventory.py) distinguish
byte duplicates from repeated JSON sections and ordered numeric projections.
They do not parse arbitrary generated TS/Rust arrays or prove equivalent semantic
coverage. The full inventory can be reconstructed from frozen Git blobs instead
of copying another 629-row manifest into this audit.

Cleanup follows corresponding verification groups TV01–TV15. It must not wait on
unrelated held work, and it must not precede the reader/independence gates that
protect its own evidence. Production deletion, test rewriting and canonical
acceptance remain deferred.
