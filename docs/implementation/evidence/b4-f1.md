# B4-F1 parser fix evidence

Scope: `each=` recovery on trusted scenarios; regression pins for
`delivery()`/`invocation()` types, `expose=`, `refresh=`, `import=csv`/`review=`.

## Fix (compiler/src/syntax/parser.rs)

`parse_scenario` intercepted `each` before the unsupported-attribute
hard error. New `parse_each_attribute` parses `each=<path> [as <name>]`
into a standard 3-child `Attribute` (+ `as`/binding leaves beside it,
mirroring `send`/`create` aliases) and reports the identical `E1203`
(`unsupported scenario attribute \`each\``, same span) as a non-fatal
push, rolled back by `attempt` if a later attribute fails. No `Error`
node is produced, so `index_module`'s `has_error` bail no longer drops
the enclosing package (resolve.rs untouched, out of scope). Downstream
readers all use keyed attribute lookup, so the `each` attribute is
inert to them; `each`-bound aliases surface as E2001 proposal
knock-ons. Malformed `each` (duplicate, bare) still hard-errors
(E1202/E1200), consistent with other attributes.

Tasks (2)-(4) needed no parser change: the Rust parser already accepts
`delivery()`/`invocation()` in all type positions (all `parse_type`
call sites), `expose=` (Selectors), `refresh=` (Path),
`import=` (Name) / `review=` (Path). A full-draft sweep confirms the
only E12xx in the corpus were the 4 `each` E1203s.
