## Fixes (compiler/src/analysis/types.rs)

1. **Local-event payloads typed.** `phase2_scenario` seeds the guard/body
   narrowing env with `event` → the declared event record (new
   `on_event_payload`: single-segment local events and `Cap.event`
   capability events; queues/timers/hooks/change-events/completions
   stay opaque). `event.check`/`event.appointment`/… now carry declared
   types, so bare enum cases claim and member misses are `E2013`
   instead of `{opaque}` cascades.
2. **Auth narrowing parity.** New `auth_proves_actor` mirrors the
   resolver's `proves_auth` boolean structure and additionally accepts
   bare role references. `phase2_scenario` seeds `actor` → `user` for
   guards/bodies when `by=` proves auth; `phase2_rule` types policy
   `where=` under the same narrowing when `read=` proves auth
   (`read=` itself stays pre-auth). `by=public` and mixed
   `or`-with-weak-arm forms still leave `actor` nullable.
3. **Empty-array unification.** `type_array` adopts the expected element
   type (nullable-unwrapped) for `[]`, so `file[]=[]` field/param
   defaults, `set` values and call args unify instead of reporting
   `array of {unknown}`.
4. **Message descriptors in overloads.** New `is_message_descriptor`
   (through groups); the `SigType::Message` matcher arm accepts
   `text`-typed inline `"…"@{…}` descriptors, and `check_format_call`
   treats them as the message overload (skips template-key checks), so
   `format("…"@{…},locale=null)` matches
   `format(descriptor:message,locale:locale?)`. No `ResolvedType`
   variant was added (inline descriptors declare no `Message` symbol).
5. **Derived fields never required inputs.** `field_is_required_input`
   returns false for `DeriveField` (mirroring `field_is_required` for
   constructs): derived fields stay readable members/selectors but are
   not demanded by `create`/fixture/invocation/CRUD-create inputs.
6. **Delivery-observation leaves in selectors.** New
   `selector_delivery_leaf` (silent try, then legacy diagnosis): in
   policy `fields=` and UI `columns=` only, a path terminating at
   `id`/`status`/`error`/`result` on a `Delivery`-typed or opaque
   (deployment-bound) delivery value is accepted when its prefix
   navigates as expressions do (nullable-unwrap, record fields).
   Leaves are terminal (`request.result.state` still fails);
   `parent`/reserved/model-interior non-delivery paths
   (`latest.created`, `observed_match.created`) still fail; lock/unique/
   form/search/filter/by selectors keep the contract-only rule.
7. **Timeline `slot item` row.** `walk_ui_page` seeds a `row` narrowing
   to the timeline domain model for the `timeline` catalog item's
   subtree (query domains via recorded node types, bare-model domains
   via namespace fallback since resolve never walks catalog
   vocabulary). Sibling subtrees keep the incoming context.
8. **New `E3019` opaque-capability-receipt.** Fires where a receipt is
   silently opaque: `send` to an external-rooted opaque target (new
   `external_target_name`; `Error`/`Unknown` targets stay silent) and
   delivery-recipe fixtures for bound-external ops, covering both the
   `Operation(None)` arm and the `Unknown`-with-external-head arm
   (2-segment external heads resolve to `Unknown` with no `E2001`;
   genuinely unbound heads stay `E2001`-only). Locally-declared
   capability sends/recipes are unaffected (still fully checked).
   Entry `E3019`/`opaque-capability-receipt` added to `explain.rs`
   (catalog 110→111) with round-tripping valid/invalid examples; the
   types module-doc `E3xxx` allocation lists it.

## Follow-up F6: G1 `set x.parent` fixed in the types pass

Fix (only `compiler/src/analysis/types.rs`): `member_lookup_on_span`'s
`Record` arm checked declared fields only, while expression `Member`
lookup (`record_member`) also handles reserved members,
contained-model `parent`, and child collections — so `set x.parent`
`E2013`d where `x.parent` reads. The shared dispatch now lives in a
new `record_member_at_span` (span-parameterized; `record_member` and
the path arm both delegate, with `unknown_member_at_span` under it),
so set-target resolution matches expression resolution exactly and
phantom members still `E2013` with byte-identical messages. No
resolve.rs change (per b4-f2.md §3: no table it owns can steer that
navigation); non-record bases in path position are untouched.

Tests (`compiler/tests/b4_setparent.rs`, 4 tests, all failing-first
verified against the pre-fix tree): `set_parent_resolves_like_expression`
(flips the `set_parent_target_current_behavior` characterization),
`set_parent_enum_value_elides` (CanBook ×8 shape: `E2013` + `E2001`
cascade before, clean after), `set_parent_bad_value_still_errors`
(`set t.parent {bogus_field_xyz=1}` errors against model `Cafe` —
the resolve-only patch checks this clean per b4-f2.md §3), and the
`set_parent_phantom_member_still_e2013` guard (passes before/after).
