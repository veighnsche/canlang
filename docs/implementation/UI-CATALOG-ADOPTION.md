# Full UI catalog adoption contract

The user approved the full daisyUI proposal on October 4, 2026 and explicitly instructed this round to leave `.can` files unchanged. The former small subset was a design mistake: it restricted agents and cannot remain Can's frontend boundary. [All 68 pinned components](../design/UI-COMPONENTS.md) are required language/library scope. Full availability means appropriate component choice, not adding every component to every app.

All apps use the shared static shell: right-sidebar page menu, bottom-right user menu, common configuration dialog and canonical login screen. Destinations and access derive from owning page descriptors. App-selected shell layouts are not adopted. Compiler, UI and Interfaces consume the same source-owned bindings, grants, versions, field/result scopes and localized messages.

Reviewed `.can`/desired-output companions express the entire frontend workflow; missing producer support is represented as a specific dependency, not silently removed from the source. Implementation and remaining acceptance are owned only by [REMAINING-WORK.md](REMAINING-WORK.md#draft-frontend-acceptance). The original adoption history is preserved in [the committed handoff](https://github.com/veighnsche/canlang/blob/104d87b63a31ce29b18fa8e0e4332489122e9bec/docs/implementation/UI-CATALOG-ADOPTION.md). Obsolete lane-launch and mixed-commit publication instructions are retired.
