# Package boundaries and build/cache contracts

B01–B08 package/build migration is accepted at its recorded scope; reuse final acceptance. Current native/release gaps are in [REMAINING-WORK.md](REMAINING-WORK.md). This document preserves the package, output and cache contracts, not a rollout queue.

## Outcome and scope

Keep Bun as package manager and use Turborepo for repository task scheduling and suitable artifact caching. Every consumed TypeScript package, including internal packages, has a declared manifest relationship and an intentionally exported API. Relative imports within one package remain ordinary; sibling source/dist paths and aliases that bypass another package's API are removed from production, tests and tools. Each package compiles only its own implementation.

Retain native dependency ownership in Cargo, Go and Python manifests. Experimental native Turbo discovery is selected only after the actual layout passes a bounded probe. Existing native task adapters remain available where discovery cannot preserve that layout. Do not create Go projects or convert standard-library Python scripts into uv packages merely to populate the graph.

This work changes packaging, imports, build/test orchestration and its documentation. It preserves authored `.can` semantics, evaluation order, current backend selection, permission/failure behavior and package-specific tests. It does not complete missing work-kernel algorithms, invent a receipt observer, qualify native releases, resume the preparation port's human HOLD, or claim universal Wasm support. Necessary producer/API repairs are identified below; unrelated implementation stays with its existing owner task.

## Output and manifest contracts

- Package implementation builds use package-local roots. Test compilation is separate where required; tests may consume the owning package's source but cannot compile sibling implementations. Preserve module format/target until a compatibility reason justifies changing it.
- Files, services and work currently have no package-root barrels/build output. B03 adds their consumed runtime/testing/distribution entry points, compilable package-local output and matching manifests before dependent imports switch. Inspect their current `.ts` import suffixes and `noEmit` configs when selecting an emitting build; preserve current source/test behavior and verify the emitted module graph. B05 finishes remaining layout cleanup rather than postponing these prerequisites.
- Remove stale sibling include/path shortcuts. Current values/state and other producer includes refer to a nonexistent root `contracts/src`; actual sibling compilation comes through imports and broad roots. Verify actual compiler programs, not only edited config strings.
- Choose final emitted paths once per producer and update exports/main/types/files, fixture copies, test globs, scripts, Worker vendor readers, generated maps and release inventory together. Keep old layouts until their real consumers are migrated; a blanket dist-path rename is not the first task.
- Runtime relationships, including public emitted declaration dependencies, belong in an appropriate consuming manifest category. Test-only runners/fixtures are development relationships; injected host implementations are not silently made unconditional producer dependencies. Use `workspace:*` for actual internal package links.
- Preserve root-owned integration tooling and explicit package tooling ownership. Central version defaults can reduce repetition, but must not make undeclared tool usage accidental. Keep existing supported Node profiles visible; deciding a unified Node minimum requires compatibility evidence.
- Regenerate the lock once shared manifest changes are collected; serialize that write. Pin Bun 1.4.2 unless the bounded probe establishes a necessary compatibility change. Select and document explicit isolated-linker behavior; prove missing declarations fail with negative fixtures rather than assuming isolation alone provides complete enforcement.
- Pack supported consumer packages, install them into a temporary directory outside the repository, and exercise exported runtime/testing APIs and emitted declarations with no sibling tree available. Use the current package manager's pack/publish semantics to check `workspace:*` version rewriting. Keep public publishing separate from this reversible local packaging proof.

## Task graph and cache correctness

Implemented in `turbo.json`, `scripts/run-tasks.mjs` and the owning manifests. Only the 13 ordinary TS producer builds are cached. Each depends on its declared producer builds and an uncached `build:prepare` that removes obsolete emissions and incremental state before either compilation or cache extraction. This prerequisite fixes a reproduced Turbo rollback defect: restoring A after B otherwise leaves B-only files. Values catalog output and the three packaged preparation-native filenames remain separately owned and excluded from TS cache archives; compiled TS preparation code is included. Tests, typechecks, catalog/native generation and release validation run uncached. Public aggregate tests preserve sequential suite execution; ordinary builds permit four tasks concurrently.

The [cache report](turbo-scheduling/README.md) limits source-selectivity claims to observed fixtures: a testkit API edit/deletion gives one miss and 12 unrelated hits, while adding its module or editing browser CSS/committed WASM changes Turbo's root internal-dependency identity and invalidates all builds. Keep the root's real dependency declarations intact. Remote caching and new native cache policies require their own proofs.

Use **Turbo 2.11.7** and its saved version-specific schema as the verified initial pin, rather than `latest`. The executed B01 probe found no native identities in Can's current layout; use deliberate command adapters for the separate native owners and keep automatic Cargo discovery off. The named root-workspace control proves the feature works in its supported shape, but `ports:C04.graph` explicitly excludes introducing a compiler Cargo workspace, and the private values workspace stays intact. Future native discovery can replace adapters only after a topology-preserving proof. Avoid registering the same native build through both discovery and an adapter.

| TS build/typecheck/unit | Build producers before consumers and test consumers. Declare outputs, shared config and generated inputs. Restore JS, declarations, maps, browser bundles/assets, required fixtures, generated Wasm/glue and executable modes. Treat `.tsbuildinfo` consistently with outputs: restore the complete paired build state or remove it before rebuilding; restoring incremental metadata without emitted files must not skip emission. Include relevant lockfiles, shared configs, builder scripts, backend/target/features, toolchain versions, host architecture and declared environment in cache identities. Start with local caching; remote cache setup is separate future work.

For each cacheable task family, prove: a cold run; a warm hit; deleting owned outputs and restoring them; an upstream-source change; a relevant lock/toolchain/target/environment change; and a failing producer. Inspect the declared dependency chain rather than expecting every root task to miss. Validate compiler commit identity and CLI executable mode specifically. Keep a task uncached if its complete inputs/output contract cannot yet be established; correct uncached orchestration is a valid intermediate result.
