# Finite executable/process boundary qualification

Actual native debug executable probes reproduced four panic-hook abort profiles: forced unwind with an anonymous closed stderr pipe; ordinary error output to an owned writable file under child-only `RLIMIT_FSIZE=0`; both output files under that limit; and forced unwind with that limited stderr file. The signal disposition ignores `SIGXFSZ` only inside the disposable child so its write reports an error rather than a signal terminating it. Baseline returns SIGABRT (-6); repaired executable returns 2 for all four. Ordinary stdout write failure with working stderr already returns 2/E7005 and remains so.

`compiler/src/main.rs` now attempts the existing one-line E7005 report using fallible `writeln!` and ignores its result. This prevents a reporting failure from panicking during an existing unwind. No CLI result policy changes. Aborts remain outside `catch_unwind`; a sink that cannot receive bytes cannot be promised an observable diagnostic. The hook still allocates while formatting and is not an allocation-failure containment mechanism.

Actual anonymous stdout pipes preserve 0 for help and 10 for a parse diagnostic after the read endpoint closes. Ordinary tool error output to a closed stderr pipe preserves 2. Owned read-only descriptors preserve the observed native 0/2 outcomes and unchanged fixture contents; they do not demonstrate the required other-write-error panic. The file-limit fixtures do. [Observation notes](observation-notes.json) retain this correction and the failed wait-error hypothesis.

Thin producer controls forward exit37 with exact `out`/`err`, map self-SIGTERM to2, inherit and forward exact 262144-byte stdout and stderr streams, and return2/E7004 for missing and unexecutable owned stubs. The direct child PID is absent after ordinary/signal/finite-output returns. Inherited `SIGCHLD=SIG_IGN` still forwards37 on this native profile and does not establish an actual wait error. `.status()` waits synchronously by source inspection; arbitrary wait failures remain unqualified. These are shell transport fixtures, not execution or correctness acceptance of the installed platform application. Existing renderer handoff/duplex evidence remains in [renderer-lifecycle](../renderer-lifecycle/README.md); it is not relabeled as new work here.

The initial locked/offline binary build, [baseline](baseline.json), [scoped baseline source pins](baseline-freeze.json), [current](current.json) and [current source/check freeze](current-freeze.json) retain exact binary hashes, relevant source hashes, commands and host information. The baseline has20 observations; current has21 including the extra ignored-SIGCHLD control. Three executable regression tests use closed Unix socket endpoints to reproduce deterministic EPIPE, separately from the retained actual anonymous pipe probes. All three and the existing11 executable tests pass. `rustfmt --check` passes for the two owned Rust files.

The15-second Python timeout supervises finite fixtures; it is not a selected product deadline. All completed without timeout. No output cap, universal timeout, reconnect, descendant-process ownership or signal-handler framework is introduced. Windows/other OS execution, release profile, forced real wait/read errors, arbitrary blocking/descendants holding inherited pipes, allocation exhaustion and abort containment remain unqualified. Those profiles are genuine qualification gaps; none is claimed fixed by this patch.

Decision text for integration: **Accepted bounded correction:** executable panic reporting is best effort and cannot replace an ordinary caught unwind's tool-failure exit with a second panic merely because stderr is unwritable. Preserve ordinary CLI BrokenPipe result codes and other-write E7005/2 behavior. Rationale: actual native closed-pipe and owned-file-limit failures demonstrated double-panic aborts; fallible reporting repairs the existing exit contract without selecting a new resource or lifecycle policy. Remaining uncertainty: other hosts, abort/allocation behavior and unforced wait/read failure profiles.
