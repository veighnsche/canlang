`probe.mjs` uses actual installed state buildContext, actual built internal Cloudflare createContext, actual public Cloudflare invokeCallable, actual production emitted module, and actual stdlib/values facades. No facade was mocked or changed. Receipts show:

- Actual generated appDefinition contains Dutch and German identities/uses but no deployment locale.
- `Shared.g` reached through public invokeCallable fails at actual installed format with the known descriptor/signature error and maps back to its source span. This is a direct pure callable join; it does not claim canonical scenario admission.

This demonstrates the needed information, not implemented generated adapter behavior.

## Smallest coherent owner closure

Recommended proposal: keep public format unchanged and introduce a trusted, normalized formatting scope on the Cloudflare **HandlerContext**, populated from existing source-derived selected-app metadata and the admitted team timezone. This avoids adding app display configuration to state receipt/admission identity when the formatter needs it only at the generated handler seam. The scope must be immutable per invocation, explicitly absent outside a qualified invocation, and fail loudly when localized formatting needs it; missing selected-app metadata is not permission to assume `en`, and missing team is the actual UTC case.

1. **Compiler owner:** build one checked merged locale value for each app from its own explicit context plus selected composed-app contexts; identical explicit settings coalesce, incompatible explicit settings diagnose, defaults apply only after the fold. Imported packages do not contribute deployment context. Consume this checked result in the existing generated appDefinition primary and composition records. Carry source language from each checked message owner. Files: analysis/effects.rs (and its owning table), the applicable type/composition checker for conflict diagnostics, codegen/ir.rs and codegen/js.rs. Selected-call types.rs changes remain the separately accepted lease.
2. **Cloudflare metadata owner:** replace filename/en reconstruction with a validated reader of `appDefinition` reached through existing `asm.entryUrl`. Resolve primary authored id and its checked default; if alternate composition selection is supported, select that authored composition entry explicitly and use the same resolved AppInfo everywhere. Do not create a second app-default registry or let operation inputs supply this value. Reuse existing `AppInfo` shape from the interfaces contract; selected app identity must also remain consistent with receipt identity. Files: worker/assembly.ts plus an owning reusable metadata reader only if needed by direct canonical entry points.
3. **Cloudflare handler context owner:** add a readonly formatting scope to runtime/context.ts/CreateContextDeps; `runScenarioSeam` derives locale from the selected app metadata and timezone from `call.context.team?.timezone`, using UTC only for a null team. `invokeWith`/nested derives need no new invocation convention. Direct canonical mutation entry must resolve/validate its supplied app id against the same generated metadata instead of accepting a second independently supplied locale. Files: runtime/context.ts and the currently active runtime/invoke.ts; these require package-chat release before any edit.
4. **Generated adapter owner:** mechanically normalize descriptor/param kinds from checked declarations to the existing values format interface, preserving exact carriers. Supply locale expression, trusted formatting scope app default/timezone and checked owning sourceLang explicitly. Return the existing provenance result intact. No new values/stdlib export is required if the compiler emits this checked bridge to existing two-argument `format`; if a reusable producer helper is chosen instead, its values implementation/catalog/interface and stdlib export assembly/tests are additional exact owners, not implied by a facade-only edit.
5. **Occurrence and presentation consumers:** verify all production constructors of a base HandlerContext used by `executeOccurrence` install the same qualified scope; existing spreading preserves it. PresentationContext already has appDefaultLocale, but viewer preferences must never choose outbound default. Its team/zone join must reuse admitted identity, not arbitrary principal JSON. No state InvocationContext change is necessary for the recommended handler-scope approach; state context construction already owns the trusted zone.
6. **Compatibility/admission:** generated formatting that requires the new trusted scope must fail clearly on old hosts; inspect the existing artifact producer-capability requirement and activation vocabulary rather than claiming matching stdlib format export proves the context protocol. Exact capability/version choice remains owner work; do not silently default missing protocol data. Relevant owners are codegen/artifact.rs and existing Cloudflare compatibility/activation tables only if this format release advertises the new generated protocol.

## Balanced carrier alternatives

- **Handler formatting scope (recommended proposal):** exposes only explicit formatter inputs; minimal state impact; works through existing nested derive `c` propagation. Requires Cloudflare canonical/occurrence/base-context joins and missing-scope failure qualification. It does not repair unrelated canonical actor/now/team emitter gaps.
- **Add appDefaultLocale to canonical InvocationContext and forward canonical context into handler scope:** one broader admitted context carrier, useful if several runtime consumers need the same immutable setting. Requires contracts/state constructor/all direct context fixtures plus the same Cloudflare forwarding; more shared contract churn, and canonical context still cannot substitute for the handler's storage/query scope. It must not overwrite established caller/store/canonical effects behavior.
- **Bind selected app configuration into generated callable factory/closure:** can avoid a context field and reuse one checked appDefinition. Requires changing current zero-argument `canApp()` convention and every module loader/dispatcher/testkit consumer, with shared package callable selection proving different apps bind different defaults. Current `invokeWith` calls canApp() with no arguments and composition selection is absent, so this is not a smaller one-file compiler repair.

These are implementation boundary alternatives over the same semantics; existing JEV advice prefers a generated adapter to public facade extension but does not pick this context carrier. No need to transmit another consequential choice before root determines whether this broader owner join is being released.
