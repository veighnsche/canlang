## Verified seam contracts

Contracts `presentation.ts:69-90` defines `MessageParamValue.value: unknown`, a canonical type id, and the UI-owned `MessageFactory`. It does **not** require every value to be a wire string or every value to be native. UI `message` copies/preserves typed pairs without scalar admission. Current `toOperand` (`messages.ts:233-298`) admits civil/instant strings and Decimal bigint/string; it refuses native tagged Date/Datetime/Decimal. `formatMessage` converts every bound parameter in key order before parsing/rendering; `formatScalar` uses the same boundary. `resolveCaption` currently owns UTC fallback. These are implemented contracts, including exact failure timing, not a desired native-only model.

Compiler `lower_message` passes existing expression values unchanged into the UI factory. Native constructors and exact Decimal lowering therefore reach it as native. Query model fields use the same emitted message form but obtain strings from actual State projection. State `query/engine.ts::projectRow` copies authorized stored values into `ProjectedRecord.data`; it does not attach field type associations or decode temporal/Decimal strings. This successful current wire path cannot be discarded to make constructor tests pass.

The public Values guards/codecs already provide checked native→wire mapping. Independently executed native date0001/date0099, canonical offset datetime, and 38-digit Decimal controls encode to exact UI-supported strings and then render correctly; wire strings supplied as native codec inputs refuse `ValueError/invalid-construction`. `stdlib.encodeValue/decodeValue/isDateValue/isDatetime/isDecimal` are identical functions to Values exports. `isDateValue` and `isDecimal` validate their relevant bounds. `isDatetime` checks tag/bigint shape only; **encodeValue additionally owns 0001–9999 range validation**, demonstrated by a structurally tagged out-of-range instant. A future native intake must use the actual codec validation as well as guards, rather than treating `isDatetime` alone as full temporal admission.

Current dependency graph from manifests: UI→Contracts (+csv-parse), Values→Contracts, stdlib→Values/State. Thus UI→Values is a new direct dependency; UI→stdlib would import an assembly rather than the defining producer. No current cycle follows from UI→Values, but absence of a cycle does not by itself adopt the edge. Values' own native formatter is not a drop-in replacement: its descriptor requires `kind:'message'` and its native operand/error/profile preconditions differ. `DESIGN.md:1120` describes the desired generated typed-message target; the surrounding proposed-output context and explicit unimplemented statement at 1064–1066 prevent treating that example as an already implemented public Values/UI API.
