# BDD checked-expression consumer closure — read-only proposal

Status: proposed; publication and consumer source remain frozen. No implementation or test source was changed in this round. Independent exact-source failures are preserved under `bdd-facts/independent-review`; the previous accepted-source fork and final manifest remain intact.

## Verified defects

- `decode_bare_name` returns free `result` and ordinary parameter identifiers. `decode_table` rewrites only common fixture aliases; `bdd::lower_table/lower_step` define only c/s(/b). Original `result` alone already fails, and newly checked `lower(result)` exposes the same gap through a real selected builtin.
- Test suite emission creates an Emitter and lowers callbacks but never emits derive functions. Checked imported/local targets therefore call canonical function names with no definition. This is required legal source behavior, not an unsupported-language carveout.
- Actual testkit success is `{ok:true}`, table observe receives neither outcome nor payload, and sequence as captures the entire envelope. Current canonical e2e adapters discard successful payloads too. A compiler-only identifier rename cannot repair this join.
- Sequence `scopeArg` is formed once before the loop; the existing table live read hook is not joined per sequence statement. Fresh fixture/input inspection requires an actual owner read port, not cached recipe substitution.
- Existing bdd_binding_runtime controls assert envelope-as-payload identity and fake successful declared Result with `{ok:true}`. Those controls contradict declared business result ownership and need scoped correction alongside real result transport.

## Proposed finite closure

1. Publish enough checked lexical identity to route BDD names by NodeKey, distinguishing Param/Context::Result from same-spelled fixtures, sequence lets and query aliases. The current generic bound_names set is insufficient. A minimal TypeTable value-binding map (or equivalent restricted binding enum) can retain resolver-owned identity without introducing another checker. Keep the original header fixture namespace and diagnostic-family contract.
2. Pick one callback transport through consultation. Local preference is distinct readonly `c.inputs`/`c.result` inspection slots, preserving documented callback arities, source frame separation and existing s/b roles. Alternatives are an explicit additional immutable observation-frame argument, or segregated namespaces under existing s. Any choice must preserve source collision semantics and genuine bounded inspection authority. Do not infer a result from s, fixtures, inputs or a success envelope.
3. Extend the owning invocation success envelope to transport the actual typed declared payload without serialization/coercion, distinguish explicit null from absent/void, and require it when an as/result use is declared. Table loader records the actual latest success; observation callbacks receive refreshed inputs and payload. Sequences advance current inputs/result after successful calls, reset current result on rejection or void, and store only business payload in as while earlier captures survive. Retain error/request behavior and rollback checks; close the actual canonical mappers which currently discard payloads.
4. Join existing live fixture inspection to every sequence statement and provide an explicit owning input-refresh projection for record inputs. Fixture-bound logical action inputs must track row replacement and current action-input identity; direct fixture references remain independent fixture slots. Scalar/struct source values may use their real captured invocation inputs; current stored records must come from genuine canonical live read ports. Do not relabel an invocation-port test as state-engine qualification.
5. Assemble only the checked callable closure required by a suite. Local preference is an emitter worklist: lowering a checked canonical DeriveFn call records its target; the same existing production body/default emitter emits the target and discovers transitive private/default-helper dependencies until closure. Helper declarations sit at test-module scope, without production app initialization, handlers or registries. Imported aliases retain owning canonical IDs. Nested message defaults/calls contribute references via their existing lowerer. Source argument capture, default order, lazy branches, effects/await and omitted/null semantics stay with the existing selected-call and function emitters. Alternatives are isolated generated shared callable modules, or actual production owner exports/imports with full initialization/dependency qualification. Current package identity modules do not emit derive implementations, so adding a test import line alone is insufficient.
