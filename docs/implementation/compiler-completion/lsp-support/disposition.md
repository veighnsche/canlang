# LSP support disposition — proposed for independent root review

Both original references can close as **RETAIN existing support, zero net production deletion and zero retirement credit**, if the owning review accepts retention as the final disposition. This proposal selects no new public support, output-layout, or position-carrier policy. No production, package, existing documentation, or Git state was changed. This is an evidence-backed disposition recommendation, not an accepted project decision.

## integration:legacy-lsp-render-builders

**Proposed close: RETAIN.** Existing typed payload emission already serializes DTOs directly. Only admitted typed-response IDs pass through `render` → `RawValue::from_string`; that narrow revalidation is not a payload reparsing engine. Keeping public legacy builders supports more than those admitted typed routes: they never run `parse_call` or ID admission and never validate hand-built `Json::Num`. They preserve payload object order/multiplicity and raw number strings, including invalid JSON supplied by an external caller. Success accepts arbitrary Json IDs; error accepts an arbitrary optional Json ID, with missing ID emitted as null. Exact envelope field order, compact spacing, control escaping, Unicode bytes, i64 error-code spelling and null/error placement remain observable.

Deleting builders because only two are internally live removes three public entrypoints. Replacing their payload or ID with general `serde_json::Value` loses duplicate members or raw spellings; replacing with RawValue validation rejects unchecked hand-built values and can introduce a panic/error where the present API always returns String. Those are policy changes even where malformed hand-built output is not protocol-valid. Wrappers retaining the full old Json render behavior provide no demonstrated deletion of that mechanism. A private common-prefix helper can preserve the contract, but adding a helper while removing only the shared `jsonrpc` member at three sites has no demonstrated positive net reduction; it needs a counted exact candidate, complete replacement closure, and identical finite acceptance. No such candidate has been selected or submitted for mutation. Retention therefore closes the support obligation without claiming the legacy route is intrinsically irreducible or prohibiting later qualified consolidation.

## integration:lsp-duplicate-position-carriers

**Proposed close: RETAIN.** Protocol DTOs already own output range fields. Backend callbacks own the existing TextPos/LspRange domain interface; source owns byte spans, LineIndex and source-ID database identity. RealAnalysis converts request positions with `ide::queries::offset_at_position` and output spans with `LineIndex::to_lsp(..., true)`/`span_to_range`; the private range adapter projects values to library protocol DTOs without taking over source conversion. Source conversion counts supplementary scalars as two UTF16 units, clamps byte offsets inside scalars, handles CRLF, and clamps beyond text. Position-to-byte conversion returns None for nonexistent lines, clamps excess columns to line end and surrogate-interior positions to scalar start. Do not silently replace these policies with different validation or encoding.

A direct substitution or public alias to lsp-types::Position/Range may preserve current field widths and construction for some callers and remove adapter code. It also changes public type ownership/identity and couples the backend interface to the library API; lsp-types carries additional traits and semantics. Removing public names breaks callbacks/field consumers; conversion wrappers or retained nominal types erase or reduce nominal retirement credit. Neither aliasing nor a migration has an owner-selected support policy. The existing six-line adapter is the explicit source-domain/protocol projection, not evidence that source UTF16 behavior should move into library types.

Authored URI text is equally binding: the document map uses the exact String identity; definition/reference callbacks receive the requesting authored URI; diagnostics/location/edit DTO envelopes keep String URIs and first-occurrence URI grouping. `uri_to_path` only projects native display metadata through URL admission; it does not canonicalize document-map keys, read files, or collapse `%2f`/`%2F`, opaque/nonfile/malformed authored spellings. Library URI normalization is not an acceptable substitute at the same contract.

## Evidence and limits

The selected dependency manifest, lockfile, all four LSP modules, private output/URI owners, JSON/diagnostic/source/IDE query owners, and selected tests match the frozen 118-input manifest. `inventory.json` pins current and frozen SHA256s, the suite/clippy logs, manifest and receipt. Only matching compiler source/dependency scope and recorded historical bodies are reused here; editor fixtures outside the 118-input compiler manifest are not frozen by it, so no complete output-fixture equivalence or current JS writer qualification is claimed.

`selected-bodies.log` contains 40 matching named bodies recorded as executed/passed: LSP unit output/admission/framing/helpers/URI bodies, source LF/CRLF and UTF16 bodies, admitted numeric and Unicode IDs, real all-output UTF16/CRLF, opaque URI output/routing, current-version edits, reference/edit capability profiles, clean rename recheck, and public queued work. The full log separately records lsp_admission 32/32, lsp_frame_reader 11/11, lsp_typed_output 8/8. Existing rpc-builder shape tests alone are weak byte/public helper qualification.

The gap is narrowed by a cheap direct control: `direct-controls.rs` compiles the exact current JSON, diagnostic, source and transport module files with local dependency rlibs, without linking an old compiler/server binary or rerunning a suite. `direct-controls-receipt.json` pins those rlibs and exact command; build/run both exited 0. Literal expected outputs check ordered duplicate result members, exponent/negative-zero raw spellings, unchecked malformed hand-built numeric payload and unadmitted boolean/array helper IDs, absent error ID, i64 minimum code, Unicode and backspace/formfeed/newline/backslash/quote bytes, source UTF16/scalar/CRLF/end clamps, and UTF8 framing byte length. These tests deliberately distinguish public builder behavior from protocol admission. They are finite controls, not arbitrary external-consumer equivalence or exhaustive hand-built-tree validation.

Future changes must reopen the relevant support boundary: removal/signature/type-alias policy needs the public API owner; byte/layout/unchecked Json changes need explicit support selection and same-output qualification; library updates need exact dependency requalification; URI changes need authored-key identity checks; carrier changes need callback/source ownership, source UTF16/CRLF and all output/edit routes. Retention is sufficient to close these two audit references with zero credit after independent root review; it does not close those future policy questions by inventing a migration.
