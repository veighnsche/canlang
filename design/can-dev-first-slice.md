# First supported `can dev` slice

**Status:** selected target and acceptance contract, not implemented or qualified. The [session/control contract](can-dev-session-control.md), [compact error contract](can-dev-error-contract.md), [Jev ranking trial](can-dev-jev-ranking.md), [construct-help reference](../docs/specification/CONSTRUCT-HELP.md) and [unfamiliar-agent tasks](can-dev-agent-tasks.md) supply the component boundaries. The dependency-ordered [implementation tasks](../implementation/can-dev-server/PLAN.md) follow this selection. Three [Jev comparisons](jev/can-dev-first-slice-20261009/assessment.md) advised the scope; observed app behavior remains the release authority.

## Selection and reason

The first agent-facing supported slice is **Task 1: Office supplies**, confined to one self-contained `.can` app and one local D1/identity profile. It is the smallest proposed business request that requires the complete agent loop: an unfamiliar agent drafts source from the tiny Given/When/Then card, checks and repairs it through construct help, serves the compiled app, uses real member authority, runs independently authored success/denial examples, and inspects a bounded failure. A source that only passes `can check`, or an anonymous page with no mutation, does not complete this task.

The prior [Generation probe](evaluation/can-dev-generation-local-20261009/README.md) is an **engineering gate**, not the supported product slice. Its existing source is useful for closing shared bundle, auth, fixture and row-runner joins: a member must load the page, queue a job, and all three authored rows must execute in isolated scopes for Generation to pass its own probe. It lacks the create form, search and view/count workflow needed by Office supplies. A remaining defect specific to its state-machine feature is recorded separately and does not by itself block Office supplies; a shared auth, bundle, fixture or row-isolation failure does. Do not silently weaken Office supplies or call Generation complete. The office-supplies acceptance app is evaluator-owned and kept out of the novice agent's starting workspace.

## Declared profile

| Included in the first slice | Explicitly outside it |
| --- | --- |
| One `.can` app source with no composition/imported app members; source-owned model, read policy, operations, page, fixture and examples. | Multi-file/composed apps, package imports, external providers, files, schedules, durable deliveries and deployment. Refuse an unsupported required capability before claiming a complete check or working preview. |
| One team-scoped D1 record model: required name, optional quantity, default available state; member CRUD and member-controlled availability changes. | Role-heavy scheduling, money/reviewer workflow, provider effects and Task 2/3 completion. |
| Local Identity users/teams/members, ordinary app sessions and authorized business `/mcp`; seeded development users use the real Identity store. | Fabricated auth cookies, bypassed business admission, live external mail or cloud credentials. |
| Source-generated page with create/edit/remove controls, list, search by name, all/available/restock views, a **count of that current filtered view**, and an empty state. | Handwritten replacement page/Worker. If the current language cannot express a view-matched count or another requested behavior, add the owning Can capability rather than changing the task. |
| Compiled inline examples for successful edit and outsider denial, isolated D1/actor scopes, and a revision-pinned new-run action. | Exact execution replay, generic browser/HTTP replay and unsnapshotted resource side-effect proofs. |
| Owner-only local Unix control session through bounded JSON CLI; protected loopback preview; deterministic help and bounded optional Jev ranking. | Development MCP as the first adapter, Windows IPC, whole-graph inspect/diff, general runtime trace stream and automatic code editing. |

The default local resource policy must report every binding as real local, simulated or unavailable. This profile requires D1 and Identity; no service provider simulation is needed. Browser resources come from the released package bundle. A local development admission check replaces the feasibility probe's hardcoded `active:true` override; it must validate the selected profile and refuse missing required bindings. The selected app source, toolchain, catalog, help index, runtime package outputs and resource profile are identified by their actual consumed versions/digests. Existing dirty debug/dist outputs are inventory, not source-current release proof.

## Acceptance criteria: one complete supported app

**A1 — App behavior and authority.** An evaluator-owned, source-generated Office supplies app passes independent checks for required name, optional quantity, available default, create/edit/delete and both availability changes. A second member of the same team sees and can act on the item; an outsider and a member of another team cannot read or mutate it. Denied mutations leave domain records and effect intents unchanged; an engine-owned rejection receipt is reported according to its existing contract, never mistaken for a business effect. The page's search, all/available/restock views, count of the **visible current view**, and useful empty state all reflect the same authorized rows. The browser form and business `/mcp` reach the same canonical operation/permission path. No implementation-only fixture or UI supplies missing business behavior.

**A2 — Local runtime and resources.** A source-current compiler artifact and installed package outputs, not a handwritten Worker, serve that app over an ephemeral loopback listener in headless Chrome. Real Identity sign-in and team selection produce an ordinary session; the create/edit/status/remove journey survives page reloads. The shared bootstrap, stylesheet and polling resource responses match packaged bytes. D1 is real local storage for the preview; a missing required binding fails explicitly. Preview access protection is distinct from app login, and unauthenticated/outsider business requests retain ordinary refusal. The generated auth route must no longer return `assembly-interim` for this profile.

**A3 — Examples.** The two required authored examples and any additional rows emitted by this app run through the compiled canonical invoker, with actual member and outsider callers and fresh D1 scope per row. The report's executed count equals the selected authored row count and is greater than zero; every required row passes. Setup failure, `unsupported`, missing observation and a zero-row harness never count as a pass. The denial row proves no domain change or effect intent in every resource admitted by this profile, while preserving the engine's rejection-receipt semantics. A second execution starts from fresh data and cannot inherit preview or prior-row mutations. The same app artifact and source revision appear in its example report.

**A4 — Session and revision integrity.** One owner-only session attaches only to its canonical checkout, selected app and profile. Separate worktrees have separate control endpoints, ports, workers and D1 state. A symlink escape, duplicate owner and stale descriptor cannot attach to the wrong session. The compiler's consumed source hashes/membership match the immutable single-file capture; edits to source or compiler/catalog/help inputs advance the session revision. An in-flight old check or Jev answer never becomes current. An invalid edit leaves the last healthy preview visibly marked with its **old serving build**; a repaired build starts with fresh preview data and reports that reset. Historical details return captured data or `revision_unavailable`, never current-file contents. Stop/crash recovery releases only that session's resources.

**A5 — Agent help and Jev safety.** The selected profile's supported constructs have one versioned authoritative help entry with signature, meaning, minimal example, availability and stable link. Deterministic context help handles exact matches; structural first errors and incomplete candidate inventories do not trigger Jev. At least one live, reliable ambiguous occurrence exercises Jev's bounded Choice path with `none` and `unclear`; a permission/effect ambiguity, unsupported behavior and the fixed no-suggestion cases do not receive a misleading top card. Provider disallow, timeout, invalid response and stale rank preserve compiler diagnostics and local preview. The default check stays compact (one focus, counts and revision-bound references), and disclosure follows the [ranking policy](can-dev-jev-ranking.md). Jev never edits source or authorizes a business operation.

**A6 — Failure and rerun evidence.** Compiler, example setup, business refusal and assertion failure paths each return a revision-bound occurrence from their owning evidence, with exact byte span only for compiler facts and an optional mapped point only when available. Missing trace, mapping or side-effect coverage is explicit. Detail output is bounded and respects the effective actor's access. A retained failed example can run again against its retained artifact in a new scope and receives a new run ID; an evicted artifact refuses. The result says `replay.available=false`, and an idempotency receipt's saved outcome is never called execution replay.

**A7 — Unfamiliar-agent result and measurement.** Freeze the [Task 1 prompt and observable checks](can-dev-agent-tasks.md#task-1--office-supplies), tiny introduction, clean starting project, toolchain/profile, agent model/settings and time budget before trials. Run at least three independent fresh agent attempts using only that introduction and the supported control surface; at least two must complete **all** A1 behavior checks with no unauthorized behavior in any run before claiming this profile helps that measured agent setup build a working app. Record incomplete attempts and unavailable capabilities rather than reducing the denominator. Use at least three fresh attempts per condition for a paired, counterbalanced deterministic-help versus Jev-ranked comparison with the **same** candidate IDs/cards and no conversation carryover. Publish completion, wrong displayed suggestions and abstentions (with denominators), edit/check turns, agent plus Jev tokens, elapsed time, provider cost and failure rate. An automatic Jev advantage or token-saving claim requires an observed non-regression in completion and wrong-intent suggestions plus an improvement in turns or total tokens; otherwise retain Jev as a requestable advisory tool and deterministic help as the default. The existing six extracted probes are offline corpus checks, not live automatic eligibility evidence.

All A1–A6 are hard functional/safety gates. A7 is the agent-facing support gate and comparison report; it must not be replaced with a source-validity count. These thresholds apply only to the declared one-file local profile and tested agent setup, not to arbitrary agents, all Can constructs or deployed apps. A source/runtime capability still under development is reported as such instead of being accepted through a draft signature or generated desired output.
