# Independent proposal review

Two existing Sol reviewers examined the core/domain candidates and the UI/package candidates without changing source. A third Sol high reviewer challenged the uncertain choices with a focused read-only brief. The reviewers inherited different context; these are independent source analyses, not independent experimental observations or calibrated estimates.

## Findings retained in the roadmap

The core review recommends enum-only exhaustiveness as a bounded candidate, ordinary approval/accounting composition, and completion of accepted effect/receipt/provider joins before broad orchestration grammar. The UI review recommends a typed authorized-read binding for dependent choices, explicit business draft models for wizards, a real duplicated fragment before named views, and measured polling cost before push. Both defer unrestricted package generics and richer statecharts.

The challenge review identifies a risk in making “finish existing seams” an unlimited barrier. The final plan instead releases narrow prerequisites and compares a complete application trial on both sides. An extension can prepare independently and proceed when its actual seam and value gate pass, without waiting for unrelated programme parents.

## Source grounded challenges

**Exhaustive handling.** Committed `compiler/src/analysis/types.rs` checks that syntactic return branches complete and already performs substantial union narrowing. Neither establishes intentional coverage of every evolving outcome. The closed `applied | conflict | missing | rejected` result in `design/complex-apps/sync.md:25` is a concrete candidate for mandatory review when a new case is added. Conversely, the archived booking handler's intentional unknown fallback is not a bug. Preserve ordinary fallback conditionals and compare a checked finite `match` against stronger conditional coverage analysis on three handlers.

**Dependent forms.** CanApprove has candidate forms with different bound mutations. The archived CanRent availability result followed by a bound hold form is a complete existing alternative. The current ignored draft retains that workflow at lines 1584–1592; it does not demonstrate automatic shared draft inputs or one-form lookup updates. Measure source, navigation/submissions, stale-selection failures and unsaved values on the same task. The accepted lookup remains authorized pure reading; final availability must still be checked by the canonical mutation.

**Accounting ownership.** Package imports and storage ownership are different concepts. A package cannot directly mutate another package's records or create a cross-owner atomic decision. Demonstrate actual co-owned composition or an explicit staged protocol before proposing a shared mutation API. The current ignored loyalty draft derives balance from earnings and reserved/fulfilled redemptions at line 32 and includes a valid reversal yielding negative availability at line 207. A universal nonnegative balance invariant would change that workflow. Generation admission policy must remain distinct from generalized ledger truth.

**Push.** Polling has concrete context/sequence/draft preservation logic and DOM-level tests. That is a real baseline. Compare completion-to-paint p50/p95, idle requests, bytes, query/server work and connection cost at several cadences on the same workload. Revocation, reconnect and out-of-order signals must pass on both paths. Push is worthwhile only for a stated freshness/load target; source brevity alone is weak evidence.

**Durable composition.** Underlying state/work code stages history/outbox/schedules and has durable dispatch/recovery tests. It does not establish a compiler-supported await API. Booking's attempts contain meaningful source/revision/allocation/cancellation evidence; shortening source by deleting it would be an unfair comparison. Require equal inspectable history, late-result policy and unknown outcomes in both compositions.
