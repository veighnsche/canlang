## Consolidated findings and same-criteria improvements

### C-I01 — Significant target drift: amount units and checked money operations

**Evidence/cause:** [T](evidence/interfaces/target-correspondence.md) cites CanRent.can:200,722,738,748; target :3310,:5605–5611,:5722–5728,:5753–5759,:5794–5796. Minor-unit accumulators are passed into `money(value,currency)`, whose canonical argument is currency units (D:220,250); raw `+/-`/comparison also bypasses canonical checked-money lowering (D:208,846). Expense target :695 uses the same helper for EUR25 units, so variable naming cannot resolve the meaning. This is a handwritten desired-target defect, not proof of an executed 100× error or observed overflow.

**Company impact/remedy:** W quote/booking/invoice evidence depends on exact amounts. Correct that target pattern with canonical typed sum/add/subtract/compare and audit the same construct in all 21 targets; no Can primitive or broad app rewrite needed. A separately declared internal minor constructor would need unambiguous typed meaning rather than silently overloading `money`.

**Benefit/tradeoff/reevaluation:** one source/target scalar meaning and checked currency/rounding/overflow; slightly more helper target text/calls, with later shared optimization possible. Reevaluate EUR25, zero, currency mismatch, quantity half-even rounding, intermediate/aggregate overflow and refund bounds statically against the same Can expressions; later executable properties/BDD stay unverified. B received this finding for E102; count it once across E091/E092/E095.
