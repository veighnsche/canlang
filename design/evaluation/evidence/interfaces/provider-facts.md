## Responsibility and installation assumptions

DESIGN:493–551 separates managed data transports from typed adapter contracts. `@canlang/stdlib` must add Can-specific admission, projection, exact arithmetic, revision fences, receipts/outbox, retention and finalized-file rules. Providers already supply transport/storage, not those business guarantees. `@canlang/ui` adds shared server rendering, HTMX control behavior, accessibility, settings and localization. Compiler static analysis should derive dependency closure, registry/schema metadata, queries/indexes, diagnostics and deployment requirements once. These are proposed responsibilities; absent implementations are the declared stage and not defects.

The useful first installation contract is a generated, reviewable plan listing selected app, canonical owners, version pins, actual bindings, provider identities/secrets needed, sender-domain configuration, quotas/retention and backup/recovery obligations. Endpoint, credential and vendor-specific wire mapping belong in deployment/adapter configuration; company business routing/consent remains in source. The plan should count shared services once and explain conditional defaults. This clarifies the existing output contract (DESIGN:743–749), without an authored manifest or portable-provider abstraction.

Provider facts bound feasibility/cost estimates, not support rates, security certification, service continuity or staff usability. A owns the 24-month total cost model including retained subscriptions and migration. B owns owner-replay/retention/business correctness. Later representative work should measure request/CPU/rows/storage/active-duration and recovery under the same P/W journeys.

## Recovery is a whole composed-app obligation

Retrieved 2026-10-04. [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/) is always on for production databases, has no extra history/restore charge, and retains 30 days on Paid or 7 on Free. Restore overwrites the database in place. Longer retention can use exported state; [Wrangler D1](https://developers.cloudflare.com/workers/wrangler/commands/d1/) provides export/migration commands. This recovers D1 only. [R2 durability](https://developers.cloudflare.com/r2/reference/durability/) protects against hardware loss but expressly does not prevent accidental/intentional deletion. R2 object [lifecycle deletion](https://developers.cloudflare.com/r2/buckets/object-lifecycles/) and Can receipt/attachment cleanup therefore need coordinated retained-copy and restore policy; immutable Can file references do not make an object undeletable.

[Worker versions](https://developers.cloudflare.com/workers/versions-and-deployments/) preserve bundled code/assets/bindings/compatibility settings, not D1/R2/DO/KV data. [Rollback](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/) leaves resource state intact and is constrained by unavailable resources/DO lifecycle changes. [Gradual deployments](https://developers.cloudflare.com/workers/versions-and-deployments/gradual-deployments/) can create version skew within a Worker and across service-bound Workers. A safe plan must assess old/new data/work contract compatibility; provider code rollback is not a composed business rollback.

Smallest clarification: the existing generated installation/maintenance plan should state who owns backups and restores; an acceptable recovery point/time; source/library/adapter/schema/resource versions; D1 bookmarks/exports; retained immutable file inventory and credentials/configuration; and how dispatch is paused then reconciled with external payments/mail after recovery. A restored old receipt must not resend a payment or assert money was undone. This adds an operating responsibility/runbook and costs, not a new business syntax or staff admin page. Re-evaluate P's receipts/Expense and W's accepted quote, booking, invoice and mail item together under one lost-database/lost-file/configuration-change scenario; later execution must demonstrate reconciled recovery. Current missing implementation is not a defect; incomplete disclosure of this required ownership workflow is the reviewable design clarification.
