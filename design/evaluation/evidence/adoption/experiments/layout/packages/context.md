Authored `nav`/`link` trees are removed rather than retaining a second navigation mechanism. Rendered URLs use typed record IDs and escaped values.

A collection child binds `row` and retains its enclosing record chain. An explicit query alias such as `list Invoice as invoice` also remains visible to descendants, so nested forms can name an enclosing record despite row shadowing. A nested direct-child collection automatically scopes to the enclosing parent; unrelated relationships require a `where` query. Bare UI field selectors resolve to that row's schema. A form auto-binds a record parameter only when exactly one compatible record exists in the enclosing chain. Otherwise `arguments={parameter=expr}` is required. Other inputs become controls. Record/member/user pickers use bounded authorized lookup results with safe labels. A user parameter never grants a global account/email directory; without a directory grant it accepts an opaque reference without disclosing account details. `fields` can omit only bound, defaulted, or optional inputs. Server-owned fields never become editable.

The same `form` also accepts a typed action expression: `form row.action`. It renders the selected canonical owner inputs with its protected record bindings hidden/read-only. A null, expired or invalidated reference renders no submit control and shows its safe availability state. The finite action type supplies all possible schemas at compilation, including multi-input inspection controls; opaque JSON editing is never the fallback. Referenced user operations enter the selected UI/MCP registry under their existing identities. A local submission uses the owning atomic operation; a bound submission creates a remote delivery and displays correlated pending, validation/conflict, failed, unknown or fulfilled feedback. Preserve editable values for correctable failures. A refreshed page rereads its declared regions; it does not implicitly run a source mutation or work-list request. The app declares refresh/poll behavior if it needs a new remote projection; fulfillment alone cannot rewrite stored work as done.

Read-form children render its typed `result`; siblings have no result scope. A page `data=` read operation supplies page-level `result`. Mutations re-run authorized page read regions. Preserve unrelated unsaved controls and focus. Validation keeps submitted values; a version conflict presents current authorized values without overwriting them. Expired authentication causes full navigation. Full page GET remains valid; HTMX handles fragments. Runtime must explicitly configure fragment swapping for validation/error statuses because [HTMX does not swap most error responses by default](https://htmx.org/docs/#response-handling).

Here `page` is the full-page declaration; an HTMX partial is a generated response containing its authorized render regions. A partial is not another page type. The current catalog has no `fragment`/`render` declarations or independently declared fragment routes. [JEV's fragment consultation](design/jev/README.md#named-fragments-versus-automatic-partial-responses) recommends retaining inline automatic regions for the current apps and considering typed named reuse when a concrete app demonstrates repeated UI content. That proposal has not added a second rendering form to v1.

`list`/`table display=split` gives the selected authorized row one adjacent detail pane; mobile uses a drawer with the same row bindings and current grants. Without a selected/readable row the pane is empty, not a guessed record. `details display=drawer` opens only the activated record, never every repeated row. `open=` applies only to Collapse details and cannot accompany drawer display. These groups retain row/parent aliases and do not create business operations.

`tabs preferences.view` binds only an owned enum preference, never a business field. As a leaf it renders case labels and supplies selection to one existing UI body/query. A bound block has `tab enum_case` suites, every case exactly once, without repeated captions. Unbound `tabs` requires nonempty `tab caption` suites and keeps transient selection per render site; captions accept text/messages. Tab content retains enclosing scope, renders/rechecks the active authorized panel, and preserves unsaved controls while inactive. Bound selection immediately uses the canonical preference save with version/value checks; failure is visible and restores the accepted selection. Keyboard/focus/panel association follows the tabs pattern. A settings dialog draft does not silently rewrite business input.

Collection `defaults={filter=preferences.field}` initializes only controls already declared in `filter`. Each scalar/enum/reference value must match that control type; arrays/member filters are not covered by this extension. Null means no initial restriction. Explicit URL and current control state wins; clearing a filter remains cleared for that view rather than reapplying its default. Defaults are presentation, never extra query permissions or a required mutation input. Changed grants are checked again on every request.


`context` immediately follows the app it configures, ignoring blank/comment lines. Its suite is nonempty and contains only the context declarations in the table. Composition apps have no package body; their single-use descriptions are inline, and imports after their optional context must resolve to local message-only groups for actual static-description reuse. App/package source overrides belong to their own logical owner, including their attached descriptions; composing/importing does not retag another owner. Source language and context default locale have different roles. The parser does not resolve that restriction or grant visibility from `uses`. An implicit app requires the whole ordered section triple and ends at the next top-level app, package or migration, or EOF. A migration cannot terminate an incomplete triple. A package has only one triple. Imports precede `Given`; neither imports nor arbitrary top-level expressions occur within the sections. An empty import group is syntactically invalid. An empty `uses` group is a semantic error rather than an inferred dependency selection. Provider paths and bound `from` paths are parsed uniformly; checking must establish the canonical owning package and the supported deployment-binding form. A path is not permission to introduce a nested package namespace.

`export` is optional on stored models, contracts, events, roles, derived functions, capabilities, fixtures, user scenarios and named messages. It prefixes the declaration at its existing indentation. It is unavailable on imports, apps, packages, contexts, preferences, derived fields, trusted scenarios, CRUD, policies/rules, presentation, migrations or effects. Exported declaration visibility and whether a scenario is a legitimate user operation are checked after parsing.

## Inline behavior examples

```ebnf
scenario_examples = "examples" example_bindings suite(example_table) ;
crud_examples     = {"examples" crud_action example_bindings suite(example_table)} ;
crud_action       = "create" | "update" | "delete" ;
example_bindings  = {NAME "=" expr} ;
example_table     = line(observations "->" observations) example_row {example_row} ;
observations      = separated(expr) ;
example_row       = line(separated(expr) "->" (separated(expr) | expected_error)) ;
expected_error    = call_expr with bare callee "error" and exactly one argument ;
```

The first child line is a header, and at least one row follows it. Both sides are nonempty. `->` at current delimiter depth divides header/row sides; commas divide columns only outside brackets/braces/calls. A sole `error(code)` on the expected side is recognized as a rejection expectation and replaces the whole expected row; it cannot be combined with expected observation cells. Other calls/expressions are parsed normally and validated in test scope. Neither a header nor a row admits semicolons or a child suite.
