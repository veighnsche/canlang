# Packages initial authoring attempt

Reviewable draft only. This attempt writes only `packages/after` and records its own retrieval/metadata/notes. It does not implement the language or edit live application sources. No JEV, delegation, independent review, or second attempt occurred. No layout superiority judgment is made.

## Changed declarations and business choices

Only `after/CanExpense.can` differs from before; Employees and Locations are byte-identical copies. The expense package remains intact in one file. App/package identities and imports are unchanged.

- Expense gains `finance_pending` between first review and final approval.
- `needs_finance` is a pure function using currency equality followed by strictly greater than `money(500,"EUR")`. Short circuit avoids cross-currency money comparison. EUR 500 is exempt; non-EUR behavior is preserved.
- `decide` still records the frozen Decision first. A positive qualifying decision now sets finance_pending; its existing rejection branch and examples are preserved.
- New immutable child `FinanceDecision` snapshots submission, amount, receipt, first reviewer, finance actor, approval, reason and timestamp. Its read policy matches Decision's private claimant/assigned-reviewer/finance boundary.
- `finance_decide` is canonical `expense.finance_decide`, by finance, requiring current location work eligibility, the pending state, qualifying EUR amount, actor distinct from both claimant and assigned reviewer, nonblank rejection reason, and an affirmative first Decision matching submission/amount/receipt/reviewer. Approval sets approved; rejection sets rejected. Neither branch changes frozen claim evidence or either history. The latest summary decision fields are updated; the original first Decision remains separately stored.
- Existing `correct` already accepts rejected claims, creates a separate draft with original evidence/reference, and prohibits duplicate correction drafts. Finance rejection feeds that same path. Finance evidence stays under the original claim and is not copied as approval into its replacement; resubmission and both decisions must happen again.
- `reimburse` retains all original payment-evidence, date, uniqueness and currency rules. Qualifying claims additionally need an affirmative FinanceDecision for the same submission/evidence and distinct actor identities. Merely setting approved in setup cannot bypass that gate.
- Review page exposes the same canonical finance action beside decide/reimburse. Claimant and review pages show FinanceDecision history under its private policy. Frozen DESIGN §10 generates the MCP tool from that same scenario and registry; no parallel endpoint is authored. The UI defaults still enforce the canonical guard; no extra presentation-only eligibility contract is invented.

## Exact example contract gap

Frozen DESIGN §5.1 says: “Each row gets a fresh team, deterministic accounts `self` and `other` in that team, and `outsider` in another team.” It defines role-selected callers as self, not an additional user. `can_work` in Employees requires `active_member(person,team)`. Consequently outsider is not a valid third same-team reviewer, and a fixture Employee record cannot grant outsider current team membership. No supported syntax supplies a third member or invokes multiple actors in a single example row.

A complete successful finance stage requires three distinct team accounts. Inventing one or using outsider would make positive setup invalid. Therefore successful finance approval, finance rejection with preserved first evidence, correction after that rejection, and reimbursement after finance approval do **not** have passing inline examples in this draft. The two-actor denial examples genuinely test distinct-actor guards, but do not exercise the later reason/first-evidence conditions. Before-review denial is explicit but its row also has claimant=actor; this is a combined rejection case, not isolated proof of sequencing. No such omissions are counted as passes.

Required independent expectations once a supported three-user fixture contract exists:

1. Set up A claimant, B assigned reviewer, C finance, all distinct active team members with work eligibility at EUR site S; use a private completed receipt, amount EUR 500.01 and submission 1. Invoke first decide as B approving. Expect finance_pending plus exactly one immutable affirmative first Decision with B/evidence; reimbursement fails before C's decision. Before B's decision, C's finance_decide must reject with no history/domain writes.
2. C approves the pending claim. Expect approved, one FinanceDecision capturing C/B/submission/amount/receipt, unchanged first Decision and receipt. C or another authorized finance actor records a full evidenced payment. Expect reimbursed and exactly one matching Reimbursement. At EUR 500, B approval alone suffices; at non-EUR 501, preserve the existing single-review behavior with a matching-currency location.
3. On independent valid pending setup from (1), C rejects with a nonblank reason. Expect rejected and original first Decision/receipt plus immutable negative FinanceDecision. A invokes correct: original status, two histories, all reasons/timestamps/actors and private receipt remain; exactly one new linked draft copies the frozen evidence but no FinanceDecision. A can edit its draft under existing CRUD, submit with incremented submission, and B/C approve anew. A second correction of the original must reject.
4. C rejects with a blank/whitespace reason; a distinct eligible C attempts approval without the exact first affirmative Decision or with unmatched submission/evidence; and any actor reimburses pending/rejected or a qualifying claim lacking affirmative finance evidence. Each must reject without writes. B and A cannot finance-approve. Unauthorized/non-working finance actors cannot approve. Stale finance and reimbursement envelopes must conflict without changes.
5. Verify claimant/assigned-reviewer/authorized finance may read the protected finance history according to its policy; unrelated users cannot read receipts/history. UI and MCP invoke the same expense.finance_decide checks with normal expected versions and operation replay semantics.
