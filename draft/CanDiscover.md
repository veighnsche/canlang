# CanDiscover — recurring opportunity research

A workspace business needs a repeatable way to find public procurement and funding opportunities, understand incomplete coverage, retain the evidence behind a recommendation, and pass reviewed opportunities to its sales team. Staff must not mistake an unavailable source, a model's confident answer or an exhausted budget for an exhaustive search or a sales commitment.

This app starts with TED notices and Grants.gov opportunities. Their adapters are deployment-bound implementations of the app-owned `DiscoverySourceV1`; typed extraction uses `DiscoveryAnalysisV1`. These are desired interfaces, not implemented connectors. Source URLs and retained text are untrusted data and cannot supply credentials, change provider destinations, invoke tools or authorize CRM writes.

## Research and coverage

A location-scoped researcher creates a Plan with two explicit search queries and fit criteria. Starting a run freezes its UTC date window, criteria, queries, limits and initiator. Each source has an independent durable continuation and immutable page attempts. A page admission validates its whole bounded result and commits its cursor and evidence together. No loop silently drops excess documents. An empty nonterminal page advances only through a new verified cursor; neither a short result nor an empty result proves exhaustion.

Every adapter must bind its opaque cursor to the exact source, query and window. `from` is inclusive and `until` exclusive over source publication dates interpreted at UTC day boundaries; an adapter unable to enforce that selection must reject or explicitly return uncertain coverage. Older opportunities outside the configured window are not claimed to be monitored for updates. Requested `take` may shrink with the remaining reservation: a provider cursor that cannot support this must fail visibly rather than reset or skip records. One normalized call permits at most one provider search-page request and at most 20 detail fetches, with no hidden unbounded traversal; these are request-count bounds, not a dollar budget. The adapter must reject an invalid, expired or mismatched cursor instead of starting over invisibly. A normalized document carries a stable source key and revision, canonical URL, retained original text, retrieval time and original deadline/zone hints. Its 60,000-character text ceiling is a rejection bound, not permission to truncate silently. A page contains at most 20 documents. Search-hit text alone must not be represented as complete opportunity evidence when a detail request is needed. Attachment bytes are outside this text-only initial adapter contract; linked material is not claimed to be retained or analyzed.

`Run.complete` means both sources exhausted the frozen query window and every applied page for each source reports the same nonnull snapshot instant. `live` and `uncertain` traversals remain partial even when their cursors end. Caps, failures, unknown outcomes and cancellation remain visible. Sources may have different snapshot instants; this is not a simultaneous global snapshot. Absence from any run never deletes or expires an opportunity. Official TED iteration is documented; Grants.gov's accepted continuation inputs and snapshot guarantees still require adapter qualification. No draft example proves real provider completeness.

## Evidence and decisions

Within a plan, `(source,key)` identifies an opportunity. Same key/revision with the same retained source fields is an idempotent observation; retrieval time alone is not a content change. A new revision creates immutable Evidence with a unique increasing ordinal. The current evidence derives from that ordinal, so a newer admission invalidates an older review for a new promotion. Conflicting bytes under one revision are retained as immutable Conflict observations and block promotion. Different keys sharing a canonical URL or a changed canonical URL require review. A current `needs_identity_review` projection blocks either unresolved key, including the earlier record that had no conflict when first admitted. An explicit duplicate link clears that collision for the selected canonical record without erasing either identity. Staff may link duplicates or explicitly accept the chosen retained identity with a reason; neither action silently deletes history or rewrites CRM.

Analysis receives only one retained document plus its frozen criteria and output-token ceiling. Its typed proposal separates title, summary, nullable deadline, original deadline text/zone, uncertainty, citations, fit score, confidence and rationale. Quotes must occur in the retained original. A normalized deadline requires an explicit zone, a deadline citation and no ambiguity claim. Those checks establish traceability, not the truth of an interpretation or calibrated probabilities. Fit and confidence are advisory scalar estimates, not an adopted probabilistic judgment or automated approval. Missing or failed analysis leaves manual review available; this version does not automatically resubmit uncertain model work.

A reviewer records an immutable Review containing corrected title/summary, cited quotes, deadline/zone or explicit unknown-deadline explanation, current reviewer and time. Current work eligibility, latest evidence and unresolved duplicate/conflict checks apply. A past known deadline blocks promotion. Staff supply canonical Customer, Contact and business value; research does not manufacture customers or accounts. Promotion calls CRM's exported `promote_research(source,input:ResearchLead)` under the same caller. CRM rechecks salesperson authority, current customer/contact/location/currency constraints and its immutable source-key intake. The key is `discover:<opportunity-id>`: identical replay returns the same deal, changed input under that key fails, and later research cannot overwrite the sales owner's deal.

## Limits, cancellation and recovery

Per run, each source permits 1–20 page requests, the shared document reservation is 1–400, analysis permits 0–100 requests, and each analysis has a 1–4,000 output-token ceiling. A page reserves its requested size before dispatch, including empty, failed and unknown attempts. An analysis reserves its slot before dispatch. Limits are conservative counts, not a monetary budget or actual usage accounting. A large page request can exhaust the shared reservation before the second source runs; that remains explicit partial coverage, never success for both.

Current initiating researcher role, workplace eligibility, Plan.active and Run.stopped gate enqueue and delayed dispatch. Pause cancels recurrence and stops the current run's continuations. It cannot cancel an already dispatched provider request or promise a refund. Resume admits the currently responsible researcher and schedules future work; `take_over` assigns the current eligible caller as responsible for future recurrence. Already frozen run attribution is unchanged. Stop cancels its source timers; late receipts stay associated with their attempts and cannot advance stopped or replaced work.

A source in attention can be retried by a currently eligible researcher with a new reserved request. The old unknown request remains distinct, so a late response cannot advance the replacement cursor. Scheduled runs coalesce while continuations are ready/fetching; terminal business states, including attention, permit the next scheduled window. Consequently uncertain requests from an earlier window may still incur provider work: this is a per-run cap, not a global outstanding-spend limit. Staff can pause recurrence while investigating. Revoked initiator eligibility stops processing; another eligible researcher can stop the old run, take over and start a new one. No automatic role impersonation or provider cancellation API is invented.

## Access and surfaces

Researcher/reviewer roles plus current `employee.can_work` at the owning location protect every model, child record and retained text. There is no public researcher directory or external-user access. Researchers manage plans and bounded runs; reviewers resolve evidence conflicts, create reviews and request promotion. Promotion additionally requires CRM's salesperson permission through its owner operation. No generated mutation CRUD is enabled for evidence, reviews, attempts or opportunity decisions. Original source text, review contents and conflicts remain locked. Browser and MCP use the same canonical operation schemas and current admission; UI row visibility does not replace mutation checks.

The `/discover` page exposes plans, run/source coverage, attempt receipts, original/model evidence, conflict history, review forms and CRM handoff. English descriptions with Dutch translations cover the app, roles, page and main workflow; ordinary field labels use shared defaults. No custom frontend store or model-generated HTML is needed.

## Draft verification boundary

The `.can` is normative draft behavior and the `.mjs` is handwritten desired output. Inline tables specify admission, current eligibility, stale versions, citation rejection, partial cursor handling, stopped/superseded completions, repeat evidence and conflicting bytes. Connected sequences actually call start→pause→take-over→resume→restart, blocked review→explicit duplicate link→allowed review, and review→CRM promotion→identical replay→changed-input denial. Provider evidence in the latter sequence is an explicit snapshot; it does not prove acquisition. Trusted completion tables use normalized isolated receipt recipes, not a public callback or live network.

JavaScript syntax and a supported-syntax source projection can be checked locally. The initial parser does not support associated delivery types or sequence bodies; removing only those for a syntax projection is not a full parse. No typechecker, provider adapter, runtime, example runner, UI/MCP server or distributed concurrency behavior has been executed. Further execution must cover snapshot consistency, current role/work revocation at dispatch, source cursor expiration, analysis rejection, provider timeouts and concurrent ordinal/CRM replay conflicts.
