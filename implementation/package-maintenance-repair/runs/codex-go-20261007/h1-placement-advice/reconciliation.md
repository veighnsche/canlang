## Complete programme dependencies that cannot be hidden in the integer patch

The immutable compiler's collect_operations is also MCP publication: it omits entire operations for unmappable inputs (duration/json/bytes/compound/nested arrays), trusted operations and expose=none. ArtifactOperationField and CanonicalScalarKind are the pilot closed set. Thus adding `type` to these surviving descriptors cannot create complete execution authority. The later Contracts/compiler owner task must explicitly make existing execution declaration intake complete independently of MCP supply/exposure, or jointly extend its supported variants and projection. This is a real finite contract dependency, not permission to build a new adapter registry.

Current Values codec support: int/decimal/money/date/datetime/duration/text/bool, stringlike email/url/locale/timezone/currency, file/user/member and identity codecs for refs/delivery/actions/invocation; JSON and schema-defined enums/nominals/unions have their own rules. Secret has no public wire encoding. `bytes` has no builtin Values wire codec despite CanByteQuantity's bigint alias. Generic artifact `string` loses subtype; `other.type` is not a full nominal schema. Unsupported selected positions must refuse profile adoption instead of being guessed or aliased to int.

**Writes need a separately explicit source-language carrier on the existing mutation input, not runtime typeof inference.** The State-owned conversion checkpoint is inside applyCallerData, after each existing unknown/known-undefined/machine/server-only check and the earlier create parent/containment checks, at the current field copy/JSON boundary. A pre-encoder in runtime would change error order. Wire CRUD calls remain wire carriers; canonical language writes use the declared Values encoder at that checkpoint. Exact hook-visible carriers must be agreed with the State owner before enabling this: current hooks receive JSON wire candidates, and hook result/default/server/derived/parent paths have their own existing checkpoints. This carrier proposal is not released by read hydration alone.

Arrays retain container nullability, nonnullable elements, index error order and fresh ordinary omission fill. Required arrays reject omission; nullable omission wins where the current State path specifies it. Operation defaults are not currently filled by generated admission; this fact must be resolved by an explicit operation-default owner task, not by calling Values create validation in runtime. Known undefined updates stay absent, explicit null stays real, unknown undefined still errors. Staged read-your-write must observe the current staged wire row through the existing lazy getter on every access, without mutating persisted data. Preserve integer grammar (actual TS accepts `01` and `-0`), exact decimal/money/UTF16/error ordering, current ref-version domain, fence/replay/hash and rejected-receipt identity.

Prepared/native owners are a separate dependency. Source-exact declaration metadata plus a frozen schema does not supply factory ownerRevision, issued plan provenance, backend/profile revision or lifetime. Genuine revision/factory/default-owner/carrier qualification must come from Values' production owner path. No private provenance hook, manual brand or tagged JSON substitute for the lossless UTF16 carrier is authorized.
