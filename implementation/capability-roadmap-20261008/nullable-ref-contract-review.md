# Nullable singular-reference repair: read-only source contract review

**The minimal repair is supported by the current contracts and can stay within State.** It needs the prepared-inputs leaf and its owning differential tests in the same bounded patch. This is a pre-write recommendation, not implemented or runtime-qualified behavior; the proposed lease extension is still awaiting acknowledgement, and an independent post-patch review remains required. Full task 9 and F1 stay open.

## Source authority and smallest association

`docs/specification/DESIGN.md:124-133` already distinguishes nullable fields (omission defaults to null; explicit null is legal) from optional fields that merely have defaults and from partial update omission. `packages/contracts/src/artifact.ts:165-189` explicitly defines `ArtifactOperationInput.nullable` as true exactly when the input accepts explicit null; its comment warns that `required:false` alone conflates nullable and default-filled omission. `CanonicalInputDef` in `contracts/src/state.ts:753-781` intentionally has no nullable member. No shared descriptor/version or Values change is necessary.

For input admission, preserve the **own, explicit `nullable:true` association on the already checked singular reference input**. The input must have a valid canonical name, checked `field.kind === 'ref'`, a checked declared target model and version requirement, and no array marker. Source the association from that input, never from `required:false`, a same-named model field, the target model, caller input or an inferred name suffix. Scenario reference parameters and CRUD field inputs then follow their own declaration. Inputs with absent/false/non-true additive nullable metadata retain today's no-proof behavior; this patch need not introduce a new general malformed-additive policy. Inherited nullable markers cannot establish the new proof.

The least disruptive carrier follows the existing engine-local `inputArrays` pattern: a copied, immutable per-operation record of known nullable **singular-ref input names**, for example `inputNullableRefs: Readonly<Record<string,true>>`. Keep `CanonicalInputDef` unchanged. An optional member on `GeneratedOperationDef` preserves existing synthetic/hand-built generated fixtures with no association. `artifactToDescriptorSet` extracts it after checking the ordinary input envelope, `loadArtifactDescriptors` passes it privately into `loadExecutionDescriptorSet`, and the loader validates/copies/freezes it before constructing the def and prepared plan. Omit this channel from artifact loader caller options just as `inputArrays` is omitted: artifact metadata owns it. If an intake-direct engine-local option is provided, reject dangling operation/input names, non-ref names, array-marked names or non-true markers as whole-set loader errors. With no such option, intake-direct behavior stays unchanged. Use own-key-safe record construction and lookup so names such as `constructor`, `toString` and `__proto__` cannot manufacture or lose a marker. A frozen record avoids the mutable-Set problem.

For the mutation pipeline, an additional model/ref descriptor channel is unnecessary. `buildModelTableFromCanonical` already maps the artifact's known-nullable field names into `InterimFieldDef.nullable:true`. The checked owning table provides the exact association: the ref's field path must name an **own top-level field** in `def.fields`, that field must declare `nullable:true`, and its array marker must be absent. The artifact loader already derives pipeline refs only from singular top-level ref tags. Do not infer nested/dotted reference nullability or array element nullability from a containing field. At the existing null-ref rejection point, permit null only under that exact owning association. Preserve the existing missing/unchanged-ref ordering, required/known-field/JSON checks, server-only checks, hooks, locks, invariants, when guards, uniques and history. Required fields still fail the required check before reference validation; optional nonnullable fields and legacy unknown-nullability refs still reject changed/present null. Non-null values retain the same id, target existence and archived-target checks.

## Admission and prepared/current parity

In `validateGeneratedInputs`, after the existing presence handling and the ref/non-ref branch, allow an explicitly supplied null only when that parameter has the checked singular-ref marker. Retain null in the fresh normalized shallow copy and add **no pending reference**: there is no record to load, compare a version against, reveal in a conflict current, or enroll in a fence. Omission remains omission in admission; creation null-fill belongs to the existing pipeline, and update omission remains unchanged. Do not fill operation defaults or null during admission, and do not accept `undefined` as null. The synthetic interim adapter receives no new association and keeps its exact legacy behavior and caller-input identity.

`prepared-inputs.ts` currently duplicates the same ref checks and has an explicit exact-current-oracle contract. It must receive the same copied marker through both `prepareDescriptorInputs` and `prepareOperationInputs`; an optional third engine-local parameter keeps current two-argument callers valid. Copy an optional true primitive into the prepared ref rule rather than holding a live map/set or reading mutable descriptor metadata during validation. `validatePreparedInputs` must make the same null-only exception at the same point. Preserve unknown-member order, required errors, array handling, version-required/invalid-version codes, malformed non-null ref behavior, extra-ref-member permissiveness, fresh arrays/shallow copies, frozen loader plans and no cache by operation name. No `state-generated/v1` tag change or second validation authority is needed; exact source/plan association and differential evidence must be refreshed by its State owner. Current repository source search found no other production consumers of these prepared plans outside State.

## Ambiguity and review outcome

No difficult language-design choice requiring JEV was found in this bounded repair: both DESIGN and the existing artifact input contract state the null rule explicitly, and State already has a checked owning-field nullability carrier. An implementation choice between equivalent immutable engine-local carriers is routine. Escalate to JEV/owners only if the patch starts deciding nullable arrays/elements/nested paths, optional-nonnullable policy, malformed additive metadata policy beyond this explicit-true association, a new shared descriptor/profile/version contract, Values scalar authority, secrecy or replay authorization. Those changes exceed this review.

Live source hashes, line counts and the read-only HEAD/status observation are saved in `nullable-ref-contract-review.json`. No tests, compilation, runtime probes, product writes, shared dist writes, Git changes or shared docs edits were performed for this source-contract review. Only this review Markdown/JSON was written. Recommendation: acknowledge the expanded bounded lease before source edits, preserve these source pins, and require the independent post-patch review.
