# Model-rule execution contract: verified context

This is a design decision in progress, not an implemented rule API or a whole-application qualification.

The current compiler emits model declarations with invariant/lock identities, `canApp().invariants[id]` pure `(c,row) => boolean` functions, and `canApp().locks[id]` objects containing declared field names and a pure pre-state predicate. The actual `rules-machine/RuleMachineCore.can` and `core-artifact.json` contain a title invariant and conditional title lock, alongside flat machine transitions. Cloudflare's `collectModelPolicyManifests` validates policy identities but does not install those execution functions. State's `buildModelTableFromCanonical` currently supplies empty invariant, lock and hook arrays. Declared model rules therefore do not yet execute through this join.

Existing State model tables support engine-local hooks, an invariant callback receiving only a synchronous `get(model,id)` final-state view, and whole-record locks represented by QueryPredicate. The mutation pipeline evaluates locks against the pre-write row after hooks, typed conversion and candidate preconditions. It runs invariants at the end of each `runMutationWrites` call against a frozen materialized provisional view. Cloudflare scenarios currently call that pipeline once per helper write and collect effects for one fenced commit. Installing final invariants unchanged would check intermediate helper states, instead of the final owner transaction.

The accepted source semantics are in `docs/specification/DESIGN.md`: line 103 retains admitted versions on ordinary references while domain fields change provisionally, with one reserved next version per owner transaction. The model-policy section requires pure row-scope invariants on affected final rows, dependency-triggered rechecks and bounded authority work. Locks name fields, test the pre-state, permit unchanged locked values and archival preserving them, and prohibit removal while locked. The transaction creating a conditional lock may set final values. CRUD, scenarios and hooks must share enforcement. Permission, owner scope, reference validity and receipts remain with State; callbacks do not create grants.

The recently released typed boundary consumes State-loaded checked associations and public Values codecs. Runtime creates lazy native views without changing stored wire rows. Only singular nonnullable int fields/inputs and declared int/void results are qualified. Local field-based text/bool/enum predicates can keep their existing native carriers; other native types, authority scans, parent traversal, hook binding, dependency rechecks, installed backends and complete apps remain open. Any first slice must explicitly refuse unsupported behavior; a classifier recommendation cannot qualify it.

The immediate comparison is how to implement a first local-field invariant/field-lock slice while retaining a path to the full semantics. All alternatives must enforce the same selected predicates, ordered staged writes, final-only invariant checks, field-scoped pre-state locks, unchanged value and archive behavior, rollback, replay, current verified context, checked callback identities and explicit unsupported cases. Broader query/dependency/hook semantics require their own implementation whichever placement is chosen. No option receives free correctness or an extra public grammar.

Options:

1. Extend State's defining model-rule API with immutable per-call context, row/final-view arguments, field selectors and an owner-transaction finalization point. Runtime binds the existing checked emitted pure functions and hydrates their known fields using Values. Existing interim predicate locks keep their behavior. This reuses compiler output but needs strict callback linkage, a read-only evaluation context, deferred finalization and a checked scope/capability boundary.
2. Extend compiler/Contracts with a small serializable checked rule expression representation for the supported local-field slice, evaluated by State at the same pre-state/final-state points. Reject other expressions explicitly. This avoids a runtime function-context bridge for the slice but adds producer/intake/evaluator and later extension work, with possible duplication beside existing emitted functions.
3. Refuse declared unsupported model rules at activation while retaining current native machines and ordinary scenario guards. Release the complete rule context/dependency/evaluation contract before activating either representation. This immediately prevents bypass and reduces incremental contract churn, but postpones application rules and still requires the selected implementation work.

JEV advice must be retained with uncertainty. Disagreement is investigated against these defining sources, not resolved by manufacturing repeated validation evidence. Product checks will run once after the chosen implementation changes.

## Current defining prerequisite (2026-10-09)

Canonical activation now explicitly refuses nonempty invariant/lock declarations, and CRUD/scenario helper writes refuse declared unsupported hooks; the earlier observation above predates that accepted refusal. The complete task11 join requires checked owning rule identities, ordered membership, dependency plans and lock field selectors from Compiler/Contracts. Hooks also need the genuine fixed context, immutable before/input, correct pending after/removal carrier and reserved native version. Current generated local predicates and hook callables lack those facts. State must then own one bounded ordered staging/finalization session across CRUD, scenarios, nested calls and hooks, with affected-row dependency rechecks, field locks and one reserved version; Cloudflare consumes its release. This records the producer prerequisite and required existing semantics, not a new representation choice, local-only substitute or inherited worker-specific hold.
