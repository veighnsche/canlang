# SEQ-010 source-contract review

Status: source review and proposed owner handoff only. No product code, builds, runtime calls, JEV requests, Git mutation or acceptance. SEQ-010 remains open.

## Finding and bounded recommendation

The canonical user-scenario seam can install the accepted source facts without inventing a second identity resolver. Prefer a narrow immutable projection of the **admitted `call.context`** onto the `c.actor`, `c.team`, `c.now`, and `c.operation` fields already emitted by codegen. Select a current-team member scenario that actually reads each fact first. This is feasible as a producer/consumer repair, but its complete actual-source execution has a separate import-peer prerequisite for datetime consumption, and typed values must not be assumed serializable into State writes or receipts.

Do not project from arbitrary handler arguments, `c.caller`, its `anonymous` sentinel, pipeline attribution strings, saved requesters, or role labels. An internal TypeScript type does not authenticate its caller; `buildInvoker` still requires the production transport resolver and State admission. Public operation IDs are supplied identities subject to shape/age/replay rules, not proof of a human actor.

| `operation.id/source` | `call.context.operationId/source` | Frozen `{id:operationId,source}` | Use the admitted identity/source, not operation name, a business input or hardcoded `mcp`. Keep existing `canonical.operation` name and `operationId` meanings intact. |

`makeUserRef` and `makeDatetime` are already public exports of the owning `@canlang/values` package through `index.ts`; Cloudflare already declares that dependency. This is an explicit verified-fact-to-language-value projection, **not** Values schema/prepared-plan registration or an owner/revision/provenance grant. Types live in `packages/contracts/src/values.ts`; no competing value shape is needed.

Use the same admitted time for the existing handler clock (`clock: () => call.context.now`) within this seam. It currently receives `opts.now`, a potentially advancing host callback. State already fixes `now` across retries; reading another clock here would weaken that accepted guarantee. Freeze copies of projected compound facts instead of exposing the mutable internal context. No whole HandlerContext freeze is required to implement this proposed projection.

Current lowering (`ir.rs:2463-2473`, `js.rs:1700`) already targets these four handler fields. The source type checker requires Team `id/timezone`, OperationContext `id/source`, and canonical datetime/user types (`types.rs:10384-10401`, `10616-10629`). `createContext` (`context.ts:132`) currently installs none of them. `runScenarioSeam` (`invoke.ts:2794`, `3000`) has the actual admitted context, whereas `scenarioParameters` only clones admitted business parameters and record views. `buildInvoker` (`worker/assembly.ts:891`) selects the canonical route and supplies a source label; State `invoke.ts:174-186` captures the clock before retry.

## Value and persistence boundary

Handler-local canonical values and State's current stored/wire values are different boundaries. Pipeline `evalServerInit` (`pipeline.ts:178-194`) still returns `{id:attribution}` for `server=actor` and an ISO string for `server=now`; `actorFor` may return `public`, `test` or a trusted-source string. Those defaults cannot establish a verified human actor. They need their own contextual-default semantics and source execution witnesses.

Pipeline JSON-safety checks (`pipeline.ts:405-418`) explicitly retain bigint refusal until the L2 codec join. D1 writes and receipt fields use `JSON.stringify` (`storage/d1.ts:288/311`, `389-390`). A tagged `DatetimeValue` contains bigint: installing it on `c` does **not** prove `set ...=now`, `create {...now...}`, `return now`, history, defaults or replay can persist it. `runScenarioSeam` forwards result to State, which places it directly in the receipt (`state/invocation/invoke.ts:328-335`). UserRef is JSON-shaped but that alone does not establish correct field validation, wire shape or hydration.

For the first context-read witness, persist/return only supported JSON-safe scalar observations and consume `now` through actual Values datetime operations in source. `datetime(...)`/`compareInstant(...)` exist at the Values owner; compiler equality/order emits them. The currently used Cloudflare runtime stdlib peer exports neither, while the public stdlib lacks emitted CRUD/effect exports. Therefore a datetime comparison witness must obtain a producer-owned compatible import surface first; no test-only mixed shim or altered emitted handler can qualify it. The existing integer `count:"1"` observation and unpreloadable NumericControl remain unqualified integer semantics. Do not solve this by ISO or bigint coercion in this context repair.

## Separate gates and consequential uncertainties

**Full actor carrier:** DESIGN §3 (`:173`) describes stable `user.id` with no directory fields, but §4 (`:297`) and example rules (`:464`) explicitly permit the authenticated actor's `email/email_verified` admission facts. State Principal and compiler `member_lookup` already carry/allow these caller-only facts; canonical UserRef itself has only kind/id. An id-only selected witness remains viable and exposes no directory, but silently removing or claiming all accepted actor reads would be wrong. Before a **full** actor carrier, choose an owner-reviewed extension/accessor or equivalent mapping that preserves caller-only provenance and source field spelling, with three equivalent verified-context JEV requests if the consequential carrier choice remains unsettled. Do not broaden generic UserRef or expose arbitrary account data. No JEV requests were made.

**Null team/app scope:** State allows null team; the checker installs nonnullable Team in scenario bodies (`resolve.rs:3983`, `types.rs:10399`). DESIGN says "when applicable" and no-team roles cannot evaluate. The selected member scenario avoids deciding public/app-scoped team availability. A universal null/default Team, UTC fictitious team or new runtime fallback is not authorized by this repair. Settle applicability/unsupported-use behavior before extending these reads globally; JEV3 is warranted if accepted text does not settle the proposed change.

**Unqualified/direct contexts:** `createContext` has ordinary callers and page/occurrence uses. Required fields everywhere would force an incomplete migration; optional fields alone would let existing emitted reads observe undefined. Root must explicitly qualify only the canonical slice and obtain a coherent missing-scope refusal/compatibility handoff before advertising broader support. This review does not select a new global failure policy.

**Trusted/occurrence:** State trusted kind enforces actor=null but nonempty trustedSource is not ingress provenance proof. Cloudflare canonical user mutation options expose no trusted kind/source join; `invokeCallableInOccurrence` checks only the occurrence stamp. No trusted carrier is qualified by this user-scenario repair; verify actual occurrence scope, producer authority, actor-null/wrong-scope and unchanged user fields independently.

**Hooks:** `$hookCtx.actor` is attribution string, `$hookCtx.now` is numeric, hook team/operation lowering is unreleased, and canonical model tables install empty hooks. Do not reuse the non-hook projection or hook `op=create/update/remove` as source operation identity. Hook owner must release carrier, attachment and evaluation-order/authorization tests separately.

**Pages/locale:** Accepted localized-format design (`DECISIONS.md:1911`) chooses immutable formatter inputs on actual HandlerContext from checked selected-app metadata and admitted team timezone, with UTC for null team. This supports the projection location but does not establish formatter locale/default provenance, page dispatch, shared derives, direct or occurrence constructor forwarding. No locale field/default is invented here. Installed identity, current owner routing, contextual defaults and unchanged complete Creative/Approve remain open.

The narrow four-fact read repair follows settled contracts and can proceed after owner lease/constructor handoff without a new language choice. Full actor mapping, no-team applicability, unqualified-scope behavior, typed State conversion and hook/trusted integration must be resolved at their own boundaries before affected implementation/acceptance. Restoring tagged values is not permission to replace them with wire strings merely to pass JSON.
