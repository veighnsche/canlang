## Fix-JSON shape (owned by S4)

Producer: `can lint --fix --format=json`. Without `--fix` the envelope is
byte-identical to before (no `fixes` key; the non-fix code path is
untouched). With `--fix`, the standard diagnostic envelope gains one final
key — a sorted `fixes` array (`collect_fixes` order: file, start, end,
rule). Renderers live in `compiler/src/lint/driver.rs`:

* `fix_to_json(&LintFix) -> String` — one fix, fixed key order:
  `{"rule":..,"title":..,"file":N,"span":{"start":N,"end":N},"expected_sha256":..,"replacement":..}`
* `fixes_to_json(&[LintFix]) -> String` — the array (`[]` when empty)
* `rejected_to_json(&FixRejected) -> String` — refusals, fixed key order:
  * stale: `{"status":"rejected","reason":"stale","expected":..,"found":..}`
  * span: `{"status":"rejected","reason":"span_invalid","start":N,"end":N,"len":N}`
  * overlap: `{"status":"rejected","reason":"overlap","first":{"start":N,"end":N},"second":{...}}`

String escaping reuses `diagnostic::push_json_str` (same as the envelope);
output is compact single-line. `file` is the numeric `SourceId`,
resolvable via the envelope's `sources` array. Nothing is ever written:
`--fix` reports, the agent applies (`apply_fix`/`apply_fixes` refuse stale
bytes with both hashes). Text mode with `--fix` appends one line per fix:
`<path>:<line>:<col>: fix <rule> <title>`. `--fix` on any other subcommand
is `E7001`/exit 2.

Observed sample (`compiler/tests/data/s4_fix.can`, one I1002 site at bytes

## Shared LSP driver API (owned by S4)

Module: `compiler/tests/common/lsp_driver.rs`. Include from any integration
test with `#[path = "common/lsp_driver.rs"] mod lsp_driver;`. Spawns the
REAL `can lsp` binary (`CARGO_BIN_EXE_can`, fallback
`<manifest>/target/debug/can`) and speaks Content-Length JSON-RPC:

* `LspDriver::spawn()` / `spawn_with(path)` — spawn the server child
* `request(method, params_json) -> String` — fresh numeric id; reads until
  the matching response, buffering interleaved `publishDiagnostics`
  notifications aside (the server pumps after every message)
* `notify(method, params_json)` — fire a notification
* `initialize() -> String` — `initialize` + `initialized`; returns response
* `did_open(uri, version, text)`, `did_change(uri, version, text)` —
  full-text sync notifications
* `code_action(uri, (line, col), (line, col)) -> String`
* `rename(uri, line, character, new_name) -> String`
* `completion(uri, line, character) -> String`
* `take_notifications() -> Vec<String>` — buffered notification bodies
* `shutdown() -> ExitStatus` — `shutdown` → `exit`, reaps the child
  (`Drop` kills a live child so failed tests never hang the suite)

Responses are raw JSON-RPC body strings; assert on stable substrings as the
in-process server tests do. The driver sends `languageId:"can"` on open.
