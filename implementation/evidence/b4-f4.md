## 1. G4: header enum elision

Root cause: the types pass checks `examples` header values with
`expect=None` (`check_example_headers`), so a bare case is never claimed
there, and `emit_unresolved` — which runs *before* the examples pass —
misfires `E2001` on it. Call-arg/observation/fixture positions thread the
expected enum type and elide the same spelling.

Fix (`examples.rs`, `Checker::elide_header_case`, called for every known
header binding in `check_table` and in blind recording): retract exactly
the earlier `E2001` when the value mirrors `type_nameref` claiming
case-for-case — lexical bindings first (bound names never elide),
otherwise a bare `NameRef` (through `Group`s) that is a case of the
binding's uniquely expected enum type (scenario parameter or
generated-create field, through nullability). Span + wording pin the
retraction, so no neighboring finding can be disturbed. Non-cases keep
their `E2001`, exactly as in fixture values (probed: `state=bogus`
`E2001`s in both positions).

The cleaner long-term fix is threading the expectation through
`types.rs::check_example_headers`; that file is outside this packet, so
the examples pass retracts the misfire instead. Observable behavior is
identical (emission already lowers header values through the
`example_values` text fallback regardless).

## 2. Emission parity: every parsed table emits runnable rows

Survey result: no packet-scope emission gap remains open. New
`*_tables_row_parity` tests (test-only emit over the real drafts)
prove every recorded table emits with every authored data row
runnable (exactly one of `expected:` / `error:` per row) and no
`E6006` table omission fires:

- CanFeedback: 14 tables / 31 data rows recorded → 14 / 31 emitted.
- CanInbox: 14 tables / 42 data rows recorded → 14 / 42 emitted.

`bdd.rs` lowering is total over what it receives
(`emit_suite`/`lower_table`/`lower_row` filter nothing; `decode_table`
constructs exactly one of expected/error per row by construction), so
no `bdd.rs` change was needed. Two candidate emission gaps were
investigated and ruled out of packet scope with CST-level evidence:

- Broken blocks: the parser fails whole broken `examples` blocks into
  `Error` nodes (no `Examples`/`ExampleRow` shape survives, verified
  over E1215/E1201/E1007/BadToken variants), and resolve skips indexing
  broken scenarios — so blind recording would need `resolve.rs` /
  `parser.rs` changes (other packets). Mixed value+error rows are
  parser-rejected (`E1210`), so no silent cell-drop exists.
- Role-array `as` cells (`[admin]`) `E6008` in `decode_as_cell` while
  `E5004` validation allows them. No draft uses one; fix belongs to
  `ir.rs` (out of packet scope).

Out of scope, observed (all zero-impact on the parity contract; rows
still emit around them with fail-closed stubs):

- General `E6008` cell-lowering gaps shared with non-example positions
  (decimal literals, `now-1m` duration arithmetic, equality over
  unknowns; e.g. CanFeedback `now-1m` cells, CanInbox `1.0` cells).
  Fix belongs to ir/js lowering (other lanes).
- CanInbox:175 `urgency=routine` keeps its `E2001`: `Triage.urgency.level`
  carries no expected enum in ANY position until G3 judgment resolution
  lands (the fixture `urgency=today` at :89 `E2001`s identically), so
  parity already holds and there is nothing to retract. The packet's
  `CanInbox:255` citation matches no header site in the current draft

  examples header); the live header site is `:175`.
- CanFeedback:201 `status=proposed` keeps its `E2001`: G1 `set`-target
