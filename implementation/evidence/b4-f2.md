# B4-F2: resolve-pass fixes (judgments + failed-handler `event`)

Scope: `compiler/src/analysis/resolve.rs` (+ `compiler/tests/b4_resolve.rs`).
`set x.parent` root-caused to the types pass — see §3.

## 1. Judgment registration (G3/G4)

`SyntaxKind::Judgment` was never indexed, so the name, its bound
self-import (`use inbox {Triage as Judge} from=deployment.…`, DESIGN
§8.2 — the capability pattern), and every use errored (`E2004`/`E2001`).

Fix: index the judgment as a fieldless contract, recorded in a new
`ResolveTables::judgments` side table (a new `SymbolKind` variant is
impossible here: 6 exhaustive matches in `codegen`/`ide` would break
the build). Every use position maps to the silent opaque treatment,
mirroring the bound-external arms: expression heads bind
`Binding::Error`, type paths record the symbol but no `TypeRef`, op
paths and caption paths return `None` silently. Names resolve; the
derived evaluate/result interface stays untyped per DESIGN:897, so
downstream behavior is byte-identical to today's poison-silence (zero
added diagnostics anywhere).

`on=Judge.evaluate.completed` keeps its `E3010`: clearing it needs
`Capability`-kind, which would convert bare-type uses to `E3008`.

## 2. Failed-handler `event` (event-in-`for`)

Not a `for`-scope bug: `event` resolves in `for` headers/bodies of
healthy handlers (CanRent:1318-24). Scenario `money` fails to declare
(`E2002`, closed builtin name), so `resolve_scenario` fell back to
`(params=[], trusted=false)` and the whole body lost `event` — the 22
`E2001`s at :1327-70, including the `for` header at :1327:49.

Fix: on lookup failure, derive `trusted` from the node's own `on=`
attribute (mirrors the index-time predicate). Failed plain scenarios
are unchanged (guard test pins `event` still `E2001` there).

## 3. `set x.parent`: NOT fixed here (types-pass gap)

Root cause is `member_lookup_on_span` (`types.rs`, serves
`type_path_value` for `Path` targets): its `Record` arm checks declared
fields only, while expression `Member` lookup (`record_member`) also
handles reserved members, contained-model `parent`, and child
collections. `resolve.rs` only records the target's scope; no table it
owns can steer that navigation.

Measured proof a resolve-only fix is unsound (temporary patch,
reverted): synthesizing a `parent` field clears the `E2013` but its
`decl` type is unpopulatable from `resolve.rs` (`decl` is CST-driven in
the types pass), so expression lookup — which checks declared fields
first — degrades `x.parent` to silent `Error`: `row.parent.typo_here`
and `set t.parent {bogus_field_xyz=1}` both check clean (exit 0).

Sound fix (~10 lines in `types.rs`, offered to the types lane):
mirror the `record_member` dispatch (reserved/`parent`/children) into
`member_lookup_on_span`'s `Record` arm — the arm's own comment already
claims to "reuse the dispatch". Resolution then succeeds and the
precise later checks fire (`E3001` kind/reserved, set-value checking
with expectations, so `state=unavailable` elides). Pinned by
`set_parent_target_current_behavior` (flip when fixed).
