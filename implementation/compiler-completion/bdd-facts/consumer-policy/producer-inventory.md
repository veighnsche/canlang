# Read-only producer and callback inventory

Checked against current source; no producer/test changes were made. This supplements the proposed policy and preserves specific owning gaps rather than attributing all failures to missing publication.

- `packages/contracts/src/wire.ts:219`: MutationResult carries optional `result:unknown`; ReadResult is declared unknown at the contract surface. `packages/contracts/src/artifact.ts:360`: operation metadata currently includes name/kind/description/inputs, without source scenario result/void metadata.
- `packages/cloudflare/src/runtime/invoke.ts:3051`: canonical scenario execution returns its real emitted callable value as execution-effects result. `packages/state/src/invocation/invoke.ts:358` returns that value in committed MutationResult. Replay at :205 normalizes missing result to null. Absence versus declared nullable-null therefore needs source declaration ownership when exposing current result; an envelope success flag cannot supply it.
- `tests/e2e/fixtures/example-hooks.ts` and `pilot-examples.ts` currently return `{ok:true}` after invokeMutation success. Their real payload is nested at `outcome.result.result`, not the outer MutationResult object. These are dropped-payload joins, not evidence that the canonical mutation producer lacks all business results.
- `packages/cloudflare/src/runtime/invoke.ts:3643` invokes the generated-model read engine and requires records[]. `packages/state/src/invocation/invoke.ts:430` accepts generated read descriptors only. General source read=true scenarios must not be claimed to run through this read entry merely because wire.ReadResult is unknown; their actual canonical callable path needs qualification.
- `runtime/invoke.ts:2761` hydrates admitted scenario record parameters from genuine recorded refs into frozen field/metadata views, with staged data reads inside the canonical call. These views are internal to invocation and are not currently returned to BDD callbacks. `packages/state/src/ports/read.ts` supplies authorized viewer/owner query ports; owner mode is explicitly a capability and must not be exposed as an unverified context option.
- PilotExamples.observeScope currently reloads only its registered fixture rows through raw store.load and returns row.data. It does not project logical current action-input identities or expose metadata fields, and row replacement must not be inferred from the original common fixture alias. This isolated test setup port is not automatically a general canonical authorized input projection.
- `packages/cloudflare/src/runtime/context.ts:93` HandlerContext has caller/store/clock/memberships/preferences and an optional canonical effects scope. Testkit callbacks currently receive FixtureBindings(self,other,imported). This is not a HandlerContext; adding inputs/result slots must not imply that callbacks receive real operation authority or that record/query stdlib methods become executable without a qualified bounded inspection port.
- Table loader captures the invocation outcome only through its caller and supplies observation callbacks with bindings plus hookScope. It does not record/send successful result. The current postcall observe hook sees StashedRow inputs but may reload only fixtures.
- Sequence runner currently fixes scopeArg before the loop, binds `as` to the complete success envelope, and never tracks result. It must refresh inspection per statement and retain captured values independently of current result.
- Additional real execution gaps: readSequenceSteps retains a request callback, but runSequenceSteps never evaluates it or sends overrides to InvokeCall. Its StepCall carrier lacks request. Assertion type IDs emitted by compiler are discarded by readSequenceSteps; generic diffReportValues is used instead. Completing callback/result execution must preserve the actual request/error/rollback and typed-assertion owners, not rely on shape-only golden evidence.
- Imported/local derive helper bodies currently live in the production entry's shared emitter. Package modules emit identity/metadata and some capability functions but do not emit executable derives. Suite lowerers do not emit derive declarations. The selected canonical body/default emitter can be reused for the reachable closure; simply adding an import to the current package module would still leave the required callable unavailable.

The proposed path scope must distinguish finite pure callback/actual testkit invocation-port controls from real canonical model/invocation/read qualification. All known legal plain result, input and derived-call controls remain required. No fabricated payload, cached fixture substitution, or unsupported-language carveout is proposed.
