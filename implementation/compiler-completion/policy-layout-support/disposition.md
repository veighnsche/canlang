## Same-contract alternatives

Pinned public serde_json 1.0.151 source is preserved in `standard-public-serializer.json` and raw files. This is inspection of actual installed public APIs, not a proposed dependency or a claim that an undocumented library feature exists.

| Alternative | Same schema/order/value outcome | Same layout/byte outcome | Budget disposition |
| --- | --- | --- | --- |
| Existing PolicyFormatter through shared Serde adapter | Typed records own key order/omissions; Serde owns value/string emission; shared escape override retains `\\u0008`/`\\u000c` | Exact mixed inline/multiline rows, nested closing indents, inline requires/params and one serializer newline; CLI adds the second | Supported now, no deletion claim |
| Public `serde_json::to_string`/CompactFormatter over the same Envelope | Can retain typed field order and omissions; default escape spelling changes backspace/formfeed | Removes spaces/newlines including root layout; adding final newline alone cannot restore it | An apparent short replacement fails the same bytes/readability contract |
| Public `serde_json::to_string_pretty`/PrettyFormatter over the same Envelope | Can retain typed field order and omissions; default escape spelling also changes | Every nonfirst object key and every array element gets a newline; rows/params cease to be inline and nested closures use depth indentation | Public supported serialization, but not a supported same-contract replacement |
| Shared public `json::to_compact_string` over a serializable Envelope | Preserves Can-compatible escapes without another escape owner | Still compact throughout, losing required mixed layout | No byte-preserving retirement |
| PrettyFormatter with alternate indent or a compatible-escape wrapper | Wrapper can preserve escapes; indentation string can change indentation width | PrettyFormatter still unconditionally writes newlines at each object key/array item; it has no public key-sensitive mixed-layout switch | Escape repair does not qualify layout; added wrapper counts |
| Internal direct writer, compact row fragments, whitespace postprocessor, or rewritten custom Formatter | Could in principle preserve this closed schema using typed pieces | Must independently preserve exact key-sensitive whitespace, empty/populated arrays, nested closure indents, escaping, options and both newline boundaries | No implemented and qualified <=budget replacement located; it would retain or relocate owned layout decisions and all replacement code must count |

It establishes that the actual standard public serializers do not preserve today's contract, and no demonstrated identical-byte internal replacement meeting 120 net exists in the inspected implementation/evidence. Keeping the current contract follows its existing guards, rather than choosing retention because it is easier.
