# ED-R06 / FAIL-R07 proposed session history ownership

Status: accepted by root for the bounded declared scope; implementation released. Root owns shared decisions, integration and Git.

The selected minimal closure is `compiler/src/lsp/server.rs`, `compiler/src/lint/driver.rs`, and a new public integration test. `source.rs` needs no reclamation/storage API. Its immutable append-only ownership, private owner token and existing IDs remain unchanged.

## Verified scope and proposed invariants

The public `LanguageAnalysis` trait synchronously borrows `&SourceDb` and a current `SourceId`. The public Server surface exposes construction, lifecycle, pending count, message handling and pumping, but no source database accessor/lease. A callback cannot retain that borrowed DB across a mutable Server operation. SourceId is already documented as identity within a SourceDb; a stored numeric ID alone does not retain its owner. CheckedProgram can outlive a callback, retaining its private identity token, and must refuse a later replacement DB with E6011. Independently held public SourceDb owners remain valid and append-only indefinitely.

Replace only the Server-owned database after accepted distinct content/open membership changes and close, using exactly one immutable current source per live document. Preserve same-text reuse and version advancement without unnecessary replacement. No workspace file loading, cross-file semantic analysis, catalog reload, background executor, cache, generational ID, lease API or revision threshold is introduced. The supported RealAnalysis still checks the selected document; all backend callbacks retain their shared all-live DB view.

The implementation can first append a changed source as today, update its OpenDoc and enqueue its work, then rebuild. Before IDs are reassigned, retain only pending tasks whose URI/version/old source ID all match the current live document. Rebuild in current-source ID order (URI breaks any tie), preserving current append order and duplicate display-path latest-live lookup behavior. Update every document ID and surviving task ID before replacing the DB; preserve FIFO task order. Stale or closed tasks cannot alias reused numeric IDs. Same-text changes keep existing pending-count semantics. Close continues to clear diagnostics and cancel all work for that URI; equal-version reopen cannot revive removed work. Shutdown/exit pumping still clears without publication.

The accepted resource bound is live source count and live text, not a constant limit or universal latency/RSS guarantee. At rest the Server DB contains one source per live URI, no historical revisions. OpenDoc retains its current text copy as before; rebuilding temporarily holds the old and new live databases plus one appended change. Backend-owned independent artifacts/checked tokens and not-yet-pumped task records are outside historical source-text retention. A large live set or large authored current file remains proportionally large.

Lint and fix collection iterate `CheckedProgram::checked_files()` in its exact recorded order, preserving IDs and duplicate selections. Unselected/historical sources do not become semantic lint inputs merely because they share a database/path. IDs absent from the supplied DB are skipped. This packet does not extend codegen cohort check-time-bound admission to lint: an invalid-at-check ID later made present remains outside the selected valid-file qualification. Existing caller responsibility to use the checked owner's DB is unchanged; this packet does not invent a lint catalog/ownership admission API.

## Fair alternatives and uncertain advice

Immediate all-live replacement has the narrowest owning closure and retains zero historical source bytes, but copies/hashes every live text on distinct changes. A reclamation storage API could avoid copying unaffected texts, but preserving immutable public SourceDb/get/iter IDs while freeing entries requires a distinct generational/lease abstraction plus caller/cohort compatibility work; bare public IDs provide no retention lease today. Budgeted immutable history reduces rebuild frequency, but requires a new revision/byte threshold and still needs the complete same remap/current-task closure while retaining unnecessary old bytes until that threshold. No project/workload requirement supplies a justified threshold or lease API demand.

Three independently rewritten equivalent minimal abstract choice requests were approved and returned complete replies after three ordinary sandbox connection failures. They transmitted no repository names, code, paths, secrets or records. Results are materially split: reclamation_api probability0.55/confidence0.33; bounded_history0.62/confidence0.43; reclamation_api0.44/confidence0.16. Source inspection explains why the broader alternatives remain plausible optimization directions but lack a supplied performance workload/API need. The proposal selects immediate all-live ownership based on the declared current borrowed callback and single-document scope, accepting proportional live-set copy cost. This is a coordinator policy decision with unresolved JEV advice, not consensus.
