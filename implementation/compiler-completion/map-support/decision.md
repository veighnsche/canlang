## DEP-02 / integration:source-map-extraction

The exact responsibility-map target is `EncodedMappings`, temporary `Vec<u8>`, one library full-map encoding → projection parse, and two `expect` sites: 16 inclusive physical lines in the inherited target, with a minimum **1 net production line** across the complete replacement closure. Current source-map owner is unchanged. The accepted support boundary remains the library's complete map codec plus Can's snapshot/name/byte-coordinate and typed artifact contract.

Pinned `compiler/Cargo.lock` selects `sourcemap 9.3.2`, registry checksum `314d62a489431668f719ada776ca1d49b924db951b7450f8974c9ae51ab05ad7`. Local official crate source, compiler inputs and linked library are SHA-256 pinned in `pins.json`. The supported public encoding interfaces are established from actual source and compiled controls:

* `SourceMap::to_writer<W: Write>(&self, w: W) -> Result<()>`, `types.rs:545–547`, calls the complete JSON encoder.
* `SourceMap::to_data_url(&self) -> Result<String>`, `types.rs:562–567`, invokes the same complete encoder, then adds base64 and a data-URL wrapper.
* `vlq::generate_vlq_segment(nums: &[i64]) -> Result<String>`, `vlq.rs:307–314`, is a **public numeric segment encoder**. `lib.rs:77` exports `vlq`. It does not accumulate map deltas, order tokens, choose 1/4/5-field segments, manage source/name identities, or join rows.
* `encoder::Encodable::as_raw_sourcemap` and `serialize_mappings` exist internally (`encoder.rs:13–15,105–147,149–184`). `lib.rs:66` makes the encoder module private and does not re-export its trait. Actual external probe rejects the import with E0603. `get_mappings` probe rejects with E0599. The library `SourceMap` does not implement Serde `Serialize` (E0277 control and full `types.rs` source search).

No line compression or smaller projection DTO is claimed as engine retirement. There is no replacement production diff to count, and the 16-line gross target is not a demonstrated saving. The public numeric encoder was investigated explicitly rather than overlooked; its presence does not imply a supported public complete mappings encoder. Upgrading the dependency or requesting a new upstream public API would be a separately scoped future task, not a deferred requirement for this decision.

Complete in-repository source-map production callers: `artifact::assemble` calls `build` for entry, package, and suite modules, while public `codegen::emit` and CLI `run_compile` reach assembly; `CompileArtifact`/module typed serializers borrow `SourceMap::Serialize` through artifact JSON output and public `codegen::to_json_string`. `to_json` remains a public source-map helper. Public reach is exported through `lib.rs` → `codegen` → `sourcemap`; unknown external callers remain supported. Source/name ID conversion, repeated authored paths, source content/order, generated-row vector order, unmapped rows, empty/repeated names, CRLF byte coordinates and wire field order cannot be waived to simplify extraction.

## ARCH-02 adjacent public map decoder

**RETAIN public production `DecodedSegment`, `decode_mappings`, `add_delta` and `validate_vlq_envelope`; 85 counted declaration lines remain, zero deletion credit.** `DecodedSegment` and `decode_mappings` are exported public Rust APIs even though their documentation describes a compatibility test view. Repository nonuse in non-test paths does not authorize removing public support or moving it under `cfg(test)`.

All repository Rust decode callers are the source-map module's four relevant unit tests (duplicate snapshots, unmapped rows, compatibility order, malformed/overflow), and codegen integration tests (`assert_sourcemap_valid` consumer helper plus source-map/name/malformed regressions). `DecodedSegment` is used by decoder construction and an empty-view unit assertion; the returned public type exposes signed `i64` fields and optional source/name fields. Library whole-map decoding sorts unsigned token coordinates and doesn't preserve authored empty/trailing rows as this view does; it cannot directly replace the public signed, ordered row API. Moving those 85 production lines to tests would leave up to all 85 repository declaration lines and break exported support; that is neither authorized nor deletion evidence.

The independent existing consumer fixture uses authored expected byte-coordinate tuples and its own arithmetic decoder, then current source runtime `lookup`, artifact parse/load, exception invocation and testkit location formatter. It also pins `@jridgewell/sourcemap-codec 1.6.0`. Those first consumers qualify generated valid maps, not every malformed/signed public compatibility input. They do not release the Rust public decoder boundary. Current envelope and checked accumulation prevent known numeric-parser invalid alphabet and signed overflow issues. This support choice introduces no new policy and does not need a new JEV decision.
