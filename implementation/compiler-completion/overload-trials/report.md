## Public controls and observed facts

The external Rust harness builds the current compiler path dependency offline, loads the unchanged `packages/values/dist/catalog.json` through public `load_catalog`, and calls public `check_program`. Thirteen exact authored sources, raw diagnostics, selected-call facts and validated-leaf node facts are saved. Ten clean controls cover int/decimal money overload selection, reversed named currency slots, plain format named slots, message format explicit null and locale, valid local-instant enum claiming, min specificity, money sum and declaration nullable/default omission. Three error controls cover positional and reordered named local-instant wrong folds, and an invalid timezone spelling. Final run exit 0; see `qualification.stdout/stderr` and `commands.txt`.

`money_decimal` selects builtin money overload 1; `money_named` selects overload 1 with slots [Some(1), Some(0)]. Plain format selects overload 0 with reversed named slots; message format selects overload 1, including explicit null. Min selects the nonempty overload 1. Declaration `f(b=null)` publishes [None, Some(0)]. These are checker observations, not newly executed JavaScript evaluation-order tests.

The wrong-fold cases emit the exact E3005 `expected one of earlier|later` on `middle` and publish no selected calls, while the `"UTC"` literal remains Scalar(Timezone) in public `CheckedProgram.types.node_types`. The named case has the same result despite source argument reordering because matching follows declaration order. This demonstrates a contextual fact written during a rejected trial. It does **not** establish that retaining such contextual facts for an erroneous program violates an owning contract, nor demonstrate a wrong hover, diagnostic, typed-IR or runtime outcome. The invalid-zone control emits E3001 plus E2001 for the unclaimed later enum name; it has no selected call. Nothing in this packet changes the existing failure precedence.

Attempt 1 is retained: `Invalid/Zone` passed the compiler's shape-only timezone check, contradicting the harness expectation. The repaired negative control uses `not a zone`, which violates the existing whitespace rule. No real-world timezone inventory claim is made.

## Candidate isolation review

`try_overload` evaluates matches using the fixed pretrial `typed` argument vector. Enum claims are stored in Trial and flushed only for the winner. `inhabit_validated` directly calls `self.record`, so its successful literal type write is shared across trials. The successful winner flush only restores enum-case claims. Union arms fork/commit trial bindings and enum claims but do not isolate the shared literal write. These are verified source mechanics, not by themselves a demonstrated successful-program bug.

The installed catalog has no pair of same-arity overloads that can claim different validated leaves for a successful literal argument: money twins both expect the same currency leaf; the only sum currency overload has a different arity from the other sums; format's plain arm is text/Display and its message arm is message/locale; local_date and local_instant validated leaves are single-overload contracts. Ordinary same-arity abs/round/overlaps and nonempty min/max do not perform differing validated-leaf inhabitation. Date/datetime are not validated-leaf inhabitants in this path. Dotted nominal leniency was outside this qualification.

Current source pins differ from the older independent selected-call review for types.rs and IR, so older runtime receipts were not upgraded into current-source proof. No fake runtime, private SigType witness, producer catalog rewrite or broad suite was used. Export and actual facade file hashes are saved only for provenance; no facade invocation is claimed.

## Remaining witness and narrow closure suggestion

Keep trial isolation as an unresolved upgrade/custom-catalog obligation, not a closed semantic defect. A stronger witness requires an actually supported producer contract with a same-arity losing arm that first accepts a validated literal and later fails, followed by a winning arm that expects that source literal as text or another leaf. A private catalog example such as first `contains(value:locale,needle:int)` then `contains(value:text,needle:text)`, called with `contains("en","x")`, would expose the proposed cross-winner difference through public check_program but would remain a synthetic contract, not current producer/runtime evidence. The next input needed for a production defect claim is an owning admissible producer contract plus its real typed-IR/IDE/runtime consumer expectation, or a declared contract that unsuccessful calls must not publish contextual literal types.

If that contract/witness is established, the smallest candidate change is confined to `compiler/src/analysis/types.rs`: add a separate trial-local literal-retype vector; append in inhabit_validated, carry it through fork/commit, and flush only after the winning overload is chosen. Do not reuse enum claims because their flush also marks resolved_cases. Do not change scores, ties, slot mapping, arity, diagnostic precedence or evaluation order. A focused new checker integration test would need both the strong witness and current successful currency/locale/named/nullable/default controls. No codegen/runtime/source lease is currently suggested; no patch was written because the stronger claim remains unproved.
