## Complete input and caller boundaries

All production parse sites are inventoried by source search: `analysis/catalog.rs::parse_catalog`, `lsp/server.rs::run_stdio` through transport's re-export, and `docs.rs::reference_json`. Tests are not credited as production callers. `lib.rs::pub mod json` and `lsp::transport` re-export `Json`, `MAX_JSON_DEPTH`, `ParseError`, `parse`, `render`; unknown external Rust users remain supported. The custom public six-variant tree, first-match `get`, `as_str`, `as_bool`, lexical `as_i64`, `as_arr`, exact `Num(String)`, ordered duplicates and public `ParseError` offset/message/display cannot be deleted on repository nonuse.

Catalog: `parse_catalog` → `load_catalog` → `CatalogAnalyzer::analyze_owned` (also public `analyze` delegate and dispatch/analyzer routes) or `RealAnalysis::from_process` (LSP startup). `load_catalog` owns flag/environment/default search order and UTF-8 admission. `parse_catalog` owns envelope version/entries and `E6003`; `parse_entry` owns first-member field reads, effects/availability and calls `parse_signature`, `check_helper_spine`, `parse_component_shape`. The latter owns component vocabulary, arrays and slot booleans; signature grammar yields `E6004` separately. Catalog IDs and entry order, duplicate-ID detection and subsequent checking remain owning domain work. On JSON error the exact `ParseError` display appears in **`catalog '{origin}' is not valid JSON: {err}`**, with `E6003` and the supplied source primary. CLI joins that diagnostic into output; RealAnalysis reanchors it to each document start (`server.rs:296`). Unknown extras are still fully parsed and strictly decoded, not bypassed.

LSP: public `run_stdio` → `read_message` → UTF-8 admission → re-exported `parse` → public `Server::handle_json` → public `parse_call` → `handle_request`/`handle_notification`. `parse_call` counts decoded reserved keys (`jsonrpc/id/method/params`) before first-match reads, rejects duplicates and invalid unique IDs, and preserves safe correlation. `valid_id`/`integer_value` admit exact integral decimal equivalents in the i32 profile without floating rounding while retaining authored numeric ID spelling. Server projections are `known_request`, `no_params`, `valid_params`, `doc_of`, `parse_coord`, `parse_pos`, `parse_range`, `parse_pos_request`; mutation/query handlers retain lifecycle/method/parameter precedence. `output::response` renders just the admitted ID into public `RawValue` and serializes typed payloads; `response_ok`, `response_err`, `notification` are public compatibility render builders. ParseError is publicly available through both modules; stdio deliberately maps a malformed complete frame to exact null-ID `-32700` / `invalid JSON`, then continues at the next frame. Stdio does **not** expose the parser's native reason/offset on the wire. Framing/body/header limits and malformed UTF-8 remain separate error origins. CLI `run` starts `run_stdio`; main routes through CLI.

Docs: `reference_json` serializes typed data and parses it into ordered `Json`; its 13 public callers are `ReferenceModel`, `ReferenceOwner`, `ReferenceDeclaration`, `ReferenceField`, `ReferenceOperationInput`, `ReferenceOperationResult`, `ReferenceOperation`, `ReferenceExample`, `ReferenceDescriptionValue`, `ReferenceDescriptionVariant`, `ReferenceConstraint`, `ReferenceSourceLocation`, `ReferenceAvailability` `to_json`. Typed live output does not release these supported adapters or their expectations/panic origin. They remain in any complete replacement budget.
