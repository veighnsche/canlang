## Normative semantics and proposed carrier

DESIGN §9 lines 798,830–832: unbound tab expressions are text/messages, transient selection per render site. Bound block expressions are enum cases, all cases exactly once; captions derive owning case labels. Bound leaf is an enum selector. Immediate canonical preference save/version/error restoration and inactive-control retention are required but actual tabs factory currently renders a POST form/Save button and pre-renders all panels. Thus items adaptation can repair caption/descendant transport without proving complete normative selection lifecycle.

Candidate checked UiFact keyed by NodeKey: factory target and finite adapter kind; admitted attrs and authored payload nodes; Tab fact {kind:unbound|bound,valueIdentity,captionNode,children}; Order fact {preferenceFieldSymbol,default:OrderTerm[],cases:(caseSymbol,OrderTerm[])[]}; full owning enum/type/grant evidence retained. IR should consume facts, preserve source order and not repeat checked semantic inference.

Unbound Tab identity choices: render-site ordinal (stable for one authored tree, unique despite duplicate/translatable captions); caption-derived identity (changes under locale/caption edit and duplicates collide); new explicit value syntax (new authoring requirement, grammar/compatibility cost). Preferred proposed ordinal scoped by page/render site; use exact enum case identity for bound tabs, never translated caption. Actual tabs default selection is first item unless open/current; language has no authored open for Tab. Distinct tabset id must be generated per render site to avoid default tabs radio/id collisions. This identity is a design choice requiring root approval/JEV before implementation.

IR candidate: dedicated IrUiTabs payload with unbound/bound selector and IrUiTabItem{value,caption:TypedExpr,children:Vec<IrUi>}; lower tabs({context,items:[{value,caption,children:()=>[...]}],id,...binding}). No tab import/export added. Children thunk preserves evaluation within render boundary; authored gates remain context-correct; bound selector reads admitted bindings once. Caption expression evaluation once; array order remains authored order.

IR order candidate: structured policy carrier preserves all static lists and one preference expression. Lower selection once to effective OrderTerm[] before collection query; default selected for absent override; field signs become asc/desc. Forward order through ListProps/TableProps -> ListQueryArgs -> actual interfaces runner -> validated invokeRead list query -> QuerySpec/BaseQueryInput. Use existing engine comparator and cursor order fingerprint; no new JS comparator/client sorting. Query/pagination owners must prove order change invalidates cursor while preserving filters/drafts. Those producer files are a consequential second lease, not released here.

Catalog profile policy: neither producer availability=implemented nor JS factory whitelist is sufficient. Accept a component only through a reviewed source-profile-to-real-props adapter. The actual catalog covers all 68 required words, but infrastructure signatures are not uniform props factories. Keep E6008 for a form whose owner adapter genuinely remains unavailable. Unknown word/attr/child profile should receive clear checked diagnostic; a custom catalog cannot grant arbitrary import access or invent a module factory. Do not add whitelist names without complete header/attrs/children/context/type witnesses. Full catalog implementation remains broader than this bounded packet.
