# Existing carrier conversion and proposed combined writer closure

Read-only follow-up, 2026-10-08. The initial claim that tagged compatibility necessarily requires a new presentation decision was too strong. An implemented conversion already exists. No production files changed.

`@canlang/stdlib` exports `encodeValue` verbatim from Values (`src/index.ts:128`, installed `dist/src/index.js`). The loaded functions are identical. `encodeValue('date', native)` emits YYYY-MM-DD; datetime emits exact canonical UTC with milliseconds; Decimal emits normalized exact decimal text. These are precisely the existing accepted UI `toOperand` inputs. Shared Contracts' `MessageParamValue.value` is unknown; its type id is retained independently. The UI factory preserves the typed pair. Converting at this factory boundary retains the typed scalar's exact value and uses existing owner codecs, without a new representation, API, dependency or formatter implementation.

`conversion-map.mjs` executes seven existing codec -> UI factory -> UI formatter controls, with fixed expected codec outputs. Modern dates, an explicitly offset datetime, Decimal1.50 and a38-digit/18-scale Decimal render correctly.0001/0099 reach the distinct low-year validator defect. Six null/already-string-as-native inputs refuse the existing public codec's `ValueError/invalid-construction`; the codec does not guess a native value or bypass nonnullable input requirements. Generated modules remain unchanged, so these positive helper controls do not claim a completed compiler fix.

The implemented descriptor owners remain distinct: Contracts/UI use `{source,variants,params?}` with string carriers; Values' descriptor additionally requires `kind:'message'`, and its formatter requires native Date/Datetime/Decimal. All converted strings fail the Values formatter's native precondition, as retained in `conversion-map.json`. The accepted future localized-context adapter must construct its Values descriptor and decode these typed UI carriers using the existing public `decodeValue`, or otherwise consume the UI formatter with the accepted trusted scope. That pending adapter is already required by the differing descriptor tag; it does not block the now-concrete page presentation mapping. DESIGN's desired generated typed-parameter example is assessed as a target contract, not proof that Values' native descriptor is the currently implemented UI descriptor.

Proposed exact implementation closure:

- `compiler/src/codegen/js.rs::lower_message`: normalize only resolved `date`, `datetime`, `decimal` parameters using existing `encodeValue(type,value)` and retain each type id. Capture all native parameter expressions once, in existing order, before codec calls; use existing injective temporary identities. The IR direct fast path currently stores original expressions in parameter order; the named/default path already captures supplied arguments and binds defaults. Preserve both stages and avoid validating the first direct operand before later supplied expressions execute. No IR or scalar constructor changes are needed.
- `packages/ui/src/messages.ts::isValidDate`: replace the year0–99-remapping construction with full-year-safe UTC validation, explicitly retaining supported0001–9999 bounds and rollover rejection. `isValidInstant` inherits this correction. No timezone adaptation is added.
- Exact focused tests: new compiler runtime fixture/test only after root releases its path; `packages/ui/test/messages.test.ts` for low-year/date-range/calendar/datetime regressions. Reuse the actual eight source/artifact/page-export/admit/render witnesses and add source order/default/getter controls, canonical offset datetime, styles, exact Decimal precision, constructor exceptions and strict null/native failures. Rebuild/re-pin the specific compiler/UI producers only after root coordinates source/binary ownership.

For invalid runtime carriers, introducing the public codec changes a previous later UI TypeError to the existing codec's ValueError. These values violate native/nonnullable preconditions; this exact error and evaluation stage must be tested and reported, not described as byte-identical. Valid source constructors retain their own errors before conversion. No new permissive fallback or string-to-native guess is proposed.
