# Compiler release input inventory (DEP-03)

Fixed scope: the compiler binary jobs currently advertised by `.github/workflows/release.yml`: `x86_64-unknown-linux-gnu` (`ubuntu-latest`) and `aarch64-apple-darwin` (`macos-latest`). The workflow installs Rust 1.99.0 and runs `cargo build --release --locked`. It does not install an explicit target, publish crates, or create a GitHub Release. No additional target is inferred from installed rustup targets.

`manifest.json` inventories every registry package in `compiler/Cargo.lock` (93 entries), lock checksum, whether its local cached `.crate` archive is present, actual archive SHA-256 comparison, archive-declared license and rust-version strings, and hashes of license/notice files found inside each available archive. It is a finite whole-lock input inventory, not a finding that every locked crate is selected for each target or an attribution approval. Project `license = "MIT"` describes the compiler package only. No dependency closure license approval is made here.

On this host, rustc 1.99.0 is installed with native host `aarch64-apple-darwin`; rustup also lists `wasm32-unknown-unknown`. That wasm target is not an advertised compiler release target. Offline `cargo tree` succeeds for the native host and `aarch64-apple-darwin`; the Linux target tree attempt cannot complete because `linux-raw-sys 0.12.1` is absent from the registry archive cache. Five of 93 registry archives are absent (`js-sys 0.3.106`, `linux-raw-sys 0.12.1`, `r-efi 6.0.0`, `windows-link 0.2.1`, `windows-sys 0.61.2`); 88 available archive hashes match Cargo.lock. The corrected scanner records 142 packaged files with standard LICENSE/LICENCE/COPYING/NOTICE names, including hyphenated suffixes. Two available archives have no recognized file, which does not prove the absence of licensing text under another name; 23 have no declared `rust-version`. Missing archive metadata is left null/absent, not inferred.

Build evidence is qualified by snapshot. The release workflow's exact manifest and lock hashes match the retained pass-10 profile receipt. That receipt records successful native macOS arm64 and Linux amd64 optimized release builds on Rust 1.99.0, but the built production source snapshot predates current source. The later resumption receipt records 1,070 compiler tests and all-target Clippy on its frozen macOS arm64 source: 13 of its 95 compiler pins differ from the tree inspected by this review. The flat-stack `results.json` release row records exit 0 and the successful build stream is `release-build.stderr`; `release-build.stdout` is empty. Four of that receipt's five source pins now differ. These are historical build/check results at their recorded snapshots. Neither receipt qualifies optimized artifacts from the current working tree or a current-source Linux build.

The package manifest declares `rust-version = "1.99"`; this is the project's selected toolchain floor as declared, not proof of a lower or higher dependency-closure MSRV. No lower-MSRV claim is made. The author reports metadata/test extraction failures involving `futures-core 0.3.34`, but their raw stderr/status receipts were not retained, so the protected-cache diagnosis is unverified. The recorded test command also lacks `--offline`; no blanket assertion about network attempts follows from that summary. The retained Linux tree stderr establishes its missing cached archive. These are inventory gaps, not evidence of target incompatibility.
