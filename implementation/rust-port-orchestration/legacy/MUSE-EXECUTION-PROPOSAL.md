## Nested workers, commands and frequent commits

Each Muse starts with at most two independent coding children where the native capability supports it. The coordinator may implement its own reserved assembly/contract work alongside them. Each child receives task IDs, exact base/inputs, finite files, acceptance witnesses and an output root. It may edit and test its files. The local coordinator alone stages explicit paths, commits, rebases or integrates in that worktree. No child `git add -A`, checkout switch, root lock mutation or cleanup of another output. Do not create extra child worktrees by default.

Codex selects a finite dependency-qualified packet, ordered alternative tasks and allowed check classes, rather than requiring permission for every shell command or local microtask. Muse may divide those approved tasks among disjoint native children and act on actual child/command results during execution. It does not run a local scheduling loop, poll a roster periodically or independently reprioritize the global queues. Codex owns cross-packet selection, priority and reassignment. New scope, shared-file ownership transfers and conflicting contracts return to Codex. A blocked child takes an explicitly approved ready alternative or completes its local assignment; it does not hold a build token while requesting work repeatedly.

The verified planning host has 10 logical CPUs and 16 GiB RAM. Initial local heavy-command capacity is **two across Codex acceptance and all four lanes**, with bounded Cargo/test worker concurrency (initially two per command), private generated outputs and no overlapping output writers. This is provisional capacity, not a claim of optimal performance. Lightweight source/fixture work can continue across all four Muses. Reduce capacity on memory pressure or contention; increase only from observed capacity and ready useful work. Four top-level instances plus nested workers do not imply unbounded host builds.

Use a supported process-held capacity mechanism during execution, verified before release; no mechanism is claimed installed by this document. If only recorded grants are available, Codex allocates finite command classes/slots at activation and each owner atomically acquires/releases its slot for the actual command. Grants are not held throughout editing. Record actual handles, deadlines, last results and output paths. Process disappearance or elapsed deadlines alone do not release ownership: reconcile exit/result and the owner's release. Reuse live handles; never duplicate a command to diagnose it.

Each worktree owns `dist`, incremental metadata, Turbo cache, Cargo targets, bundle staging and fixture/persistence roots. Share only supported immutable/download caches. No mutable symlink to canonical outputs. Same-tree native children serialize commands that touch the same output even when their source files are disjoint. Keep generated files out of source commits unless their owning task deliberately requires them.

Commit early, after each coherent task-sized tested slice; avoid a large end-of-lane batch. The user's instruction authorizes these future local commits without repeated commit questions. Snapshot commits may preserve unfinished work but are labeled **candidate/WIP**, never released or accepted. Use Conventional Commit messages. No per-commit public push is implied.

Development checks on a dirty tree do not certify a SHA. Before handoff, freeze the candidate commit and run relevant checks in a clean/frozen isolated candidate or exact-source CI. A handoff contains base/commit, tasks, changed files, original prerequisites, actual commands/logs/results, failure/negative controls, source/tool hashes and explicit writer/command release.
