## 4. Independent JavaScript number-oracle recipe (future execution)

Freeze one reproducible corpus definition, then save two independent package-local observations of it. Use actual JS builtins for text; use the hashed owning TS source for full callers. No fixture has been generated here.

1. Capture exact Node executable/version/V8/platform, `rustc -vV`/Cargo and target triple later. Package engine floor >=22 is not an exact tested pin. Generate under an owner-selected installed Node/V8, rerun observations under the actual supported Bun/workerd release only where such host acceptance is claimed; record versions and disagreement. Document results from one engine as that engine's results.
2. Seed unsigned64 xorshift at `0x6a09e667f3bcc909`. For each draw apply `x ^= (x << 13) & MASK`, `x ^= x >> 7`, `x ^= (x << 17) & MASK`, mask64 after each xor; MASK is `(1n<<64n)-1n`. Keep drawing until **10,000 distinct** 16-digit hex patterns are retained in generation order. Fixed boundary cases are additional, not counted toward the10,000. This is a deterministic coverage sample, not an exhaustive proof.
3. For each pattern, use DataView.setBigUint64(0, BigInt('0x'+hex), false) followed by getFloat64(0,false). Calculate expectations with independent `String(n)` and `JSON.stringify(n)` builtins. Record original hex, observed host bits from a separate DataView roundtrip, `Object.is(n,-0)`, finite/NaN classification, string text and JSON token text. Original bits are JSON strings, never JSON numeric input. Native tests reconstruct from the original u64, never from a decimal fixture. No formatting candidate, ryu-js or serde-generated expectation is imported.
4. Boundary patterns: ±0; smallest and second subnormal; largest subnormal/first normal and neighbors; max finite and neighbors; ±Infinity; multiple quiet/signaling NaN signs/payloads; ±1,0.1,0.3; nextDown/self/nextUp of ±1e-6 and ±1e21; ±1e20; ±2^53 and adjacent representables; ±2^63 and adjacent representables; JS conversion of int64 min/max and adjacent decimal spellings; powers-of10 and2 around notation/digit transitions. Obtain adjacency via increment/decrement of exact IEEE bits with signed-order handling, not adding Number.EPSILON. Include known difficult shortest-roundtrip decimals such as1000000000000000128 represented by its actual host bits. Don't imply int64 max is exactly representable as f64.
5. Freeze full callers via explicit per-operation inputs and capture actual results/throws. Artifact representation records property presence and ordered entries; bigint as text, number as original/reobserved bits, JS strings as UTF-16 units plus UTF-8 bytes only when scalar-valid, object refs as call-local tokens and traces when relevant. Never JSON.stringify whole arbitrary results as the sole observation. JSON number token is an intentional text expectation, not a carrier. Compare exact error bytes and counts/order; omit engine stack text.
6. First save expectations before running candidate Rust/native/Wasm. Record generator+donor source hashes, corpus definition/version/seed/count, engine versions, fixture hash, command exit/output and independent reviewer. Later fixture regeneration is deliberate and reviewed, never automatic on mismatch. Do not update old frozen vectors to bless candidate drift.
7. Negative controls must make deliberately faulty outputs fail: i64 saturation for ±1e20, `-0` text, JSON NaN as `NaN`, exponent without `+`, wrong notation threshold, one-bit mutation, altered error code/field order/punctuation. A current-values formatter mismatch is not asserted without reproduction. Keep allowed surrogate residuals separate so a passing count cannot hide them.

## 7. Exact envelope templates (source expectations; not executed captures)

`${...}` below is template substitution by the original JS caller, not precomputed fixture data. Full caller freeze must capture actual source, not implement these templates as the sole oracle. Omitted properties stay omitted; Rust Option=None is not permission to serialize null.

- Values `round(value, scale)` integral out-of-range: TS throw `{name:"ValueError", kind:"value", code:"out-of-range", message:"round scale out of range 0..18: ${String(scale)}"}`; native Failure has only code/message; exact_call response `{ok:false,code:"out-of-range",message:...}`. Noninteger scale wins first with invalid-construction/`round scale must be an integer`.
- Values `makeDate(year,month,day)` all integer but invalid combination: ValueError/invalid-construction/`invalid civil date: ${String(year)}-${String(month)}-${String(day)}`. Any noninteger part wins first with `date ${label} must be an integer`, scanning year,month,day in order.
- Values `makeMoney(1n,numericCurrency)`: ValueError/invalid-construction/`invalid currency code shape: ${String(numericCurrency)}`; preserve the primitive-only profile and maker argument order.
- Values `decodeValue("int",n)` for a number: SchemaError/kind schema/message `schema validation failed with 1 violation(s)`/violations `[ {path:[],code:"type",message:"int has the wrong wire type",expected:"canonical int64 decimal string",actual:"number ${String(n)}"} ]`. Native codec Err carries that ordered violation only; exact_call returns `{ok:false,violations:[...]}`. All properties shown are present. Public smoke backend currently has its different scaffold mapping; do not bless that as public codec parity.
- Values money shape with missing minor: `{path:["minor"],code:"required",message:'money {minor, currency} is missing "minor"',expected:"money {minor, currency}"}`; `actual` is absent. Missing currency follows minor. Unknown key k: `{path:[k],code:"unknown-field",message:"money {minor, currency} has no field ${JSON.stringify(k)}",expected:"money {minor, currency}",actual:actualWire(wire[k])}`. Shape required/extra observations precede field decode checks in their original order.
- Values money currency string malformed: path `["currency"]`, code format, message `money.currency is malformed`, expected `ISO 4217 currency code`, actual JSON.stringify(currency) then UTF-16 truncation. Full public SchemaError message uses the actual total violation count.
- Values `encodeValue("money", {kind:"money",minor:1n,currency:"AAA"})`, when AAA is absent from the pinned table: ValueError/invalid-construction/message `unknown currency "AAA" at $["currency"]`. Native Failure and transport layer map as above. Public unknown-currency encode guard only admits three uppercase letters; arbitrary escaped currency text is an internal raw-MoneyParts probe, not equivalent public input. Currency-shape-invalid records must keep `expected a money value at $` before unknown-currency formatting.
- Work/state rows count mismatch: `{name:"KernelTableError",message:"work.fanout_intent.memberCount ${String(memberCount)} mismatches members length ${members.length}."}` for work; state adds name StateError, code validation, details null. Native RowsError has name/code Option/message, no details field; required host mapping is a separate join.
- Work/state cohort diagnostic: work message `fanout cohort must be model or anchored-collection, got ${JSON.stringify(value)}.`; state starts `Fanout`. Choose number/nonfinite value here to reach JSON numeric-token formatting while retaining shape-check precedence.
- Receipt stale revision: `{name:"ReceiptTableError",message:"${what}: stale revision ${String(revision)} under current ${String(current)}."}`, code absent. Unknown status: same name/message `work.receipt.status is unknown: ${JSON.stringify(value)}.`. Native ReceiptFailure contains name/message.
- Linkage receipt skew: `{name:"StateError",code:"validation",details:null,message:"Receipt join: receipt revision ${String(receiptRevision)} disagrees with association revision ${String(associationRevision)} for ${JSON.stringify(deliveryId)}."}`. Native LinkageError has name/code/message only. Earlier malformed row/duplicate/no-receipt faults retain precedence.
- Recovery resume skew: `{name:"Error",message:"planRelatedProgressResume: association revision ${String(associationRevision)} disagrees with receipt revision ${String(receiptRevision)}."}`, code absent; native RecoveryError contains name/message. Earlier unknown relation/status/foreign receipt stays first.

These templates are supported by the exact local caller hashes in JSON, not fresh observations. They do not mandate JSON object key serialization order of transport structs: preserve existing transport key order and compare its exact layer separately; ordered violation arrays/paths and owned record ordering are semantic obligations.
