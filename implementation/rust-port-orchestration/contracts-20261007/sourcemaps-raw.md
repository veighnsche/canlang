## Frozen external behavior

Keep public `DecodedSegment`, `DecodedLine`, `MappedPosition`, `decodeMappings(mappings): DecodedLine[]` and `lookup(map, genLine, genCol): MappedPosition|null`. They are synchronous and pure in the current source. The ordinary V3 subset in contracts/artifact.ts has version, file, sources, sourcesContent, names, mappings; no declared sourceRoot/indexed sections/ranges. Runtime lookup ignores version/file/sourcesContent/sourceRoot and reads raw source/name tables. Do not turn an ignored optional extension into normalization authority or add indexed-map support through a candidate default.

- decodeMappings("") returns []; nonempty semicolon-separated strings preserve every line, including leading/trailing empty lines. Split commas preserve empty-segment faults. Segment forms 1/4/5 only. Generated delta accumulator resets to zero each line; source index/line/column/name accumulators persist across lines. One-field segments update only generated column. Four-field segments do not reset previous name.
- Each VLQ field uses current JavaScript signed 32-bit bitwise accumulation and shift semantics. This includes modulo-32 shifts, arithmetic right shift, sign behavior, accepted noncanonical/long encodings, and signed-zero deltas. No explicit overflow, nonnegative accumulated-coordinate, safe-integer, canonical-minimal-encoding or sorting guard currently exists. A segment's fields are completely decoded before bad field-count refusal. Preserve this odd acceptance as oracle scope, not desirable semantics or a fabricated strict guard.
- lookup rejects noninteger/negative genCol and noninteger/genLine<1 to null **before decoding**. For valid inputs it decodes the whole mappings string before checking requested line/segments/source table. A malformed later unqueried line therefore throws; out-of-range valid line does not bypass corruption. Infinity/NaN fail the integer gate; arbitrarily large integral JS Numbers are admitted to normal lookup/null behavior.
- On a sorted line choose the last segment with generated column <= query (GLB), including the **last** duplicate exact column. One-field winner stops mapping and returns null; never fall back across it to the previous mapped segment. Before first eligible segment, empty/out-of-range line returns null. On an unsorted line the actual source-order scan breaks at the **first** segment with genCol>query; later eligible segments are not examined. This is not mathematical GLB on all segments; do not sort or reject it silently.
- Winner lacking src/srcLine/srcCol returns null. sources must be an Array and sources[src] a string; otherwise null. Empty string is a valid raw source. Source index access uses ordinary JS array property semantics, including unusual negative/property values if supplied by a nonstandard host object; finite ordinary JSON/typed artifact fixtures are the primary supported corpus. Negative source line/column are currently accepted and returned +1, even zero/negative result coordinates. No successful-map validation may be inferred from the comment claiming 'never misresolves'.
- Optional name: when segment has name and names is an Array, include name only if names[index] is a string. Missing/out-of-range/negative/wrong-type name omits the property, while preserving successful source position. It does **not** return null. Empty string name is valid. sourcesContent has no lookup role.
- Input generated line is 1-based/column 0-based; output both 1-based. invoke subtracts V8 column once. Current lookup reads sources/names live on each call and decodes mappings each time. In-place mutation, replacing mappings/sources/names and previously failed→valid transitions are visible on next call. Exported decode returns fresh mutable arrays/objects despite readonly TS types; returned mutations cannot affect later decode/lookup. No cache currently exists. Any cache is a separately tested implementation choice with invalidation and evaluation-order contract; a cache keyed solely by map object is incompatible. Default release requires no cache until qualified.

Complete explicit Error.message oracle:

- `sourcemap: bad VLQ character ${JSON.stringify(String.fromCharCode(code))}` for first invalid UTF-16 unit within the current field/segment.
- `sourcemap: empty segment`
- `sourcemap: truncated VLQ value`
- `sourcemap: bad segment field count ${N}` for 0/2/3/>5; currently reachable ordinary input counts 2/3/>5, since empty segment already faults.
- Preserve source's defensive `sourcemap: bad segment field count` and count-0 branches if internal unreachable state is exposed; do not translate them to library defaults.

Within a segment bad character/truncation wins over field-count rejection; segment/line order decides first fault. Structurally missing mappings is **not** proven null: valid query currently reaches decodeMappings(undefined) and a native TypeError. Wrong mappings types similarly preserve actual native failure oracle. Declared SourceMap requires a string; don't silently expand that admitted domain. Invalid query bypasses even these failures. Proxy/getter/coercion arbitrary host-object equivalence is not certified; explicit supported JSON/typed input and any retained host-object route must be stated before implementation.

invoke's mapThrownError catches map/decode errors and returns undefined, preserving the original thrown message/generated position; diagnostic failure never breaks invoke's never-throws contract. It first recognizes assembled frames, then raw source suffix matches; it uses `artifact.modules.find(...).map` for fallback, not staged .map file contents. Existing `test/sourcemap.test.ts` verifies real invoke round-trip, no-map message-only, malformed-map recovery, generated/remapped frame handling and local-dev inline map delivery. Reading those tests is not fresh evidence of their execution.
